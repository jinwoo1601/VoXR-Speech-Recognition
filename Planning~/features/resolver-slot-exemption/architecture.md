# feat-resolver-slot-exemption — Architecture

Realizes `Planning~/features/resolver-slot-exemption/requirements.md` (#161, Track **Full**) — DR-8 and DR-9 of `scoring-model.md` §0E (Amendment A5, locked at G1 2026-10-02): a missed required slot whose name has a registered resolver costs 0 raw / 0 den and still counts as missed everywhere else, fewer exempted slots ranks immediately after score, and every scoring site agrees given the same registered set (M5). The governing driver is the hot path (`Runtime/Commands/**`, review binding): the parser scores (command × pattern × start) per round per utterance, and per recognition result on the eager path, so the registered set must reach the innermost scoring loop as **one bool read in the required-slot-miss branch**, never as a lookup, a call or an allocation per candidate — and with nothing registered the parser must behave bit-identically to today (F8).

## Context & scope

The parser holds no registry reference today: it receives `_slotManager.BuildEffectiveSlots(_slots)` at construction (`VoxrCommandRecogniser.cs` `Configure` :277, `RebuildParser` :463) and nothing else, and `RegisterSlotResolver` (:431) writes only to `DynamicSlotManager._resolvers` (:26), deliberately triggering no rebuild (`DynamicSlotManager.cs` :18-22). The feature adds one read-only seam from the registry into the parser and changes arithmetic and selection inside the parser only.

**Owns:** the exemption arithmetic (`TryMatchScored` :3617, miss branch :3702-3721; `ScoreFollowUp` :4494, miss branch :4539-4543); the DR-9 key (`CompareCandidate` :3457); the per-pass snapshot; the runner's names input and verdict; the DocCheck pin moves.

**Deliberately untouched:** Step 3b (`VoxrCommandRecogniser.cs` :878-994) and its three floors — the exemption only lets more candidates reach the `minScore` floor it already applies; the follow-up resolution (:1074-1087) and its `Score > 0f` floor; the eager refusal on `bestMissedRequiredSlot`, which keeps an exempt miss from ever committing (M2); the bar; the construction-time sibling-tie scan (`ScoreAfterDroppingDiscriminator`), which never calls `TryMatchScored` (M6); `minScore`, the confidence gate, the grammar, `NativeBridge~/`. No diagnostics surface learns of the exemption (R3): `ParseDiagnosticEntry`, `VoxrMatchAttempt`, `VoxrCommand` and the session log are not edited.

## Decision register

- **How the parser sees the registered set — a ctor-held, read-only source.** An internal `IRegisteredSlotNames` (`bool Any`, `bool Contains(string slotName)`, ordinal) arrives as a new optional `registeredSlots` parameter appended last to `VoxrCommandParser`'s constructor (:466); `DynamicSlotManager` implements it over its live `_resolvers` (`Any` is `HasResolvers` :108), and the recogniser passes `_slotManager` (:178) in `Configure` (:277) and `RebuildParser` (:463). The parser holds the manager, not a copy, so `RegisterSlotResolver` keeps its no-rebuild contract: a registration lands in the dictionary and the next pass reads it. A fixed `RegisteredSlotNames` (an ordinal `HashSet<string>` copied at construction) serves the runner, tests and both rigs. Both types live in `VoxrCommandParser.cs` beside `SiblingSet`, because the rig stages a fixed file list (`stage.sh` :15-26) without `DynamicSlotManager.cs`. *Why:* F4 and adr-0002, and the parser's own precedent for state a rebuild must not lose — `recordSiblingTies` and `minScore` are constructor parameters because "a post-construction setter is one call site away from a silently flag-off parser after a rebuild" (:448-451). *Rejected:* rebuilding on register (breaks F4 and the reason the registries are separate, `DynamicSlotManager.cs` :18-22); a setter pushed on register/unregister (repeated on every rebuild, and a push from a resolver lands mid-pass); copying the names at construction (a registration would need a rebuild); a per-call parameter on `ParseInternal`/`TryEagerCommit`/`ScoreFollowUp` (three recogniser sites that must agree, and `DocCheck.cs` :406-416 invokes `TryEagerCommit` by reflection with a fixed four-argument array).

- **One pass sees one set — a snapshot into a slot-indexed mask, taken first in `BuildCoverageTables` and in `ScoreFollowUp`.** `SnapshotRegisteredSlots()` fills `bool[] _exemptSlot` (indexed like `_slotNames` :234, allocated once in the constructor, only when a source is given) and `bool _anyExempt`. *Why:* `BuildCoverageTables` (:4083) is already the per-pass preparation every path to `TryMatchScored` must run first (its contract :4078-4082, enforced in the Editor by `AssertCoverageTablesMatch`), and it runs the start probe (`IsAdmissibleStart` :4246 → :4269), so any later snapshot would let probe and selection read different sets. Flush (`ParseInternal` :2474), eager (`TryEagerCommit` :4610), the probe, tests calling `BuildCoverageTables` directly and DocCheck's `Candidate` helper (`DocCheck.cs` :40-41) inherit it with no new call. No game code runs inside a pass, so a registration by a resolver (Step 3b, Step 5) or a subscriber (Step 7) lands by the next pass — the next utterance on the flush path; Step 2's `ScoreFollowUp` and Step 3's parse have no game code between them, so they agree. *Rejected:* reading the live source per candidate (an interface call per missed slot per candidate on the hot path); a separate snapshot call at each entry (an entry that builds the tables but forgets it scores its probe against a stale set, and both rigs need a second reflection call); a per-utterance snapshot owned by the recogniser (the parser has no utterance boundary — eager runs per result — and the runner and rigs have no recogniser).

- **Exempt inside the existing miss branch, guarding only the arithmetic.** In `TryMatchScored`'s `else if (!isOptional)` branch (:3702), `rawScore += RequiredSlotMissPenalty; denominator += MatchScore;` run only when `!(_anyExempt && _exemptSlot[slotIdx])`; otherwise a local `exemptedSlots` is incremented. The latch (:3710-3711), `missedRequired++`, `missedRequiredSlot = true` and `requiredAfterLastMatch++` stay unconditional, in the one place they are today. `ScoreFollowUp` applies the same guard to its own two lines (:4541-4542). *Why:* M2/adr-0003 make the exemption arithmetic only, and keeping every other effect in a single unconditional site makes that structural — the latch's own comment (:3638-3644) derives "first required element" from there being exactly two required-miss sites; `drive cut drive` stays 1/3 because the orphan-table selector still sees the miss (lab surprise 6). *Rejected:* the lab's separate `else if` branch before the existing one (`lab-2026-10-02.md` appendix) — it duplicates the latch and the three counters into a third site, which a later edit to one copy silently diverges from.

- **Where `MatchResult` carries the count — a `byte ExemptedSlots` in the padding hole.** Declared fourth in the bool run, directly after `LeadingRequiredMissed` (:3390), it occupies the one padding byte before `EndIdx` and the struct stays 32 bytes; a new test pins the size (`UnsafeUtility.SizeOf<MatchResult>() == 32`), closing the gap the layout note itself records — "there is no size pin anywhere to catch it" (:3385-3389). The bound is 255 exempt slots in one pattern, recorded in the field's comment. *Why:* the struct is returned by value into the innermost body of both selection loops, and the note (:3375-3384) measured that an appended field widens every per-candidate copy to 36 bytes. *Rejected:* an `int` appended after `MissedRequired`, as the lab patch did (36 bytes per copy, the cost the note exists to prevent); deriving the count from existing fields (impossible — `MissedRequired` mixes exempt and charged misses); an `out` parameter on `TryMatchScored` (changes the signature `DocCheck.cs` and `Sweep.cs` reach by reflection, and adds a write per candidate).

- **The key is a required `CompareCandidate` parameter.** `CompareCandidate` gains `int bestExemptedSlots` with **no default**, compared immediately after score (fewer ranks better); flush (:2584), eager (:4654) and the Editor runner-up (:2760) each carry an `ExemptedSlots` beside their other `best*` / `runnerUp*` locals and pass it. *Why:* DR-9/adr-0004, and M5's uniformity made a compile error rather than a convention — `CandidateOrder`'s comment (:3423-3426) records that a key added in one place and forgotten in another is a silent divergence. *Rejected:* the lab's `= 0` default (a forgotten site compiles and ranks every incumbent as having zero exemptions — which is how the lab left the runner-up unpatched); the cost accepted is a mechanical edit to the direct comparator tests (`VoxrCommandParserTests.cs` :6341-6459), each passing 0 with its assertions unchanged.

- **`ScoreFollowUp` applies DR-8 by the same mask.** After its own snapshot it maps each unfilled required slot's name through `_slotIndex` and skips the −1/+1 when the mask is set; the score is still fixed before Step 5's resolution runs (`VoxrCommandRecogniser.cs` :1074-1087), and `WithResolvedSlots` carries it unchanged. *Why:* F6/M5 — the pending re-score is a scoring site, and a pending whose remaining slot has a resolver would otherwise re-score under different arithmetic than the same utterance at the flush. *Rejected:* leaving it (the lab did, and listed it as not measured); routing the follow-up through `TryMatchScored` (it scores a filled-slot set against a pattern, not tokens — a different shape and a wider change than the rule needs).

- **The runner's input shape — names, by constructor, appended last.** Both public `VoxrBatchTestRunner` constructors (:21, :38) gain `string[] registeredSlotNames = null` as their last parameter; a non-empty array is copied into a `RegisteredSlotNames` handed to the runner's parser (:32, :67); null or empty means no source, today's runner exactly; a name absent from the grammar is ignored; a null element throws `ArgumentNullException`, as `RegisterSlotResolver(null, …)` does. *Why:* R1 (names, never delegates; scores as the runtime does), F7's "given none, unchanged", and the runner builds its parser in its constructor, so one runner holds one set — the parser's own reasoning for constructor parameters. `string[]` matches the runner's existing `activeSetNames`. *Rejected:* resolver delegates (R1); a settable property (needs a rebuild or a mutable set shared with a built parser); a new overload pair (doubles the constructors for one optional input).

- **The verdict and its CSV form — a rejection reason, header unchanged.** In `PassesThresholds` (:192), where `HasUnfilledRequiredSlot` (:218-225) is consulted today: when every unfilled required slot (`VoxrCommandParser.UnfilledRequiredSlots` :4440, pattern order) is in the runner's set, the reason is `would ask resolver for 'track'` (several: `would ask resolver for 'missile', 'track'`); when any is unregistered it stays `required slot unfilled`. It reaches the CSV's existing `Reason` column (`ToCsv` :322) through `FailureReason` — `expected intent 'launch_weapon' but rejected: would ask resolver for 'track'` — and `CsvEscape` quotes it when it carries a comma. Single quotes follow the runner's own strings; the requirements' backticks mark a placeholder. *Why:* R1 asks for a verdict distinct from `required slot unfilled`, and the runner cannot know whether the game will fill or decline — counting the case as fired credits a slot nobody spoke and an answer nobody gave, what requirements §3 protects in a cut. *Rejected:* accepting it so an elided case can PASS (a green corpus would certify fires a declining resolver never makes); a third status, a new CSV column or a `VoxrTestResult` field (a public shape change R1 does not ask for).

- **How the DocCheck rig and the lab rig get a set — the constructor parameter the runtime uses.** DocCheck's §7 A block (`Run` :114-149) and §6 block (:253-283) build their parsers with `registeredSlots: new RegisteredSlotNames(...)` over the lab's demo-grammar set `weapon, target, range, heading`, and their two pins move, 0.167 → 0.400 and 0.333 → 1.000; every other block stays unregistered. F10 stages the rig from the worktree (`stage.sh WORKTREE`), drops `a4l.patch`, and has the lab's `Lab.cs` pass `LAB_FILL`'s names the same way; the key's round count, which needs a probe the built parser lacks, comes from diffing round-1 winners against a staged copy with the key's comparison removed — measurement only, in `.scratch/`. *Why:* F9 and F10 must measure the built path; DocCheck pins each published number under the configuration its page states, so only the two claims that become resolver claims carry a set. *Rejected:* registering on every block (pins claims no page makes); a reflection hook into the mask (a path the runtime never takes); re-applying `a4l.patch` (measures the prototype, not the build).

## Data contract & runtime flow

**The seam.** `IRegisteredSlotNames { bool Any { get; } bool Contains(string slotName); }`, ordinal. `VoxrCommandParser(…, float minScore = DefaultMinScore, IRegisteredSlotNames registeredSlots = null)`. Parser state: `_registeredSlots` (null: no source), `_exemptSlot` (`bool[_slots.Length]`, null when no source), `_anyExempt`. Snapshot: no source → return; `!Any` → `_anyExempt = false`, return (the mask is not read while false); otherwise write `_exemptSlot[i] = Contains(_slotNames[i])` for every grammar slot and set `_anyExempt` to whether any was set. Only the grammar's slot names are ever looked up, so a resolver for a name the grammar lacks changes nothing and throws nothing (F4).

**The per-candidate contract.** `MatchResult.ExemptedSlots` (byte) = the candidate's missed required slots that were exempt. `Score` = raw / (den + coverage) with the exempt slots absent from raw and den; `MatchedRequired`, `MissedRequired`, `MissedRequiredSlot`, `LeadingRequiredMissed`, `HasUnmatchedRequiredTail` exactly as today (an exempt miss counts as missed in all of them). A pattern whose every required element is an exempt missed slot has den 0 and scores 0 through the existing `denominator > 0f` guard (:3804), and is barred by the latch anyway. The start probe's verdict (`IsAdmissibleStart` :4271) cannot move: it requires missed < matched, which forces raw > 0 with or without the exemption (lab: 0 of 4959 positions differ). `CompareCandidate(in MatchResult candidate, int startIdx, float bestScore, int bestStartIdx, int bestConsumedEndIdx, int bestLiteralCount, int bestExemptedSlots)`: admission (score floor, DR-7) unchanged; then start → score → **exempted (fewer better)** → consumed span → literal count → `Tied`.

**One utterance, live.** `HandleResult` → per result, `ProbeEagerCommit` (:737-753) → `TryEagerCommit` → `BuildCoverageTables` (snapshot, then the start-probe tables, which score with the snapshot) → the scan with the key → `bestMissedRequiredSlot` still refuses Commit, so an elided command waits for the flush (F2). At the flush, `ProcessParsedResultsCore`: Step 2 `TryFollowUpSlotFill` → `ScoreFollowUp` (snapshot, exempt arithmetic) → Step 3 `ParseInternal` (snapshot via `BuildCoverageTables`; rounds; the bar; the Editor runner-up ranked with the same key) → Step 3b resolves each candidate that passes its three floors and misses only required slots, as today — an elided candidate now arrives there at 0.667 instead of 0.250 → fill: `WithResolvedSlots` copies `Score` unchanged; decline: pending (`allowPartialMatch`) or rejection, as today (F5, requirements §4 steps 1-2).

**The runner.** Constructor names → `RegisteredSlotNames` → its parser. `Run` → `Parse` (same snapshot, same arithmetic, so the same score as the runtime, F7) → per result `PassesThresholds`: score gate; completeness, now three-way (complete / every unfilled required slot registered → `would ask resolver for '…'` / otherwise `required slot unfilled`); confidence gate. It never calls a resolver.

## Non-functional realization

- **Zero cost with nothing registered (F8), structurally.** With no source — every existing test, the rig, a runner given no names — `_exemptSlot` is never allocated and `_anyExempt` is never set, so the only change on the hot path is one `false` bool load inside the required-slot-miss branch; the matched-slot, literal and optional branches are untouched. With the recogniser's source and nothing registered, the per-pass cost is one interface call to `HasResolvers`; the mask is not touched. Selection is bit-identical because `ExemptedSlots` is 0 for every candidate, so the new key never decides. The existing EditMode and PlayMode suites passing unedited — save the CompareCandidate call sites and the re-pins F5 names — are the enforcer.
- **No per-candidate allocation with resolvers registered.** The mask is allocated once at construction; the snapshot writes into it with `Dictionary.ContainsKey` (`DynamicSlotManager`) or `HashSet.Contains` (`RegisteredSlotNames`), neither allocating; the count travels in a `MatchResult` that stays 32 bytes and is pinned there by test. Enforced by a twin of the existing `TryEagerCommit` allocation pins (`VoxrCommandParserTests.cs` :5908, :5976) run with a registered set over tokens that exercise the exempt branch, with Unity's `Is.Not.AllocatingGCMemory()` — `GC.GetAllocatedBytesForCurrentThread` is inert in this project — and the green mutation-verified (a deliberate allocation in the snapshot turns it red).
- **One set per pass (§6 robustness row).** Realized by the snapshot's placement (Decision register); nothing reads `_registeredSlots` between snapshots. **Degraded dependencies** are unchanged: a declining resolver sends the command to pending or rejection, a throwing one propagates (`slot-resolver` D-9), and the feature adds no call into game code.
- **Accepted reading of "no added per-candidate cost".** The one bool load above is the floor for a rule that must be visible in the innermost loop; removing it takes two specialized copies of `TryMatchScored` chosen per pass, the duplicated-rules hazard `CandidateOrder`'s comment (:3423-3426) warns against. The review's efficiency angle rules on it.

## Risks, tradeoffs & open questions

- **Test re-pin scope is the widest unknown in Phase 1.** Every resolver test that registers a resolver and then relies on an elided candidate scoring below `minScore` — the slot-resolver D-5 regression guard is the clearest shape — changes premise under A5, not only `Resolver_FilledSlot_DoesNotChangeTheScoreOrConfidence` (`VoxrCommandRecogniserInjectionTests.cs` :2728). Phase 1's plan inventories the resolver tests (`VoxrCommandRecogniserInjectionTests.cs` :2514-3721, `VoxrPendingCommandTests.cs` :1935-2570, `VoxrDynamicSlotTests.cs`) before editing; a test whose purpose survives keeps it by reaching the below-gate shape through literal misses instead, and each edit is traced to A5 in the PR.
- **The two unprototyped sites.** The lab patched flush, eager and the probe only; `ScoreFollowUp` and the runner-up are new. The follow-up change can move a pending whose only remaining gap is a registered slot from a non-positive re-score to a positive one — F6's intended result, after which Step 5's `TryResolveMissingSlots` call behind its `Score > 0f` floor (:1074-1087) lets the resolver fill it.
- **The exempt count is a byte.** A pattern with more than 255 exempt missed slots would wrap and invert the key; no grammar comes near it, and the bound is recorded at the field rather than guarded per candidate.
- **The runner's rejection verdict cuts one way.** A test case that expects rejection passes on a `would ask resolver` verdict, and a passing row carries no reason in the CSV, though the runtime may fire if the game fills. Stated in the rewritten comment and, after G2, in the product docs.
- **Eager and flush may see different sets within one utterance** if game code registers between partial results; nothing in the package runs game code there, eager never commits an exempt miss, and the flush re-scores — so the worst effect is a different hold verdict.
- **DocCheck's two pins become resolver claims.** `Documentation~/scoring.md`'s §7 A start-2 and §6 `fire at` worked numbers must state the registered resolver after G2, or DocCheck and the page disagree.
