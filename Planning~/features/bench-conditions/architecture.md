# feat-bench-conditions — Architecture

Realizes `Planning~/features/bench-conditions/requirements.md` (Track **Full**; S1, F1–F14 as ruled R1–R4, the §6 NFRs, §10 questions 1–5), the condition feature of design `audio-bench` (§6), built on `bench-fast-replay` (PR #198) and `bench-paced-mode` (PR #199). A conditioned run is fast mode's run, unchanged, as the clean reference; then a new `--bench condition` verb of the rig, after repeating the clean reference's self-check, writes the seeded conditioned clips with their speed-scaled truth into the run's `.scratch/` output, as 48 kHz mono 16-bit WAVs and a harness pin copy listing them; the verdict harness replays them, unchanged, as one more `--dump` pass; and `--bench run` scores each case and negative clip under each condition through the recogniser layer, unchanged, and appends the per-condition sections to fast mode's report. The governing driver is **conditions that never touch the pinned path** (requirements §3; F4, F14; adr-0003, adr-0004): the clean reference still ties exactly to the pins, conditioned audio only ever reaches the bridge through the harness binary Command 3 builds, nothing under `NativeBridge~/` changes, and a run naming no condition writes the bytes `main` writes.

## Context & scope

The harness (`bench.sh` :144-147 → `NativeBridge~/harness/main.cpp`, per-case loop from :538) takes `--fixtures <dir>` and `--manifest <pin>`, refuses a pin lacking `gain`, `grammar`, `libvosk` or the model copy's `modelConf` (:362-385) and a fixtures WAV the pin does not list (:403-419), reads `expectedFinals` only where present (:545-547), and loads only 48000 Hz mono 16-bit PCM (`wav_reader.cpp` :15-17, :92-101). `--bench run` (`ab-rig/Bench.cs` `Run` :46-265) runs `FastPrelude` (:470-575: readers, `TruthCheck` :1207-1294, pinned `Join`, finals self-check, exit 3), scores each case through `Joined.ScoreRecogniser`, `Stamps` (:670-706) and `BenchMetrics`, and writes `BenchReport.Build` (:97-483), whose header prints `Seed: none — clean renders, no condition applied` (:177). `JoinedInput.Join` has an unpinned form (:748-791); `ReadManifest` (:481) reads any corpus-schema manifest whose keys are in `ManifestCaseKeys` (:125-145). The Unity corpus tests read only `audio/manifest.json` and require every `audio/tts/` WAV listed there (`Tests~/Editor/VoxrFixtureCorpusTests.cs` :49, :139-144). The rig's `perturb.py` perturbs text transcripts (issue #65), not audio.

**Owns:** `ab-rig/BenchConditions.cs` (pipeline, grid, add-on readers, verbs `condition` and `condition-check`); `ab-rig/BenchCurves.cs` (per-condition scoring, curves, false fires); `Tests~/Fixtures/audio/negatives/`; `bench.sh --condition`, `--seed`, `--audio-root`. **Edited:** `Bench.cs` (dispatch, `run`'s conditioned arguments, the truth rule extracted, F13's pairing), `BenchReport.cs` (conditioned sections; fast text unchanged), `Program.cs` (`BenchVerbs` :152), `Rig.csproj` (the `flag bench` comment, :21-24), `stage.sh` (:115), `bench.sh`. **Run, not edited:** `Tests~/Fixtures/generate.sh`, `generate.py`. **Read, not edited:** `BenchPaced.cs` (its seams already take the conditioned data). **Untouched (F14):** `NativeBridge~/`, `expectations.json`, `audio/manifest.json`, `audio/tts/`, `Runtime/`, Command 3, `Joined*.cs`, `BenchMetrics.cs`. **Out:** voices, A/B, McNemar, percentiles (requirements §2, §7).

## Decision register

- **Code home and language — C#, in the rig's recogniser stage (§10 Q5; adr-0004).** `BenchConditions.cs` and `BenchCurves.cs` sit beside `Bench.cs`, staged under `recogniser` only, so a parser stage stops their verbs by name (bench-fast-replay *Code home*); the generator side stays Python: the 16 negative phrases are rendered once by `generate.sh` with the cached Piper venv and committed. *Why:* conditioning runs every bench run, and the bench is C#: the scaled truth, realized values and toys live in the process that scores them; a run needs only the .NET SDK and Command 3's build, never the venv (as fast-replay's truth mode), and pure-Python resampling and convolution would be slow without numpy. *Rejected:* the pipeline in `generate.py` after `synth()`, as R6 :188 maps it (pre-rendering, adr-0004 (B), or a venv per run); in the harness (a `NativeBridge~/` edit, F14); Python with numpy at run time (a second language writing the truth the C# scorer trusts).

- **Delivery — conditioned WAVs and a pin copy under `<out>/cond/`, replayed by the harness unchanged (F1, F14; adr-0002, adr-0003).** `--bench condition` writes each clip as a 48 kHz mono 16-bit WAV; `cond/pin.json`, the run's harness pin (committed, or a named configuration's copy) with `cases` replaced by the conditioned files, no `expectedFinals`; `cond/manifest.json`, corpus schema, existing keys only (`file`, scaled `speech`, `category`, `phrase` or `segments`, `expectedIntent`, `expectedSlots`); `cond/conditions.json`, seed, grid, sources, filter and per clip its source, condition, drawn and realized values. `bench.sh` runs the harness with `--fixtures <out>/cond --manifest <out>/cond/pin.json --dump <out>/cond.jsonl`; exit 0 or 1 continues, exit 2 stops. A conditioned `--out` must lie under `.scratch/`, as a named configuration's (`bench.sh` :68-69). *Why:* fast mode is the harness (bench-fast-replay); its fixture directory and pin are arguments, so conditioned audio rides the pinned binary, push size and padding by identity; 16-bit WAV is the one format it reads. *Rejected:* float audio pushed from C# through a bridge binding (a second push loop, rejected by bench-paced-mode); manifest keys for the condition (loosens the committed manifest's strict reader; the sidecar has one owner). **Amended 2026-11-10:** the `.scratch/` guard also stands in `BenchConditions.Condition`, not only in `bench.sh` (:78-79), so the verb run by hand cannot write conditioned audio elsewhere; keep both.

- **Clean reference gates every number (F4; adr-0003).** `--bench condition` runs `Bench.FastPrelude` on the clean dump before any draw, and `run` again before any world: a pin mismatch exits 3 naming the cases, no conditioned audio, no report. Without `--condition`, `bench.sh` runs today's steps and `run` today's arguments, so `FastRun` and `BenchReport.Build` write today's bytes; the conditioned arguments are a positional block after the paced one (`Bench.Run` :100-158). Phase 1 keeps a fast-only `report.md` from the unmodified tree; every later gate `cmp`s against it. *Why:* F4's two checks; bench-paced-mode's baseline practice. *Rejected:* the check in `run` only (the set written and decoded before the refusal).

- **Determinism — one seed, keyed streams, a rig-owned RNG (F1).** The seed is a decimal unsigned 64-bit integer, required with `--condition`, refused without it. Each draw comes from a stream keyed by (seed, FNV-1a 64 of the conditioned clip's own name — a noise-only twin's differs from its partner's —, condition id, stage tag) through SplitMix64, seeding xoshiro256**; uniforms are its top 53 bits, Gaussians Box–Muller. Drawn per clip and condition: RT60 and the response's tail (or the SLR28 file), the noise (or the MUSAN file and offset), the level, silence's partner, the game-audio window; speed and SNR are the condition's, never drawn. *Why:* `System.Random`'s seeded sequence is not promised across .NET versions; keyed streams mean a new clip, condition or game step never moves another clip's audio; toys pin the first outputs of a known key. Identity holds on one machine and runtime (transcendentals are the runtime's); the report holds no path, clock or hash order. *Rejected:* one sequential stream (any change shifts every later draw); `System.Random`.

- **The pipeline — per clip, in this order (F2; adr-0004; R6 :191-196).** Speech: speed by band-limited windowed-sinc resampling to round(n ÷ factor) samples, 1.0 an exact copy (Ko et al.'s perturbation, tempo and pitch together) → a synthetic room response → the mic filter. Noise: pink Gaussian noise over the whole clip (or a MUSAN segment) → the mic filter. The filtered noise is scaled so the filtered speech's RMS over the scaled speech segments, over the noise's RMS on the same samples, is the SNR step; the sum is peak-scaled to a level drawn log-uniform in [0.04, 0.4] and written at 16 bits. The room response is a direct path at lag 0 plus a Gaussian tail decaying 60 dB over the drawn RT60 (Polack's model), its direct-to-reverberant ratio a named constant; its RT60 is measured by Schroeder integration and a response outside 0.2–0.5 s is redrawn from the same stream; the echo is cut at the clip's speed-scaled length. `condition` measures each clip's realized SNR, 16-bit peak and RT60 into `conditions.json` and stops (exit 2, clip named) outside F2's bounds. *Why:* filtering speech and noise apart, then summing, is the filtered mix (the filter is linear), so the step holds at the decoder's input; pink noise falls with frequency as room noise does, where white noise at 48 kHz puts most of its power above the decoder's band (the dump's `decoderRate`); log-uniform levels cover the decade-wide range evenly. *Rejected:* SNR set before the filter (not what the decoder hears); white noise (generate.py's `noiseFloorDbfs` kind); an image-source room (RT60 not set directly); uniform linear levels; tempo-only stretching (not R6's recipe).

- **Truth — the clean truth scaled, the truth rule on the speed stage (F3; adr-0006).** A conditioned clip's `speech` is its source's, each bound round(x ÷ factor). Speed is the only stage that moves samples: the direct path is at lag 0, noise additive, the filter causal, level a scale. `condition` runs `TruthCheck`'s rule — the last sample at or above `TruthFloor` before the tail within `FrameTolerance` of the recorded end (`Bench.cs` :23-25, :899-916) — on each clip's speed stage, tail scaled; the rule becomes one internal method both call. *Why:* under 5–20 dB SNR or an echo tail no floor scan finds end of speech; the speed stage is where a bound could move. *Rejected:* rescanning the conditioned clip (fails by construction); an energy detector (adr-0006 (B)). Ruled at PLAN 2026-11-09: F3's acceptance is reworded to match — the truth rule passes on each conditioned clip's speed stage, the one stage that moves samples (requirements F3).

- **Mic filter shape — three biquads in cascade (§10 Q3; values → the tuning pass).** A second-order Butterworth high-pass (a small capsule's roll-off), a peaking section (a port resonance), a second-order Butterworth low-pass (voice-band capture); RBJ-cookbook coefficients at 48 kHz, fixed per run, never seeded, each value a named constant the header prints. *Why:* the design names mic-like filtering, no response, and Quest's is unpublished (R6 :451): a plausible band-pass with knobs the tuning pass can move. *Rejected:* a measured Quest response (a human measurement); a filter drawn per clip (a grid axis R1 did not rule).

- **The conditioned set and the grid (F5; R1, R2).** 12 conditions, speed {0.9, 1.0, 1.1} × SNR {20, 15, 10, 5} dB, ids `s0.9-snr20` … `s1.1-snr5`, each with echo, the filter and a drawn level; `grid` names all. Conditioned: the 16 non-pause cases and the negative set; the 36 pause cases run clean only. Steps are named constants, provisional → the tuning pass; `BenchConditions` holds the one list of names, printed on an unknown one (exit 2).

- **The negative set — its home and truth (§10 Q1; F6; adr-0007).** (1) 16 phrases, 8 out-of-set (no word in the pin's `grammar`) and 8 near-miss (a grammar word, no command), rendered in `en_US-lessac-medium` by `generate.sh --manifest audio/negatives/manifest.json` (argparse keeps the last `--manifest`, `generate.sh` :60-66), committed as `Tests~/Fixtures/audio/negatives/*.wav` with `manifest.json` beside them in the corpus schema, categories `negative-out-of-set` and `negative-near-miss`, no `expectedIntent`, `speech` by truth mode (`generate.py` `write_truth` :183-218); run clean and under each condition. (2) Noise-only clips per condition, a twin per non-silence case of the 16, never committed; they run conditioned only, having no clean form, and the silence case stands as their clean form (ruled at PLAN 2026-11-09). (3) The committed silence case, in F5's conditioned set and the negative set: its rows show in the per-case tables, and its fires count once, in the negative false-fire rate only (ruled at PLAN 2026-11-09); the positive rates already exclude it (no `expectedIntent`). `condition-check` checks the list: no out-of-set word in the grammar; each near-miss phrase, a one-final timeline through `Joined.ScoreRecogniser`, fires nothing. *Why:* clean renders (adr-0004), and Piper is not byte-deterministic, so committed once; a sibling directory is invisible to the corpus tests and the pin. *Rejected:* `audio/tts/` (`EveryCommittedWav_IsListedInTheManifest` fails); `manifest.json` or `expectations.json` (F6); `Planning~/` (the bench outlives this feature). **Amended 2026-11-10:** the 16 phrase cases carry `"expectedIntent": ""` and `"expectedSlots": []`, not no key, because `JoinedInput.ReadManifest` requires both; an empty intent is how the positive rates exclude them. Do not strip the keys.

- **A speech-free clip's level — its partner's interferer (§10 Q2).** A noise-only clip at a step carries noise at the RMS the filtered, level-scaled noise had in its partner speech case there, from its own stream, at the partner's length, filtered, not re-levelled; twin j's partner is case j, silence's is drawn per condition. Game-audio negatives follow the rule per SIR step. *Why:* with no speech to reference, the step's noise is what the positives heard at it, so false fires and accuracy face one interferer and the level range is inherited. *Rejected:* peak-scaling noise into [0.04, 0.4] (noise as loud as speech, no step's condition); a fixed dBFS per step (another knob).

- **Scoring and report (F7–F10; adr-0004, adr-0007, adr-0008).** `run` joins the conditioned dump and manifest unpinned, drives each clip through `Joined.ScoreRecogniser` and `AppliedGrammarGuard`, stamps it with `Bench.Stamps` against its scaled truth, and `BenchCurves` subsets by condition, reusing `BenchMetrics.Score` and `Command` unchanged. The report is fast mode's text, then: **header** lines (`Seed:` carrying the seed) naming the grid, noise source, room-response source, mic filter and values, level range and distribution, game-audio status, and the labels — TTS-only, provisional; augmented numbers rank conditions, not field rates (R6 :451); digital mixing a lower bound on difficulty (I1 :274); **conditioned latency** per case and condition, three signed offsets, no aggregate (F9); **conditioned accuracy**, class, finals, extra fires, pending, WER; **curves**, a table per speed, a row per metric (intent, semantic, phantom, WER, ECE, NCE, false-fire rate), a column per SNR step plus the clean reference over the same cases, each cell with its n in phrases and cases, no total across conditions (F8); **negative set**, per condition and group — F7's "per condition step" is each of the 12 conditions, laid out per speed, never pooled across speeds (F8; ruled at PLAN 2026-11-09) —, false fires per negative case and per hour of negative audio (first and extra fires over the group's duration), labelled provisional and stand-in, zero printed "0 — set too easy", never netted (F7). No basis prints `undefined` and why (`BenchMetrics.Value`). *Why:* curves per condition, never pooled (R6 :198, :336); the n per point keeps pseudo-replication visible. *Rejected:* a pooled pass rate (R6 :336); a separate report (F10 names one header).

- **Add-on and title-audio folders and formats (§10 Q4; F11, F12; adr-0004).** One root, `${XDG_CACHE_HOME:-$HOME/.cache}/voxr-bench/` (`generate.sh` :22's rule), overridable by `bench.sh --audio-root <dir>`: `musan/`, the archive as distributed, `musan/noise/**/*.wav` read; `slr28/`, likewise, `slr28/RIRS_NOISES/simulated_rirs/smallroom/**/*.wav` read, only responses measuring 0.2–0.5 s eligible; `game-audio/`, any accepted file. Accepted: RIFF WAV, PCM 16-bit or float 32-bit, 1 or 2 channels (averaged), any rate (resampled to 48 kHz by the speed resampler); files in ordinal path order. A folder absent means the generated or synthetic kind, named; a file that cannot be read, or a folder with none eligible, stops (exit 2) naming it and the accepted formats (§6). *Why:* gigabytes of corpus and the maintainer's title audio stay outside every tree, far from a commit or Unity's import; one root serves every worktree; MUSAN and SLR28 ship at 16 kHz. *Rejected:* `.scratch/` (per tree); a gitignored `Tests~/` folder (imported by the host run); 48 kHz mono 16-bit only via `VoxrWavReader` (a hand conversion). **Amended 2026-11-10:** a MUSAN or game-audio file shorter than the window is read looped from a drawn start and no length stop exists (ruled at Phase 4's RECONCILE; F11 says any audio file); a window with no signal is redrawn, at most 100 draws, then a stop naming the folder; an SLR28 response is trimmed to its peak and divided by it so the direct path sits at lag 0, which *Truth* relies on: do not keep the onset.

- **Game audio (F11, Should; R3).** With `game-audio/` supplied, conditions `game-sir20`, `game-sir10`, `game-sir5`, `game-sir0` (SIR {+20, +10, +5, 0} dB, provisional) mix a seeded window of title audio, filtered, under the speech at speed 1.0 with echo and level as the grid, no generated noise, scaled over the speech segments as SNR is; `grid` then names 16 conditions, the report adds the SIR curve, and per SIR step a game-audio-only negative per non-silence case joins the set by the partner rule. Absent: `game audio: not supplied`, game ids refused by name. *Why:* one SIR curve isolates game audio. *Rejected:* SIR crossed with the 12 (four times the run; rejected at PLAN); game audio as the SNR noise (conflates two curves). Ruled at PLAN 2026-11-09: F11's game-audio condition is these four conditions at speed 1.0 with echo, the mic filter and level, no generated noise, one SIR curve. **Amended 2026-11-10:** whether game audio was supplied travels as `conditions.json`'s `gameAudio` text, tested against the shared `NotSupplied` constant, so `run` keeps its 12-argument block; a boolean beside it was ruled out at review (it would change a conditioned output). A stop on a game step labels it SIR, with the step id.

- **Paced under one condition (F13, Could; adr-0003).** `bench.sh --paced --condition <id>` (`grid` refused) runs the clean reference and that condition's fast pass, then both paced passes on `<out>/cond/` with the same pin copy; `matched-check` and `run` pair them with the conditioned fast dump, `BenchPaced.CheckMatched`, `Paired` and `Assemble` taking the conditioned manifest, dump and outcomes; the paced section names the condition. *Why:* the matched check's premise, same samples and push size, holds for any clip. *Rejected:* pacing the grid (hours; adr-0003). **Amended 2026-11-10:** `BenchPaced.cs` is unchanged: `CheckMatched`, `Paired` and `Assemble` already take the manifest, dump and outcomes as arguments, and `Bench.cs`, `BenchCurves.cs` and `BenchReport.cs` supply the conditioned ones; no clean paced pass runs under a condition. The matched check's premise holds only since BCN-1 (PR #200, `main`) padded 49152 samples, 12 x 4096, in `NativeBridge~/harness/main.cpp`: at 48000 the paced read grid after a clip end sat 2944 samples off fast mode's and the check exited 3 (adr-0001's kill criterion). Do not return the padding to a non-multiple of 4096.

## Non-functional realization

- **Performance (§6).** No budget is ruled. A conditioned run costs one extra harness pass over the conditioned set and one world per clip; the room response is applied by FFT convolution, the one cost that would otherwise grow with RT60 × clip length.
- **Input boundary (§6), each a named stop with exit 2 and no report.** `--seed` without `--condition` or the reverse; a seed that is not an unsigned 64-bit decimal; an unknown condition (the valid list printed); a game id without game audio; `grid` with `--paced`; a conditioned `--out` outside `.scratch/`; a negative case without `speech` (`TruthCheck`'s stop, run on the negatives manifest); a truth-rule failure on a speed stage; a realized SNR, peak or RT60 outside F2; an add-on file that cannot be read or a folder with none eligible; a stale `cond/`. A metric with no basis at a curve point — NCE with every word right, a rate over no case — prints `undefined` and its reason, never a number.
- **Degraded dependencies (§6).** MUSAN, SLR28 or title audio absent is not an error: the header names `generated (pink Gaussian)`, `synthetic (exponential decay)`, `game audio: not supplied`. The clean reference failing stops in `condition` before any draw and again in `run` before any world, exit 3.
- **Determinism (F1), structurally.** Streams keyed by name and condition; conditioned clips and rows in manifest order, then grid order; numbers printed invariant-culture at fixed precision; the harness's read boundary is the one run-dependent input, measured unmoved on the clean set (bench-fast-replay *Determinism*) and re-measured on conditioned audio by Phase 1's probe.
- **Only clean renders committed (adr-0004; F6, F14), by construction.** Conditioned audio is written only under a `.scratch/` `--out`; the negative renders are the one committed audio this feature adds; no write set holds `NativeBridge~/`, `expectations.json`, `audio/manifest.json` or `audio/tts/`; each gate checks `git diff main` empty for those paths.
- **Hot paths and the device.** None touched: `Runtime/**` and `NativeBridge~/src/**` unchanged; no on-device check is owed.

## Build plan

Lowest risk first, with the riskiest assumption probed in the first phase: the pipeline and its determinism probe (rig only), then the one committed-data change, then the scored run and its report, then the optional inputs, then paced mode and the closing gate. ## Risks, tradeoffs & open questions

- **The riskiest assumption: a conditioned report repeats (F1) — probed at Phase 1.** It rests on floating-point DSP repeating on one runtime and on the harness's read boundaries repeating on noisy audio, which keeps the decoder busier than clean audio. A moved boundary is a change to the pinned path's behaviour, a stop for the human, never a rounding fix.
- **Two readings ruled at PLAN 2026-11-09.** F3: the truth rule runs on each conditioned clip's speed stage, since no floor scan finds speech end under noise or echo, and F3's acceptance is reworded to match (requirements F3; register *Truth*); F11: the game-audio condition is four conditions `game-sir20/10/5/0` at speed 1.0 with echo, the mic filter and level, no generated noise, one SIR curve, SIR crossed with the 12 rejected (register *Game audio*).
- **The stand-in negatives are small.** A condition's negative audio is a few dozen short clips, far short of the five hours R6 :340-341 needs for a per-hour rate, so one false fire moves it in a large step. Both labels say so; R4 replaces the set (adr-0007).
- **Curve points are thin.** Each point holds at most the 16 cases; ECE and NCE will often print `undefined`, and Vosk's near-flat `conf` (R6 :208) makes NCE fragile. The n per point keeps this visible.
- **Synthetic stands in for real.** The room model, the pink noise and the filter shape are plausible, not Quest's (R6 :451; I1 :274); every value is a named constant for the tuning pass, and the header prints each.
- **The near-miss phrases are a judgment.** The checks prove only that each fires nothing as text; the maintainer's approval is the acceptance (F6).
- **Coupling and drift.** `run` reuses `Stamps`, `Selected`, `JoinedScorer.Classify` and `BenchMetrics` unchanged, so a change there moves clean and conditioned numbers alike; the truth rule is shared with `TruthCheck`; the harness's strict pin checks and 16-bit reader bound what `condition` may write. TTS-only evidence never ranks decoders (C12).
