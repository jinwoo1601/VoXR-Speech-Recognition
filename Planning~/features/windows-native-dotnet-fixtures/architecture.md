# feat-windows-native-dotnet-fixtures — Architecture

Realizes `Planning~/features/windows-native-dotnet-fixtures/requirements.md` (Track **Full**; S1, F1–F9, the two §6 NFRs): Command 4 (the `Samples~` compile) and the parser A/B rig's DocCheck run on native dotnet from Git Bash, `Tests~/Fixtures/generate.sh` on a stock Windows Python, the binding and recipe lose their last WSL routes, and a closing sweep closes deferral WSL-1 (adr-0001, adr-0005, design §1 rules 1 and 3). The governing driver is **Git Bash path conversion**: Claude Code's Git Bash sets `MSYS_NO_PATHCONV=1`, a plain Git Bash does not, and the bound text, DocCheck and `generate.sh` must behave the same either way (NFR; F3). So each decision puts a drive-letter path wherever a Windows program reads one, save for the uneditable `stage.sh`, given the one conversion mode it needs.

## Decision register

- **The csproj location — `.scratch/samples-compile/` under the project root (§10 item 3).** Binding and recipe both name `.scratch/samples-compile/SamplesCompile.csproj`; the recipe's "session scratchpad" text and its `/tmp/claude-1000/…` example go. *Why:* the binding already names it; one path for every session and for a maintainer, who has no Claude scratchpad; `.scratch/` is gitignored and Unity skips dot-folders. *Rejected:* the session scratchpad (per-session, unknown to a maintainer); committing the csproj (the recipe's "generated, never committed"; machine paths tracked). **Amended 2026-10-14:** Command 4's build and the recipe's sanity build run in a subshell, `(cd .scratch/samples-compile && dotnet build …)` and `(cd "$SP" && … | wc -l)`, so the shell stays at the project root: the recipe repeats the build (mutation, revert by `git checkout --` from the root, sanity count), and a relative `cd` left in the scratch directory fails the next one (review finding 1).

- **The csproj path form — drive-letter form with forward slashes.** `UnityData` `C:/Program Files/Unity/Hub/Editor/6000.4.7f1/Editor/Data`, `PkgRoot` `D:/Workspace/VoXR-Speech-Recognition`, `HostAsm` `D:/Workspace/VoXR TestGround/Library/ScriptAssemblies`; the rest of the listing (:147-209) unchanged. *Why:* MSBuild reads the file with no bash between, so no MSYS path is converted (design rule 3); forward slashes match the globs and row 1's `C:/…` arguments. *Rejected:* `/c/…`, `/d/…` (rooted on the current drive, `D:\c\…`); `C:\…` (mixed separators against the globs); `PkgRoot` as `$(MSBuildThisFileDirectory)../..` (`..` in compiler output and the count; the other two stay machine paths).

- **The input check — an MSBuild target in the generated csproj, one `<Error>` per input.** A target `VoxrCheckInputs`, `BeforeTargets="BeforeBuild"`, fails naming the missing path for each of: `$(PkgRoot)/Samples~`, `$(UnityData)/NetStandard/ref/2.1.0/netstandard.dll`, `$(UnityData)/Managed/UnityEngine/UnityEngine.CoreModule.dll`, `$(HostAsm)/UnityEngine.UI.dll`, `$(HostAsm)/Unity.InputSystem.dll`. *Why:* the degraded-dependency NFR: a missing reference is today MSB3245, demoted to a message (`MSBuildWarningsAsMessages`, :169), and a missing `Managed/UnityEngine` empties the glob into hundreds of CS0246 errors naming no input; the paths stay in the one file using them; a property override makes the negative run. *Rejected:* an `ls -d` precheck in the bound command, as Command 3 has (the paths kept in step in two places); no check (the NFR).

- **The sanity count — normalized separators, case-folded.** `… -t:CoreCompile -v diag 2>&1 | tr '\\' '/' | grep -oiE 'D:/Workspace/VoXR-Speech-Recognition/Samples~/[^ ";]*\.cs' | sort -fu | wc -l` must print 7. *Why:* F1 names the pattern; MSBuild prints the glob's fixed part as written and the matched part with backslashes, either drive-letter case, so the old `/mnt/d/…` pattern prints 0 and a naive Windows one could double-count; excluding `;` keeps a joined item list from fusing two paths; `tr`, `grep`, `sort` are MSYS programs. *Rejected:* a backslash-only pattern (misses the fixed part); no count (the cheap guard against a green that compiled nothing). **Amended 2026-10-14:** the backslash is written in octal, `tr '\134' '/'`, and the whole pipeline sits inside the subshell of the csproj-location amendment. The Claude Code Bash tool halves `'\\'` to one backslash, on which GNU `tr` prints "an unescaped backslash at end of string is not portable" beside the count; `'\134'` is one backslash to every runner, and a plain Git Bash (review finding 3).

- **No SDK pin.** Command 4 and DocCheck run whatever `dotnet` selects, here 10.0.300 (newest installed, no `global.json`). *Why:* `netstandard2.1` builds on any installed SDK; `Rig.csproj`'s `net10.0` fails loudly below 10 (NETSDK1045, naming the framework). *Rejected:* a generated `global.json` (one more generated file, broken by a routine SDK patch update).

- **The DocCheck section's shape — one recipe section, one command line, a fixed output directory (ruled fork 1).** A new `## Parser A/B rig — DocCheck` at the end of the recipe gives, from the project root, `env -u MSYS_NO_PATHCONV bash "Planning~/features/coverage-in-selection/ab-rig/stage.sh" WORKTREE .scratch/doccheck && cd .scratch/doccheck && dotnet build -v q --nologo && dotnet run --no-build -- --doccheck` (section text in *Data contract*). *Why:* F2's check is "followed verbatim", and one `&&` line stops at the first failing step; the prefix serves `stage.sh`'s `git -C "$HERE"` (:13) alone; `stage.sh` empties the output first (:29), so `Rig.csproj`'s incremental false green (:9-17) cannot arise; `dotnet run` returns `DocCheck.Run`'s exit code (`Program.cs` :181-182; `DocCheck.cs` :905). *Rejected:* a README in `ab-rig/` (fork 1 ruled the recipe); a bound Command (requirements §7); two separate steps (the second can run on a stale stage); `MSYS_NO_PATHCONV=` empty (unrecorded whether MSYS reads it as set; `env -u` is proven); `pwd -W` in `stage.sh` (design §1); a trailing `; echo "exit=$?"` (exits 0, hiding a failure). **Amended 2026-10-14:** the steps after `stage.sh` run in a subshell — `env -u MSYS_NO_PATHCONV bash "Planning~/features/coverage-in-selection/ab-rig/stage.sh" WORKTREE .scratch/doccheck && (cd .scratch/doccheck && dotnet build -v q --nologo && dotnet run --no-build -- --doccheck)` — so the shell stays at the project root and a rerun finds `stage.sh`; the subshell's exit code is `dotnet run`'s (review finding 1).

- **The interpreter — `VOXR_PYTHON`, else the first of `py -3`, `python3`, `python` that runs as Python 3 (§10 item 1).** Each candidate must pass `<candidate> -c 'import sys; sys.exit(sys.version_info[0] != 3)'`; `VOXR_PYTHON`, when set, is the only candidate, and its failure is an error naming it, never a fallback; no candidate passing exits 1 naming the four tried. The bootstrap line names the candidate and its `--version`. *Why:* F3: stock Windows has `py` and `python`, not `python3`; `py -3` first keeps this host's hand-made `python3.exe` from proving F3; the probe rejects a Microsoft Store alias stub (exits non-zero without running Python) and a Python 2 `python`; on Linux `py` is normally absent and `python3` found as today (F4); `VOXR_PYTHON` reaches any other interpreter and drives the negative run. *Rejected:* a host switch on `uname -s` (breaks on an MSYS2 or Cygwin Python; still needs the stub check); `python3` then `python` only (`python3` may be the stub); `py -3.12` (a minor pin adr-0005 does not make); `PYTHON` (node-gyp and others read it). **Amended 2026-10-14:** `VOXR_PYTHON` is a command line split on spaces, as `py -3` is (one unquoted `$PY` serves both, `plan-2.md` :45), so it may name a launcher with arguments (`py -3.12`) but not a path containing spaces; the script header and the `VOXR_PYTHON` error text say so (review finding 2).

- **The venv layout — read from the venv, not from the host.** After `-m venv`, `$VENV/Scripts` present means `VBIN=$VENV/Scripts`, `EXE=.exe`; otherwise `VBIN=$VENV/bin`, `EXE=` empty; every venv program is `"$VBIN/<name>$EXE"` (flow in *Data contract*). *Why:* adr-0005: the layout belongs to the interpreter that made the venv; explicit `.exe` keeps `-x` and `subprocess` off implicit-extension lookup; Linux paths equal today's (F4). *Rejected:* layout by host (the `uname` objection); `python -m pip` (a change on both hosts beyond adr-0005's two names); `sysconfig.get_path("scripts")` (a backslash path bash must convert).

- **`generate.sh`'s path form — the cache root converted once to drive-letter form (ruled 2026-10-14).** Right after `CACHE` is set (:17): `if command -v cygpath >/dev/null 2>&1; then CACHE="$(cygpath -m "$CACHE")"; fi`. Every path the script passes to Python (`-m venv`, `--data-dir`, `--piper-bin`) derives from it, so in Git Bash each is `C:/Users/…`; the rest are relative. On Linux `cygpath` is absent and every path equals today's (F4). *Why:* F3 as amended (requirements §2 In 3, §5 ruling): conversion rewrites only `/`-prefixed arguments, so a drive-letter one reaches Python alike in either mode; `cygpath`, an MSYS program, gets its argument unconverted; Git Bash's bash takes `C:/…` in `-x`, `-e`, `mkdir -p` and as a command word; one line covers every derived path; within adr-0005's "changes only where the hosts differ", per the ruling. *Rejected:* the script unedited, its header requiring an `env -u MSYS_NO_PATHCONV` prefix (forgotten, Python reads `/c/Users/…` as `D:\c\Users\…`, builds the venv there and fails at `pip` naming no cause; behaviour still differs by mode, against F3); `unset MSYS_NO_PATHCONV` or a re-exec at the top (rests on the runtime rereading the variable mid-process, unrecorded); converting at each of the three call sites (three edits for one).

- **The binding's Path form line ends with the working-dir read (ruled 2026-10-14, approving `plan-1.md`).** The line closes with `; the working-dir read `pwd -W` already prints this form (`D:/…`)`. *Why:* the harness's doctor check V21 (`_path_form_reading` in `scripts/harness.py`) warns on a unity `verification` Path form that names no Editor-path conversion and passes one that says the working-dir read `already prints` the form; `pwd -W` prints drive-letter form, so without the clause the warning would outlive Phase 1.

- **The recipe's dated :3 note — edited in place, the edit dated.** The parenthetical "(and `build-desktop` in WSL)" is deleted, and the line closes with *Edited <date>: a clause on the old Linux desktop cache dropped; the desktop harness now configures fresh into `build-windows/`.* *Why:* F7 sweeps the whole recipe for "prints nothing"; the rest of the note and the workspace-move record stay true; the dated marker keeps the record honest without the matched word. *Rejected:* excluding :3 (changes F7's ruled areas); deleting the note (loses a true instruction and the record); a marker quoting the old clause (the sweep would match it).

- **`### WSL Usage` becomes `### Git Bash usage` — adb and logcat by `/c/…` command word, the cmake entry dropped.** Text in *Data contract*. *Why:* F6 ("rewritten as Git Bash usage of adb and logcat"); `/c/…` command words follow row 1's ruling B for the recipe's `CMAKE=`; CMake already sits in `### Building NativeBridge` and step 2b, so a third copy would drift; the device-path note covers a plain Git Bash's `adb push`/`pull` trap (design §3). *Rejected:* deleting the section (F6); `C:/…` command words (against row 1's form); keeping a cmake line.

- **Step 4's wording — "needs the Quest headset".** *Why:* the checks need the device, not a host; no host name to go stale. *Rejected:* "cannot be verified from Git Bash" (true of every host; renames the host coupling rather than removing it).
