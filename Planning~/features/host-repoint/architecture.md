# feat-host-repoint — Architecture

Realizes `Planning~/features/host-repoint/requirements.md` (Track **Full**; S1, F1-F9, §6, §10 items 1-4; items 5-6 are the tuning pass's, Phase 4) for design `parallel-trees` §1 H1-H6 as re-locked 2026-11-05 (adr-0002, the keystone). The code of this feature is the verification procedure: one new script, `Planning~/host-run/host_run.py`, carries the whole Commands 1-2 bracket — the host lock, the at-rest read, the repoint of TestGround's `file:` path, the `Tests~` rename, both platforms, the evidence read, the restore and its check — and the `verification` binding's Commands 1-2 become one invocation of it; Command 4's generated csproj takes `PkgRoot` from its own location; Command 3 runs on pinned inputs copied into each branch tree's `NativeBridge~/vendor/`. The governing driver is §6 robustness: a crashed or failed run must never let a later run test the wrong code silently, so the restore lives in one process's `finally`, the lock dies with its holder, and green is read off what Unity itself wrote during this run.

## Decision register

- **Host lock — an OS byte-range lock on `D:/Workspace/VoXR-Speech-Recognition/.scratch/host-lock/lock`, the hub's (F1; H1, H2; §10 item 1).** The script opens that file and takes a non-blocking `msvcrt.locking` lock on its first byte, retrying on a poll until the wait bound, then exits BLOCKED quoting `host-lock/owner`, which the holder rewrites right after taking the lock with its tree root, platforms, process id and UTC start. The OS releases the lock when the holder's process ends, however it ends. *Why:* the design's failure mode 1 (`parallel-trees.md` §3) has a crashed run leave the host pointed at a tree and the next run stopped by the at-rest read — which holds only if a crash frees the lock; a lock that dies with its holder needs no stale-lock rule, and H2 forbids the run repairing anything. The hub is the one fixed path every tree knows (named by the binding today, by the `trees` Hub slot after `trees-fill`); its `.scratch/` is gitignored (`.gitignore` :37) and hidden from Unity's import, so the lock writes nothing into TestGround. *Rejected:* an atomic `mkdir` lock (a crash leaves it held, so failure mode 1 becomes a timed BLOCKED and a hand-clear step the design does not name, and invites an auto-break H2 forbids); a lock under TestGround (`Temp/` is Unity's and is cleared by its runs; anywhere else is a host byte beyond the manifest and a `git status` leftover there); `flock` (not reliably in Git for Windows).

- **At-rest read — four conditions, read under the lock, before any write (F2; H1, H2).** The host is at rest when: the manifest's `com.jinwoo1601.voxr` value is `file:` + the hub; its `testables` equal those of `git -C "<host>" show HEAD:Packages/manifest.json` (a read), compared parsed; `packages-lock.json`'s `com.jinwoo1601.voxr` `version` is `file:` + the hub; `<host>/Temp/UnityLockfile` is absent. Paths compare per the binding's Path form. Any miss exits with a stop for the human naming what it found, nothing written; a tree-side precondition — `Tests~` present, `Tests` and `Tests.meta` absent — is read first and stops the same way. *Why:* H1's three conditions, plus the lock file, which Unity rewrites to the tree's path during a run (PM fact, 2026-11-05) and which still names a tree after a restore that did not finish; reading it makes "host bytes unchanged" (F2, F3) cover both tracked files. *Rejected:* both files byte-equal to `HEAD` (stops on any uncommitted manifest change the human makes, stricter than H1's definition); the three H1 conditions alone (misses a half-finished restore).

- **Manifest edit and restore — snapshot bytes, one value rewritten, snapshot bytes written back (F3; adr-0002; §6; §10 item 3).** After the at-rest read the script copies the exact bytes of `Packages/manifest.json` and `Packages/packages-lock.json` to `.scratch/host-lock/rest/` beside the lock, then replaces the single occurrence of `"com.jinwoo1601.voxr": "file:<hub>"` with `"com.jinwoo1601.voxr": "file:<tree>"`, the tree in `pwd -W`'s `D:/…` form — a count other than one, or a tree path holding `"` or `\`, stops before writing; where tree and hub are one path nothing is written. `testables` and every other byte are untouched; `packages-lock.json` is never edited, only Unity rewrites it. The restore writes both snapshots back whole and checks each byte-identical, then re-runs the at-rest read; a miss is a stop for the human naming the snapshot directory, which holds the pre-run bytes. The host's `git status --short` is read before and after and any difference reported, never repaired. *Why:* byte replacement keeps F3's byte identity by construction; the snapshot, not git, is the restore source, since the vc-guard forbids `git checkout` and §6 forbids touching TestGround's other changes; the snapshot sits beside the lock so the human recovering from a crash finds it, and the at-rest read guarantees it is overwritten only by a run that found the host at rest. *Rejected:* parse and re-serialise the JSON (reformats bytes F3 checks); `git checkout`/`git restore` of the two files (a git write in TestGround, §6); hand-editing `packages-lock.json` back (the snapshot is exact, an edit is not); keeping the snapshot in the tree (a crash leaves it where the next tree's run cannot point to it).

- **Resolved-path evidence — `packages-lock.json` read after each Unity exit, before the restore (F4; H3; §10 item 4).** After each platform's Unity process exits, the script reads `packages-lock.json`'s `com.jinwoo1601.voxr` `version`; green needs it to equal `file:<tree>`. Unity writes that value when it resolves the manifest at the run's start; the bracket never writes it, and the at-rest read proved it named the hub before. With the per-platform green (Unity exit 0, the XML deleted before the run and present after, `failed="0"`, `inconclusive="0"`) and the host back at rest after the restore, it is H3's whole condition; the summary names it as `resolved: file:<tree> (packages-lock.json)`. In the one checkout the value is unchanged, since the only path is the hub. Phase 0 proves the rewrite before anything is built on it; if Unity does not rewrite the lock in batchmode, the decision stops for a ruling. *Why:* evidence Unity itself produces in this run, read from a file the bracket already snapshots, with no new test code and no dependence on `-testFilter`. *Rejected:* scraping the Unity log (an undocumented format, and nothing printed when the path is unchanged); a probe test asserting `PackageInfo.resolvedPath` (new test code, and a Targeted run's filter can drop it, leaving no evidence).

- **One bracket per Commands 1-2 run, in one process (F1, F3; §4 items 3-4; §6).** `py "Planning~/host-run/host_run.py" <EditMode|PlayMode>… [--filter "<target>"] [--wait <seconds>]`, run from the tree root, takes the lock once, repoints once, runs the named platforms in order — the bound run names `EditMode PlayMode` — and restores in a `finally`, so a failed or crashed test run still restores; a killed script leaves the lock freed and the host not at rest, which the next at-rest read stops on. The tree under test is the script's own checkout (two levels above it), which must equal the working directory, else a stop: a hub copy run from a tree, or a tree's copy run from the hub, cannot test one checkout and report another. Exit 0 green, 1 not green, 2 BLOCKED on the lock, 3 a stop for the human. The binding's Command 1 line carries the invocation; Command 2's line keeps PlayMode's green and names it as run by Command 1's invocation; Targeted adds `--filter`. *Why:* requirements §4 items 3-4 describe one run doing both platforms between one repoint and one restore, as today's split preconditions and revert already do; a prose bracket across several runner tool calls has no `finally`; one repoint, not two, pays the re-import (F9) once per run; `compile-check` runs one listed command and never invents. *Rejected:* one bracket per platform (two repoints, two re-imports per run from a tree); a prose bracket run step by step (a runner stopping mid-way leaves the host pointed at the tree with nothing to restore it); a Bash script (the parsed `testables` compare and the byte lock want Python's `json` and `msvcrt`; `py` is already on the Git Bash PATH, `.claude/bindings/core.md` `## session-launch` Context read).

- **Script home — `Planning~/host-run/` (F1-F5).** A `~` directory, so the host never imports it, outside `Tests~`, which the bracket renames while it runs. *Why:* the precedent for verification tooling run by hand from Git Bash is `Planning~/features/coverage-in-selection/ab-rig/` (recipe :222-232). *Rejected:* `Tests~/` (renamed mid-run; Unity would mint `.meta` files for it); a root-level `scripts/` (imported by the host as package content).

- **`Tests~` rename and `.meta` cleanup by listing (F3; H1).** Before the rename the script lists every path under `Tests~/`; after the revert it deletes only `.meta` paths absent from that listing, and the root `Tests.meta`, and reports any other new path without deleting it. *Why:* the run's own creations are exactly the new paths; uncommitted test files in the tree are what gets tested (adr-0002) and are never touched. *Rejected:* deleting every untracked `.meta` by a git read (would take a developer's untracked file of the same suffix).

- **`PkgRoot` — derived from the csproj's own location (F6; H5).** The recipe's listing sets `PkgRoot` to the directory two levels above `$(MSBuildThisFileDirectory)` — the tree root, since the csproj is generated into that tree's `.scratch/samples-compile/` — and the 7-file sanity check greps the compile list for `<pwd -W>/Samples~/`. `HostAsm` stays the host's `Library/ScriptAssemblies`, read without the lock. *Why:* one verbatim listing serves every tree; a substituted literal is a per-run edit whose omission silently compiles the hub, exactly the wrong-tree green H3 exists to kill. *Rejected:* writing the tree's root into the csproj at generation (an edit to forget); an MSBuild property passed on the command line (Command 4's command changes in every tree's binding read, and a bare `dotnet build` still compiles the default).

- **`vendor/` per branch tree — the two pinned input directories copied from the hub (F7; H6; §10 item 2).** A branch tree is provisioned by copying `vosk-win64-0.3.45/` and `vosk-model-small-en-us-0.15/` from `D:/Workspace/VoXR-Speech-Recognition/NativeBridge~/vendor/` into the tree's `NativeBridge~/vendor/`; `overlaid/` is not copied — Command 3's `confgen` writes it in that tree. Where the hub lacks them, the README's download blocks apply (a human step, since agent downloads are refused). Writer trees are never provisioned, so Command 3 in one fails on its missing model (exit 2) rather than writing anywhere. In the one checkout nothing is copied. The procedure is a README section the binding's Prerequisites cite. *Why:* real directories keep every write in the tree with no link semantics to trust; copying from the hub needs no network and no re-check of the zip's SHA-256 (README :16), the harness's own `libvosk` and `modelConf` pins checking what it decodes. *Rejected:* directory junctions to the hub's pinned directories (a tree removal or `rm -rf` that follows the junction deletes the hub's inputs, and a writer can mutate a shared target); copying the whole `vendor/` (527M, `du -sh`, carries the hub's `overlaid/` output and the Linux leftovers README :28 names); a per-tree download (network, and refused for agents).

## Seams

- **PM / `compile-check` → the bracket.** The binding's Command 1 invocation, run in the background from the tree root (`compile-check.md` :22, :29); back across: the exit code and stdout summary — per platform `<platform>: total/passed/failed/inconclusive`, `resolved: …`, `host: at rest`, or the stop or BLOCKED line naming what was found. Cite: `.claude/bindings/unity.md` :6-7, :13 · `Planning~/host-run/host_run.py`.
- **The bracket → the host lock.** `<hub>/.scratch/host-lock/lock` (the byte lock), `owner` (written by the holder, read by a waiter), `rest/manifest.json` and `rest/packages-lock.json` (the snapshot). The lock spans the at-rest read to the restore check.
- **The bracket → TestGround.** Reads: the two `Packages/` files, `Temp/UnityLockfile`, `git show HEAD:Packages/manifest.json`, `git status --short`. Writes: the manifest's one `file:` value, then both files' snapshot bytes. Unity writes `packages-lock.json`, `Library/` and `Temp/` during the run. Cite: `D:/Workspace/VoXR TestGround/Packages/manifest.json` :3, :52-54; `packages-lock.json` :3-7.
- **The bracket → Unity.** `Unity.exe -runTests -batchmode -projectPath "<host>" -testPlatform <p> -testResults "<tree>\.scratch\test-results\<p>.xml" -logFile "<tree>\.scratch\test-results\<p>.log"` with `-testFilter` when given, no `-quit`; back: the exit code, the XML, the log, the rewritten `packages-lock.json`. Cite: `.claude/bindings/unity.md` :6.
- **The bracket → the tree.** `Tests~` renamed `Tests` and back; `.scratch/test-results/` created if absent; the root and working directory compared.
- **Command 4's csproj → the tree root.** `PkgRoot` from the csproj's location; `HostAsm` the host's, unlocked. Cite: `Planning~/verification-recipe.md` :147, :177-178, :136-140.
- **Command 3 → the tree's `vendor/`.** Reads the two copied pinned directories; writes `vendor/overlaid/continuous-default`. Cite: `.claude/bindings/unity.md` :8; `NativeBridge~/harness/README.md` :12-27.

**Flow:** a Commands 1-2 run from a tree: the runner starts `py "Planning~/host-run/host_run.py" EditMode PlayMode` at the tree root → the script checks root == working directory and `Tests~` ready → polls the lock up to the bound (held past it: exit 2, owner quoted, nothing written) → writes `owner` → the at-rest read (a miss: exit 3, nothing written) → snapshots both `Packages/` files and the host's `git status --short` → rewrites `file:` to the tree → lists and renames `Tests~` → per platform deletes the old XML, runs Unity, reads its exit, the XML's counts and `packages-lock.json`'s `version` → `finally`: `Tests` back to `Tests~`, run-created `.meta` deleted, snapshots written back and checked, at-rest read again, host status compared → the lock released → summary and exit 0 only when every platform is green, the evidence named `file:<tree>` after each, and the host is at rest.

## Non-functional realization

- **Robustness at the input boundary (§6).** Wrong-code-silently is closed structurally on three sides: the restore is a `finally` in the process that made the edit, so a failed or crashed Unity run restores; a killed script frees the lock with its process and leaves `file:` on the tree, which the next at-rest read stops on before writing — and the snapshot it would overwrite is still there for the human, since snapshots follow a passed read only; and green needs `packages-lock.json` to name this tree after Unity exits and a freshly written XML, so a stale XML or a host pointed elsewhere is never green. A Unity crash that leaves `Temp/UnityLockfile` fails the post-restore read and stops for the human.
- **Degraded dependencies (§6).** In TestGround the bracket writes only `Packages/manifest.json`'s one `file:` value and then the two `Packages/` files' own pre-run bytes; it runs only git reads there (`show`, `status`), never `checkout` or `reset`; the human's uncommitted `Assets/XR/Settings/OpenXRPackageSettings.asset`, `ProjectSettings/EditorBuildSettings.asset` and untracked `Assets/Samples/…` are never opened, and any status change a run causes elsewhere is reported, not repaired.
- **Performance (§6, F9).** One repoint per run, not per platform, so a run from a tree pays one package re-import on entry, and the host pays one more on its next open on the hub; the script prints its lock wait and each platform's wall time, which Phase 4 reads. No budget is fixed; the wait bound is the script's `--wait` default and the binding's text, provisional until Phase 4 sets it.
- **One checkout unchanged (F8, H7).** Tree == hub: the at-rest read passes as today, no manifest byte is written, the evidence reads the hub, `PkgRoot` resolves to the hub, and `vendor/` is the hub's own; outcomes match today's, and the host rests on the hub.
- **Structural laws.** Command 3 never runs in a writer tree because writer trees are never provisioned; Command 4 never takes the lock because it reads only two non-VoxR host assemblies (H5).

## Risks, tradeoffs & open questions

- **The evidence rests on an unverified Unity behaviour.** That batchmode `-runTests` rewrites `packages-lock.json` to the manifest's new `file:` path is inferred, not read; Phase 0 retires it before anything is built on it, and a no stops for a ruling.
- **Re-import cost unmeasured.** Each run from a tree may pay a full package re-import, and the human's next Editor open on the hub another; if it is heavy, the tuning pass may weigh batching (design §2). Phase 4 measures it.
- **Command 4 during another tree's bracket.** `HostAsm` can be mid-rewrite while Unity compiles; the two DLLs are not VoxR's, so a clash is a transient file error, never a wrong green (H5 stands as locked).
- **The binding's Command 2 line.** It becomes the PlayMode half of Command 1's invocation; its wording must stop `compile-check` running a second bracket. Phase 3's `doc-writer` item.
- **A killed script.** The lock frees, the host stays on the tree, and the next run stops for the human, who restores from `<hub>/.scratch/host-lock/rest/` — by design (§3 failure mode 1), but a manual step the recipe must name.
- **Drift watch.** The hub and host paths are constants in the script, named in the binding too; the layout binding's Tests slot does not list `Planning~/host-run/`; adr-0002's fork text (:13) and the binding's Command 1 (:6) still describe adding `testables`, which Phase 3 retires in the binding (the ADR is a record, not edited). `compile-check` runs from the hub until `trees-fill` changes Run from, so worktree runs are the PM's.
- **Readings.** The at-rest read adds `packages-lock.json`'s `version` to H1's three conditions, and the restore writes that file's own pre-run bytes back, read as within §6's "edits only the manifest's `file:`" because the bracket never authors a byte of it (PM fact, 2026-11-05). F6's check is run from the worktree too, at no host cost. Accepted as readings by the human at PLAN 2026-11-05 ("Accept as readings (Recommended)"); no locked or requirements doc changes.
- **Open, owned by Phase 4:** the wait bound's value (§10 item 5) and the re-import cost per repoint (§10 item 6).
