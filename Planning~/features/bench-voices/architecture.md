# feat-bench-voices — Architecture

Realizes `Planning~/features/bench-voices/requirements.md` (Track **Full**; S1, F1–F13 as ruled R1–R4, the §6 NFRs, §10 Q1–Q4; Q5–Q6 carried as open), the voices feature of design `audio-bench` (§6, adr-0005), on `bench-fast-replay` (PR #198), `bench-conditions` (PR #201) and `bench-paced-mode` (PR #199). Two halves never run together. Once, the maintainer renders the voiced set — the 15 spoken non-pause cases and the 16 negative phrases — in 12 Kokoro-82M voices with a script that reuses the generator's layout and truth, into an untracked cache outside the repository, a record per voice. At bench time `bench.sh --voices` runs the clean reference first as today; a new `--bench voice` verb checks and copies the named voices' clips into the run's `.scratch/` output; the harness replays them unchanged as one more `--dump` pass; `--bench run` scores them per voice. The governing driver is **the baseline never moves and the bench never needs Kokoro** (requirements §3, §8; F3, F13; adr-0005): with no voice named the bench writes `main`'s bytes, the pins, committed WAVs and `NativeBridge~/` lie outside every write set, and the bench reads only WAVs and JSON.

## Context & scope

`bench.sh` (`ab-rig/`) takes one value per option (`take`), runs the clean harness `--dump` pass over the 52 committed cases, builds a ref, optionally `--bench condition` and a pass on `<out>/cond/`, then `--bench run`; `AUDIO_ROOT` defaults to `${XDG_CACHE_HOME:-$HOME/.cache}/voxr-bench`. `Bench.FastPrelude` requires the corpus manifest's top-level `voice` (`Prelude.Voice`), runs `TruthCheck` (`ReadPcm` over `VoxrWavReader`, 48000 Hz mono 16-bit only; `TruthRule`) and the finals self-check, exit 3. `BenchConditions.Condition` writes `cond/` (WAVs, `pin.json`, `manifest.json` with existing keys only, `conditions.json` with per clip `source` and `condition`), which `BenchCurves.Read` joins unpinned. `JoinedInput.ReadManifest` ignores a top-level `voice`, admits only `ManifestCaseKeys` and names a case by its basename; `BenchReport.Build` prints one `- Voice:` line. So no carrier exists per clip, and Kokoro's 24 kHz is not what the harness reads (recon). `generate.py` synthesizes with Piper (`synth`, soxr to `TARGET_RATE`), lays out in `build_case`, writes `write_wav`, scans truth in `speech_truth`; `generate.sh` keeps its venv in `${XDG_CACHE_HOME:-$HOME/.cache}/voxr-fixture-gen`.

**Owns:** `Tests~/Fixtures/voices.py`, `voices.sh`; `ab-rig/BenchVoices.cs` (ids, cache reader and checks, verbs `voice` and `voice-check`, per-voice tables); the cache layout and record; `bench.sh --voices`. **Edited:** `generate.py` (`build_case` takes the speaker; Piper behaviour unchanged), `Bench.cs` (dispatch, `run`'s voice block), `BenchConditions.cs` and `BenchCurves.cs` (visibility only), `BenchReport.cs` (voice lines and sections), `Program.cs` (`BenchVerbs`), `Rig.csproj` (`flag bench` comment), `stage.sh`, `bench.sh`. **Untouched (F3, F13):** `NativeBridge~/`, `expectations.json`, `audio/manifest.json`, `audio/tts/`, `audio/negatives/`, `Runtime/`, Command 3, `Joined*.cs`, `BenchMetrics.cs`, `BenchPaced.cs`. **Out:** paced voices (F12), A/B and significance tests, tuning the list (§2, §7).

## Decision register

- **Render home — its own script beside the generator, reusing its layout and truth (§10 Q4; F1, F2; adr-0006).** `Tests~/Fixtures/voices.py` imports `generate` and renders each case through `build_case`, `write_wav` and `speech_truth` unchanged; the one `generate.py` edit is that `build_case` takes the speaker (text → 48 kHz samples), `main` passing Piper's `synth`. Nothing in `bench.sh` or the rig calls the render. *Why:* one definition of lead, tail, gap, peak and scan serves both engines, so F2 cannot drift; the render writes only to the cache. *Rejected:* an `--engine` flag in `generate.py` (its `main` writes committed WAVs and rewrites the committed manifest's truth, one flag from moving F3's files, in Piper's venv); a copied layout (two kept equal by hand); the render in the rig (C# cannot run Kokoro).

- **Venv and model — beside the Piper toolchain, local paths only (§8).** `voices.sh` keeps its own venv and the model under `${XDG_CACHE_HOME:-$HOME/.cache}/voxr-fixture-gen/kokoro/` (`venv/`; `model/` with `config.json`, `kokoro-v1_0.pth`, `voices/<id>.pt`), takes Python as `generate.sh` does (`VOXR_PYTHON` or the launcher) and refuses one outside ≥3.10, <3.13, the stricter of the two bounds the researcher read. Its first run installs `kokoro` 0.9.4 and fetches the model and 12 voice packs, as `generate.sh` fetches the Piper voice — the maintainer's step; subagents are refused downloads. `voices.py` loads model and packs by local path only. *Why:* torch and Kokoro's bound must not move the Piper venv's pins; outside the tree Unity never imports it (`generate.sh` :20-21). *Rejected:* one shared venv; the hub's default download cache (a path the record cannot name).

- **24 → 48 kHz — soxr in the render, as `synth` resamples Piper (§10 Q3; F2).** The Kokoro speaker resamples its 24 kHz output by `soxr.resample` to `TARGET_RATE` before `build_case` scales and pads it. *Why:* the fixtures' own resampler; the harness and `VoxrWavReader` take 48000 Hz only; truth is scanned on the bytes replayed. *Rejected:* caching 24 kHz and resampling per run with `BenchConditions.Resample` (a per-run stage; truth on bytes the render never wrote).

- **Cache — a directory and a record per voice under the add-on root (§10 Q3; R1; F1, F8, F10).** Clips live at `<audio-root>/voices/<id>/<stem>.wav`, `<stem>` the source case's basename, under the root `bench.sh` already resolves and `--audio-root` overrides. `voice.json` records the id, licence and its source, engine (`kokoro` or `stand-in`), `kokoro` and `misaki` versions, sha256 of model file and voice pack, and per clip its source `file`, `phrase` or `segments`, `gapSeconds`, `peak`, `speech` truth, realized peak and sha256. A clip is keyed by voice and source case and is current while its recorded text and layout equal the manifest's. *Why:* one root for every tree, far from a commit (bench-conditions *Add-on folders*); a record per voice lets one voice be rendered or removed alone, F8's partial state; it carries the Kokoro facts the report names, which no file at bench time holds. *Rejected:* `.scratch/` (per tree, lost with it); a gitignored repository path (R1); one record for the cache (a re-render rewrites all).

- **Determinism — the cache is the audio; digests either way (§10 Q1; F2, F11).** No source states Kokoro repeats its bytes, and `KModel` never calls `.eval()` (researcher). The bench never re-renders: it replays cached bytes, checks each against the record's sha256, and names per voice a render id, 12 hex of the sha256 over the record's clip digests in order; truth is scanned from the written bytes, as for Piper (`generate.py` :12-14). The probe — one voice rendered twice into two `.scratch/` roots, digests compared — needs Kokoro installed, so it is a human step or the PM's after the maintainer's install, at Phase 5 or earlier; it decides only what a re-render may claim (equal: it reproduces the render id; unequal: it makes a new one), amended into this bullet. The render does not force `.eval()`. *Why:* F11's identical reports and F2's truth need fixed audio, which the cache gives under either outcome; the digest exposes a stale or altered clip. *Rejected:* digests only if deterministic (a silent cache edit would pass); forcing `.eval()` (alters the library's inference in a way no source establishes, for a property the design does not need).

- **OOV and espeak-ng — refused by the render (F9; R6 :18, :321).** Without espeak-ng KPipeline warns and skips an out-of-lexicon word (researcher), the silent drop §6 forbids. `voices.py` builds the English G2P with no fallback, runs it on each text before synthesis, and refuses the case naming the phrase and each word left without phonemes; it refuses a text the pipeline splits into more than one chunk (the 510-phoneme limit), which would add unplaced gaps; at start it refuses if an installed distribution's name contains `espeak` or `phonemizer`, printing the list. The token rule is a pure function with toys run without Kokoro. *Why:* only the render sees the G2P. *Rejected:* trusting the warning (a dropped word, a wrong clip with a right truth); an audio check (cannot name the word).

- **Stand-in engine — Piper lessac in the voiced layout.** `voices.sh --stand-in` runs `voices.py --engine piper` in the cached Piper venv: each named id gets the voiced set in `en_US-lessac-medium` through the same `build_case`, its record's engine `stand-in` and licence `stand-in, not a Kokoro voice`, both printed in the report; agents render stand-ins only into `.scratch/` roots. *Why:* the bench side, F8 and the crossing are built before the install, on real speech, through the refactored Piper path. *Rejected:* code-written tones (nothing to score; a second cache writer); waiting on the human step.

- **The voiced set — one predicate, both languages, checked against the record (F1; R2).** Positives are the corpus cases not `pause-lead` or `ladder` with speech (`BenchConditions.Condition`'s predicate less silence); negatives every case of `audio/negatives/manifest.json`; 15 and 16, read from the manifests' `category` and `file` keys on 2026-11-22. `voices.py` and `BenchVoices` each derive it; a present voice's record must hold exactly it. *Why:* R2 sets the set by rule, so a stale cache shows. *Rejected:* a committed file list (a third copy of the manifests).

- **Naming voices — `--voices all|<id>[,<id>…]`, one list in the rig (§10 Q4; F5, F12; §6).** `BenchVoices` holds the 12 ids in F1's order, refuses an unknown or repeated id printing the valid list (exit 2), and runs voices in that order. `--voices` with `--paced` is refused in `bench.sh` (exit 2, naming adr-0003) and again in `run` and `matched-check`, as `grid` with `--paced` is. A voiced `--out` lies under `.scratch/`, checked in `bench.sh` and the verb; `--audio-root` is accepted with `--voices` or `--condition`. *Why:* `take` admits one value per option; one owner of the ids, as `BenchConditions` owns condition names. *Rejected:* a repeated `--voice` (refused by `take`); ids in `bench.sh` (two lists).

- **Clean reference first (F4; adr-0003).** `bench.sh` runs the clean pass over the 52 cases before anything voiced; `voice` runs `Bench.FastPrelude` before reading the cache, `run` before any world: a mismatch exits 3 naming the cases, no `voice/`, no report. Voiced clips carry no pins: `voice/pin.json` has no `expectedFinals`. *Why:* F4; bench-conditions' rule. *Rejected:* the check in `run` only (the set copied and decoded before the refusal).

- **Delivery and the per-clip voice — a `voice/` directory and its sidecar (§10 Q2; F5, F7).** `voice` copies each present voice's clips to `<out>/voice/<stem>__<id>.wav` and writes `voice/pin.json` (the run's harness pin, `cases` replaced), `voice/manifest.json` (corpus schema, the source case's existing keys, `file` `voice/<name>`, `speech` from the record, top-level `voice` naming the sidecar) and `voice/voices.json` (status line; voices named, present, missing with reasons; each record's fields and render id; per clip `source`, `voice`, `condition`). `bench.sh` empties `<out>/voice` first and runs the harness on it into `<out>/voice.jsonl` when `voice/pin.json` exists (exit 0 or 1 continues, 2 stops). *Why:* the manifest's `voice` is one value and `ManifestCaseKeys` guards every committed manifest; the sidecar is bench-conditions' proven pattern; copying fixes the run's bytes and lists every WAV the harness sees. *Rejected:* a `voice` key per case (loosens the committed manifests' reader); a pass per voice (twelve model loads); the harness on the cache (unnamed voices' WAVs are unlisted, refused).

- **Provisioning — three states; only the inconsistent one stops (F8; §6; adr-0005).** No `voices/` or no voice with a record prints `voices: baseline only — Kokoro not provisioned` on stdout and in the header, writes no voiced audio, exit 0. A named voice with no directory, no record or a listed WAV absent is missing: named with its reason, the rest run. A malformed record, an id differing from its directory, a set or text differing from the manifests, or a clip whose sha256, format, peak (outside [0.04, 0.4]) or `Bench.TruthCheck` (root `<out>`) fails stops, exit 2, voice and clip named. *Why:* absence is adr-0005's normal state; a wrong clip makes a made-up number. *Rejected:* a missing clip as a stop (F8 expects a name); a stale record as missing (hides a changed phrase).

- **Crossing — voiced clips through the conditioned pipeline on request (F11; R3; adr-0004).** With `--condition` and `--seed`, `voice` also writes each voiced clip under each condition of the run's grid through `BenchConditions`' `Speeded`, `SpeechClip` and add-on readers, made `internal` and called unchanged, with the speed-stage truth rule and realized-value stops, and writes `voice/conditions.json` by `cond/`'s writer so `BenchCurves.Read`'s stale and join checks apply. Streams stay keyed by the clip's name, `<stem>__<id>__<step>.wav`, so voices never move `cond/` audio; noise-only twins are not voiced. Voices run clean by default. *Why:* R3; keyed streams make the crossing additive. *Rejected:* voices inside `cond/` (changes a no-voice grid run's files, F3); a second pipeline.

- **Scoring and report — per voice, never pooled (F5–F7, F10; design :132; R6 :198, :370; adr-0007, adr-0008).** `run` peels a voice block off its arguments' end before the conditioned block, joins `voice.jsonl` with `voice/manifest.json` unpinned, and scores each clip through `Joined.ScoreRecogniser`, `AppliedGrammarGuard` and `Bench.Row` unchanged. Header, in `## Configuration` after today's lines and only with a voice block: the status; per voice id, licence, engine, package versions, model and pack digests (12 hex, as `JoinedReport.ConfSha12`), render id; missing voices; the voiced clip count; the label — TTS-only (Kokoro-82M), provisional, per voice, never ranks decoders. Then, after today's sections, per voice: latency per case (signed offsets, no aggregate); accuracy per case (class, finals, extra fires, pending, WER); the six counts, three rates, corpus WER, ECE, NCE over its positives; negatives' false fires per case and per hour apart from them (`0 — set too easy`); crossed, a curve table per speed with the voice's clean clips as the clean column, modelled on `BenchCurves.Section` and reusing its helpers (`Cell`, `Phrases`, `FalseFire`). Every point states its n in phrases; no figure spans voices. *Why:* the voice is the block (R6 :370); pooling counts one phrase twelve times (R6 :198). *Rejected:* a pooled rate (design §3); `BenchCurves.Section` per voice (its groups assume silence and noise-only twins); a separate report (F7 names one header).

## Seams

**Components:** the render, `Tests~/Fixtures/voices.py` and `voices.sh` over `generate.py` (F1, F2, F9, F10); the cache, `<audio-root>/voices/<id>/` (F1, F8); `bench.sh` (order, `--voices`); `Bench.cs` (dispatch, `FastPrelude`, `TruthCheck`, `Row`); `BenchVoices.cs` (F2, F4–F8, F10–F12); `BenchConditions.cs` (F11's pipeline); `BenchReport.cs` (F7); the harness, unchanged (F13); the recogniser layer and `BenchMetrics`, unchanged.

- **Manifests → render: the voiced set** — `file`, `category`, `phrase` or `segments`, `gapSeconds`, `peak`. Cite: `audio/manifest.json`, `audio/negatives/manifest.json` → `voices.py` → `generate.build_case`.
- **Render → cache** — `voices/<id>/<stem>.wav`, 48 kHz mono 16-bit, and `voices/<id>/voice.json`. Cite: `voices.py` → `generate.write_wav`, `generate.speech_truth`.
- **bench.sh → `voice`** — clean dump, corpus and negatives manifests, pin, fixtures root, the run's harness pin, `--out`, `--voices`, add-on root, and condition and seed when given. Cite: `bench.sh` → `BenchVoices` → `Bench.FastPrelude`.
- **Cache → `voice`: record and clips**, checked and copied. Cite: `voice.json` → `BenchVoices` → `Bench.ReadPcm`, `Bench.TruthCheck`.
- **`voice` → harness** — `voice/*.wav`, `voice/pin.json`. Cite: `BenchVoices` → `main.cpp` (pin checks, `LoadWav`).
- **Harness → `run`: the voiced dump**, schema 2. Cite: `main.cpp` `DrainResults` → `JoinedInput.ReadDump`, `Join` (unpinned).
- **`voice` → `run`: truth, voice and condition per clip** — `voice/manifest.json`, `voice/voices.json`, crossed `voice/conditions.json`; a sidecar whose voices, seed or condition differ from the arguments stops (exit 2). Cite: `BenchVoices` → `Bench.Run`, `BenchCurves.Read`.
- **`run` → recogniser layer, metrics, report.** Cite: `Bench.Row` → `Joined.ScoreRecogniser`; `BenchVoices` → `BenchMetrics.Score`, `Command`; `BenchReport.Build` → `<out>/report.md`.

**Flow:** once, the maintainer runs `voices.sh`: the espeak-ng check, the voiced set, per voice and case the G2P check, synthesis, soxr to 48 kHz, layout, WAV and truth, then the voice's record. Later `bench.sh --voices all`, from the project root in Git Bash, checks its inputs (exit 2; `--paced` refused), runs the clean pass, builds the ref, runs `--bench condition` and its pass if a condition is named, then `--bench voice` — prelude (exit 3, nothing written), statuses, clip checks (exit 2), copy, crossed clips — writing `<out>/voice/`; then the harness into `<out>/voice.jsonl`; then `--bench run` with every block, which repeats the prelude, scores per voice and writes `report.md`.

## Non-functional realization

- **Baseline byte-identical, nothing committed moves (F3, F13), by construction.** With no `--voices`, `bench.sh` runs today's commands with today's arguments and `run` gets no voice block, the only source of a voice line; the visibility edits change no output. No write set holds `NativeBridge~/`, `expectations.json`, `audio/manifest.json`, `audio/tts/` or `audio/negatives/`; the render writes only the cache, the bench only `.scratch/`. Each rig gate `cmp`s a fast-only and a `--condition grid --seed 7` report against Phase 1's baselines from the unmodified tree, and checks `git diff main` empty for those paths.
- **No Kokoro at bench time (§8), structurally.** The bench reads WAVs through `VoxrWavReader` and JSON through `System.Text.Json`; nothing in `bench.sh` or the rig names the render or its venv; the record carries every Kokoro fact printed. `py` stays only where `bench.sh` already uses it.
- **Degraded cache (F8; §6).** Absent or partial is a status, exit 0 (register *Provisioning*). The clean reference failing stops in `voice` before the cache is read and in `run` before any world, exit 3.
- **Input boundary (§6).** Each stop of *Naming voices* and *Provisioning*, exit 2 with no report, plus a stale `voice/`; at render, *OOV and espeak-ng*'s refusals, a missing model file or a Python outside the bound. Never a silent drop or a made-up number.
- **Run time (§6; F11).** No budget is ruled. A clean voiced run adds one harness pass over 31 clips per voice, 372 for the 12 (F1), and a world per clip; a crossed run is about twelve times a grid run (§6). The header prints the voiced clip count from the verb's own count; Phase 4 measures the wall time on 12 stand-in voices (§10 Q5).
- **Determinism (F11).** Cached, digest-checked bytes; clips in id order, then manifest order (positives, negatives), then grid order; keyed streams; invariant-culture numbers at fixed precision; no path, clock or date in the report.
- **Hot paths and the device.** None touched (`Runtime/**`, `NativeBridge~/src/**` unchanged); no on-device check is owed.

## Risks, tradeoffs & open questions

- **The riskiest part waits on a human step.** The Kokoro speaker, token rule and espeak-ng check are written against `kokoro` 0.9.4 and `misaki` unrun until the install; the stand-in proves layout, truth, record and bench, not Kokoro's API. Phase 5 opens with the Kokoro render.
- **Whether `kokoro`'s install pulls espeak-ng is not established.** The researcher found it optional but not whether `misaki`'s English extra depends on a loader for it; if so the render refuses and F9 cannot be met by a default install — a stop for the maintainer's ruling, never a removed check.
- **Determinism is open until the probe (§10 Q1).** The design holds either way; only a re-render's claim changes, amended into *Determinism*.
- **The voice packs' licence is the repository's by inference.** The researcher saw no separate licence; the record and header say so.
- **The split case's truth may refuse a voice.** `speech_truth` needs one sub-floor run of at least the gap between segments; a voice pausing that long inside a segment is refused by name.
- **F6's significance clause is read as keying, not testing.** Tests are `bench-ab-report`'s (§7); every point states its n in phrases and rows are per voice, so a later resampling blocks by voice (R6 :370).
- **Crossed run time is unmeasured (§10 Q5)** — measured at Phase 4; no budget is ruled.
- **The voice count and list are provisional → the tuning pass (§10 Q6).** The 12 ids are one constant per language; the record's set check stops a disagreeing cache.
- **Coupling and drift.** The render depends on `generate.py`'s `build_case`, `write_wav`, `speech_truth` and constants: a change there changes the next render, and the record check marks the cache stale. Crossed audio depends on `BenchConditions`' pipeline, as `cond/` does. TTS-only evidence never ranks decoders (C12; adr-0008).
