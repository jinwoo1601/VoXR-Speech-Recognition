# feat-agc-filter — Architecture

Realizes `requirements.md` (Track **Full**; S1, F1–F18, §6, §10 items 2–6; item 1 is the tuning pass's) for design `agc-filter` (rules 1–13, adr-0001 – adr-0004). One native unit — a DC-normalised 219-tap FIR decimator, a 10 ms frame accumulator, AGC2's voice detector, estimators, adaptive digital controller and limiter from pinned `webrtc-audio-processing` 2.1 source, and the int16 conversion — links statically into `libvosk-bridge` on the device and in the harness, and ships to the Windows Editor as `voxr-frontend.dll` behind a small C ABI that `EditorMicBackend` calls by P/Invoke; `downsampler.h`, `agc.h`, `Agc.cs` and `Downsampler.cs` go. The driver is **one stream function** (rules 7–8): the unit's int16 output depends only on its configuration and the input samples since its last reset, never on a caller's chunking, so parity is a property of the unit, checked by a digest it computes over its own output, and §6's arbitrary chunk lengths are met once, where the samples are.

## Context & scope

On the device the front end sits in `recognition_loop` (`NativeBridge~/src/vosk_bridge.cpp` :87): a ring read of up to 4096 samples (:62, :104), `g_frontend->Process` (:126), `vosk_recognizer_accept_waveform_s` (:130-131); `BeginStream` runs at start (:184), `Reset` at destroy (:288) and `vosk_bridge_reset` (:329). `micGainTargetDb` (`Runtime/VoxrSpeechRecogniser.cs` :35-41) reaches `vosk_bridge_init` (:275) and the `FrontEnd` constructor (`vosk_bridge.cpp` :246). In the Windows Editor, `EditorMicBackend.ProcessChunk` (`Runtime/EditorMicBackend.cs` :412-450) passes mic chunks sized by frame time (`Tick` :371-410) or 4800-sample replay chunks (:456) to `voxr_fe_process` and the result to `libvosk` (`Runtime/Native/VoxrNative.cs` :17). The harness replays fixtures through the bridge in push mode, resetting per case (`NativeBridge~/harness/main.cpp` `RunHarness` :425-500); the `windows-x64` preset builds the bridge with MSVC (`NativeBridge~/CMakePresets.json` :5-19); `Runtime/Plugins/x86_64/` ships `libvosk.dll`, its MinGW runtime and `voxr-frontend.dll`.

**Owns:** `NativeBridge~/src/frontend/` (core, taps, C ABI), `NativeBridge~/cmake/webrtc_agc2.cmake`, `NativeBridge~/tools/design_decimator.py`, `NativeBridge~/harness/fe_probe.cpp`, `Runtime/Plugins/x86_64/voxr-frontend.dll`, `Runtime/Native/FrontEndNative.cs` (all new); the front-end lines of the bridge, its CMake, the harness and its pin, and `EditorMicBackend`; the `pause-lead` fixtures; the rig's F13 block and manifest keys; the probe in `Planning~/features/agc-filter/probe/`. **Untouched:** capture, ring buffer, result queue, the Vosk calls, the parser, R11, the pre-DSP input level (`vosk_bridge.cpp` :114-125; `EditorMicBackend.cs` :414-420), every public API (no Command 4), the non-Windows Editor. **Owed after G2:** `Documentation~/` (`native-bridge.md` :61's "never loads `libvosk-bridge`" stays true), `KNOWN_LIMITATIONS.md`.

## Decision register

- **One unit, two callers (F7, F8; adr-0001; §10 item 2).** The core, `voxr::FrontEnd`, is a static library (`voxr-frontend-core`) linked into `vosk-bridge` on both platforms; on Windows the same library plus a C ABI shim builds `voxr-frontend.dll`, which depends on neither `libvosk` nor the bridge. The device ships no second `.so`. *Why:* the Editor needs the DSP, not the bridge — capture and Vosk stay managed (rule 7). *Rejected:* the Editor loading `vosk-bridge.dll` (it links `libvosk.lib` and carries the bridge's process-global session — adr-0001 (b) by the back door); a front-end `.so` on Android (a load and an ABI with no device caller).

- **The C ABI — handle-based, blittable, caller-owned buffers (F7; `review` hot paths).** `src/frontend/voxr_frontend.h`: `voxr_fe_abi_version`; `voxr_fe_create(target_db)` → handle; `voxr_fe_process(h, in48k, n, out16k, cap)` → int16 samples written, whole 10 ms frames only; `voxr_fe_begin_stream`; `voxr_fe_reset`; `voxr_fe_get_stats` (a plain struct: gain dB, last frame's pre- and post-gain RMS, input and output counts and output digest since the last reset or stream start); `voxr_fe_destroy`. Cdecl, no strings, no callbacks, no allocation after create. *Why:* arrays marshal by pinning, so a chunk allocates nothing; a handle lets tests run two units and each backend own one. *Rejected:* a singleton ABI like the bridge's (no independent units for tests); float output (the int16 conversion would stay in each caller). **Amended 2026-11-06:** "no allocation after create" covers the per-chunk path, `voxr_fe_process`; `voxr_fe_reset` (and create) may allocate, the cold `Reset` rebuilding the AGC2 objects (*Lifecycle*) — the human's ruling at Phase 3's plan.

- **Frame buffering lives in the unit (§6 robustness; F9).** Each input sample enters the decimator on arrival; every third yields a 16 kHz sample into a 160-sample accumulator; AGC2 runs per completed frame; only whole frames are emitted, a remainder waits. Callers size `out16k` for `n / 3` plus one frame. *Why:* the bridge reads whatever the ring holds (`recognition_loop`) and the Editor whatever the frame time gave (`Tick`) — neither a multiple of 3 or 480. *Rejected:* buffering in each caller (two copies of what parity depends on); multiples of 480 imposed on callers (the remainder bookkeeping moves into both).

- **The decimator — a committed, generated table, direct form at kept samples (F1, F2, F17; adr-0002; §10 item 5).** `design_decimator.py` (numpy, the fixtures venv) designs the R4 candidate — Kaiser, 95 taps, 7.8 kHz, β 8.5 — normalises the taps to sum 1 in double and writes `decimator_taps.h` as float literals, parameters in its header; the filter keeps a contiguous history and evaluates the dot product only at every third input, in scalar C++. If Phase 3 misses F1's bar, a design that clears it replaces the table, recorded under `## As-built deltas` (F17). *Why:* a table is the same bits under MSVC and clang, and its generator records the provenance the 15-tap table lacked. *Rejected:* taps designed at run time (two C runtimes' `sin`/Bessel give two tables); a hand-typed table; SIMD intrinsics (a second arithmetic path per architecture before any cost shows). **Amended 2026-11-07:** as built, the fallback fired: `r4` missed F1's bar at Phase 3, and the committed table is `f1` — Kaiser, 219 taps, cutoff 8000 Hz, β 5.65326 (`decimator_taps.h` :13-17), the generator's default; "the R4 candidate" above is the design Phase 3 started from (Phase 3, *F1 fallback*).

- **The AGC2 driver — upstream's classes composed in `gain_controller2.cc`'s order (rules 3–6; F4, F5, F10; adr-0003).** Per frame: the RNN voice detector's speech probability; the speech-level and noise-level estimators and saturation protector; the adaptive digital controller; the limiter (recon, WebRTC APM research, "Order"). The unit thus holds the applied gain (for stats and F10's tests) and the speech probability (reachable for R16, F3). *Why:* `GainController2` keeps gain and probability private and takes APM's `AudioBuffer`, pulling buffer and band-split code into a subset adr-0003 limits to gain controller, voice detector, limiter and `common_audio`. *Rejected:* `GainController2` behind its config struct — its extra code (*Why*) lies beyond adr-0003's subset, so it is no fallback: a failed composition stops Phase 1 for the human, a reopen of adr-0003 (b). **Amended 2026-11-06:** Phase 1 composed the classes cleanly, so the stop did not fire. *Order as built* (2.1 `gain_controller2.cc`): voice detector, noise-level estimator, speech-level estimator, saturation protector, adaptive digital controller, a fixed-gain stage (`GainApplier`), limiter; the chain follows the source, so the noise-level estimator precedes the speech-level one and a fixed gain precedes the limiter. *APIs:* the speech probability is `VoiceActivityDetectorWrapper::Analyze`, public, so it is reachable for R16. *Constants (§10 item 4):* detector confidence threshold 0.95, confident-frame count 12, speech-level time to confidence 400 ms, noise-floor update period 500 frames (5 s); the full table is `Planning~/features/agc-filter/probe/report.md` `## Constants`. *Gain readout:* upstream has no getter (the applied gain is private), so the unit reads it as the frame-energy ratio across the adaptive stage; a zero-energy frame holds the previous reading, the first being the 15 dB initial gain (`## Gain readout`).

- **Configuration (F4, F11, F17; rules 6, 11).** One struct inside the unit: adaptive digital on, headroom = −`target_db` (−18 → 18 dB, a −18 dBFS speech target), max gain 50 dB, initial gain 15 dB, 6 dB/s, output noise ceiling −50 dBFS, fixed gain 0 dB; no input-volume controller, noise suppressor or echo canceller is compiled. The ABI takes only `target_db`. *Why:* the field keeps its name and meaning with no migration, and the harness `gain` pin stands; every other value is the tuning pass's (§7). *Rejected:* AGC2 knobs on the ABI or as serialized fields (a tuning surface before the tuning pass; `I1` :59's migration hazard). **Amended 2026-11-06:** the configured headroom = −`target_db` stands and the code is unchanged, but the speech level the controller steers to is −(headroom + the saturation protector's headroom), because 2.1 adds that headroom to the speech level before it computes the gain (`adaptive_digital_gain_controller.cc` :138); "a −18 dBFS speech target" above reads as the configured headroom only. F11's +6 dB test therefore needs input in the boost region, below that effective target: lead A sits above it and takes 0 dB at both −18 and −12. The tuning pass judges the level — the human's rulings at Phase 3's Step 8 and Phase 6's pickup.

- **Pinned source and the CMake integration (F3, F16; adr-0003; §10 item 3).** The 2.1 tarball and the abseil archive its meson wrap names sit in `NativeBridge~/vendor/` (gitignored; a human download); `webrtc_agc2.cmake` holds both SHA-256 pins, hashes each archive at configure, stops naming file and hashes on a mismatch, and extracts the verified archive into the build directory (`file(ARCHIVE_EXTRACT)`, CMake ≥ 3.18). The WebRTC subset is an explicit source list (the composed classes' link closure); abseil builds by `add_subdirectory`, `EXCLUDE_FROM_ALL`, only `absl::` targets linked. *Why:* agents cannot download, so the fetch is the human's and the check is the build's; only verified bytes compile. *Rejected:* download at configure (refused to agents; not offline); committing the source (the pin would guard nothing review does not); a CMake port of upstream's meson build; listing abseil's files (re-derives its per-platform selection). **Amended 2026-11-06:** the source list is the link closure read from the pinned tree's `meson.build` files, with the `rtc_base` and `system_wrappers` completions (and `winmm`) that the first MSVC links named as unresolved externals, part of deriving that closure; it links, and nothing shows it minimal (`probe/report.md` `## Source list`). Pins: `## Pins`; the abseil pin equals the 2.1 wrap's `source_hash`; the 2.1 tarball's published-checksum status is none reported. Abseil takes no patch. MSVC does not get `-msse2`: SSE2 is the x64 baseline.

- **Symbols and runtime (F3; adr-0003's ODR risk).** All front-end, WebRTC and abseil targets compile with hidden visibility and inlines; the `.so` link adds `-Wl,--exclude-libs,ALL` beside `--strip-all`; only `vosk_bridge_*` (`vosk_bridge.h` :6-14) and `voxr_fe_*` export. The Windows build uses the static MSVC runtime project-wide (`CMAKE_MSVC_RUNTIME_LIBRARY`), so the DLL needs no runtime DLL. *Why:* local abseil symbols cannot collide with another plugin's abseil in the APK; a DLL with no runtime dependency cannot fail on a runtime version the Editor process chose. *Rejected:* a version script alone (static-library symbols leak); the dynamic runtime (`/MD`). **Amended 2026-11-06:** do not undo — (1) `ABSL_MSVC_STATIC_RUNTIME ON` is required beside the project-wide `CMAKE_MSVC_RUNTIME_LIBRARY`: abseil's own `CMakeLists.txt` sets `CMAKE_MSVC_RUNTIME_LIBRARY` and builds `/MD` unless that option is on; removing it reintroduces a runtime-DLL dependency. (2) `WEBRTC_ENABLE_SYMBOL_EXPORT` is omitted on purpose: it turns `RTC_EXPORT` into exports. (3) The `.so` also exports `JNI_OnLoad`, which "only `vosk_bridge_*` … export" omits: the committed `.so` exports 17 names, 16 `vosk_bridge_*` plus `JNI_OnLoad`, and all three probe variants equal them.

- **Lifecycle — `Reset` versus `BeginStream` (F10; rule 10).** `Reset` is cold: decimator history, remainder, all AGC2 state (estimators, gain, detector state, confident-speech run, limiter envelope), stats, digest. `BeginStream` clears history, remainder, stats and digest and keeps all AGC2 state. `reset_pipeline` stops touching the front end; `start_internal` calls `BeginStream`; init, destroy and `vosk_bridge_reset` (between its stop and restart) call `Reset`. In `EditorMicBackend`, `Start` begins a stream, `Reset` and `StartPlayback` reset, `Release` destroys. *Why:* the learned level is AGC2's state; history and an unfinished frame are stream continuity, and keeping them would splice pre-stop audio into the next session. Replay starts cold as the harness does per case, keeping replays order-independent. *Rejected:* keeping everything (the splice); resetting at start (today's, which rule 10 replaces); replay inheriting the mic session's level. **Amended 2026-11-06:** the cold `Reset` rebuilds the three AGC2 objects that carry that state — `VoiceActivityDetectorWrapper`, `NoiseLevelEstimator` and `AdaptiveDigitalGainController` — because the pinned 2.1 source gives them no reset (`agc2/vad_wrapper.h` :27-74, `agc2/noise_level_estimator.h` :22-28, `agc2/adaptive_digital_gain_controller.h` :26-49); `Reset` and `BeginStream` are rare control calls, so the allocation is accepted (*The C ABI*), and no source patch is made — the human's ruling at Phase 3's plan.

- **Parity — a unit-owned digest, pinned by the harness (F9, F14; rule 8).** The unit folds each int16 it emits into a 64-bit FNV-1a digest and counts samples in and out. The bridge publishes that snapshot after each chunk through a new export, `vosk_bridge_get_frontend_stats`; the harness pushes a fixture, waits until the unit's input count equals its length, reads the digest, then pushes its padding, and pins `frontEndDigest` per case — written only by `--write-baseline`, compared on every other run. A PlayMode test replays every manifest fixture through the backend's playback seam in chunk lengths multiples of neither 3 nor 480 and asserts count and digest equal the pin; an EditMode test asserts chunk invariance on the DLL alone. *Why:* both callers' real paths run, the pin is harness-written, nothing large is committed. *Rejected:* committed golden samples (megabytes, pinned outside a harness run); a C# re-implementation as the reference; claiming device/host bit-identity (*Risks*). **Amended 2026-11-06 (pickup 4):** the digests are host-scoped to the pinning host's CPU features, with no source patch: on x64 the AGC2 wrapper's 16→24 kHz resampler is host-selected AVX2, SSE or C with no injection point, so a pin may fail on a host with different features. The harness README says so when Phase 4 pins — the human's ruling.

- **The evidence instrument — `fe-probe` (F1, F6; §6; §10 item 6).** A harness executable linking only `voxr-frontend-core` and the WAV reader prints one JSON report and exits non-zero when a bar fails: F1 on the decimator alone (the table's response across 0–8 kHz and above 8.4 kHz, confirmed by sine sweeps through its `Process`); F6 on composites of TTS command speech from `Tests~/Fixtures/audio/tts/` (speech the detector accepts) with digital silence, −60 dBFS noise and broadband bursts, reading the per-frame gain; host cost per frame; the added latency at worst-case remainder. Standing guards are EditMode tests over the DLL under Command 1. *Why:* the decimator alone is reachable only in C++, and the evidence lands in the phase that builds the unit. *Rejected:* the decimator on the ABI for a test (test surface in a shipped DLL); plots read by hand (no bar, no exit code). **Amended 2026-11-06:** do not undo — `FrontEnd::Process`'s fifth argument, `float* out_float_s16 = nullptr` (the post-limiter floats `FloatS16ToInt16` reads), exists only for `fe-probe`'s F5 sign check: C++ only, never on the C ABI (`voxr_frontend.cpp` calls the four-argument form; seven exports), and Phase 4's bridge call takes the default. **Amended 2026-11-06 (pickup 4):** the human confirmed that the rejected "test surface in a shipped DLL" is the exported C ABI only, so `Process`'s non-exported fifth argument stands as built.

- **The Editor's DLL load and diagnostics (§4.2; §6).** `EditorMicBackend.InitialiseAsync` calls `voxr_fe_abi_version` before the model loads, in its own `try`: `DllNotFoundException`, `EntryPointNotFoundException` or an unexpected version fire `ModelLoadFailed` through `fireError`, naming `voxr-frontend.dll` and `Runtime/Plugins/x86_64/`, and initialisation fails. `PreAgcRms`, `PostAgcRms` and `AgcGain` read the unit's stats (`AgcGain` linear from dB), so `VoxrSpeechRecogniser` (:88-92), `VoxrDebugWindow` (:205-211) and `AudioMetricTests` are unchanged. *Why:* the existing catch names `libvosk.dll`, the recogniser's the Android bridge (`MarkBridgeUnavailable`, `VoxrSpeechRecogniser.cs` :729-740). *Rejected:* a first call inside `ProcessChunk` (failure mid-capture, on the per-frame path); any managed fallback (rule 7; §4.2).

- **Fixtures (F12; rule 12).** `generate.py` gains `leadSilenceSeconds` (per entry, else `LEAD_SILENCE_S`) and `noiseFloorDbfs` (seeded white noise at that RMS across the whole fixture). The 15 new entries, category `pause-lead`, 2.0 s, −60 dBFS, are one per command case among the 16 demo (non-`ladder`) cases — the 14 single phrases and the split case, whose `segments` and `gapSeconds` stay after the lead pause — with the source's phrase or segments, `layer`, intent and slots, plus `firstWord` (*The A/B*); none for the silence case (no command) or the `ladder` cases (F12). `--write-baseline` pins them on **today's** front end. Tier B skips `pause-lead` until Phase 5, since until then it replays the AGC being retired. *Why:* a pause at a real floor is what makes today's AGC climb (design §3); digital silence is failure (d), already in the corpus. *Rejected:* noise in the pause only (an artificial step at the onset). **Amended 2026-11-06:** do not undo — (1) the noise seed is `zlib.crc32(Path(case["file"]).name.encode("utf-8"))`, the CRC-32 of the file name **with** `.wav`; renaming a `pause-lead` WAV, or changing the seed form, changes its noise, so that fixture is regenerated and re-pinned under F14, never hand-patched. (2) The Tier B skip carries no code comment (`.claude/references/core/coding-conventions.md` `## Comments and docstrings`): this bullet is the only record of why `VoxrWavReplayTests.cs` `ManifestFileNames` drops `pause-lead`, and Phase 5 removes the filter.

- **The A/B (F13, F14; rules 12–13).** Side A is a `--dump` of the Phase 2 tree (kept and re-dumpable: *Amended*); side B is Phase 4's. `joined.sh --vary decoder` runs both at one parser ref, at the parser and recogniser layers, over the whole manifest; F13's set is its non-`ladder` cases — the 16 demo cases and the 15 `pause-lead` — and the `ladder` rows are reported outside it. `JoinedReport.cs` gains an F13 block per side, emitted only when the manifest its headers name (read by `JoinedInput.ReadManifest`) holds `pause-lead` cases: correct fires, wrong-intent and false fires over F13's set, and the first-word retention line — the share of `pause-lead` cases whose space-joined finals start with the case's `firstWord`. `firstWord` is a manifest key on each `pause-lead` entry, written with it: the phrase's first word, the split case's first segment's, and for the filler case the first word after its filler, `launch` (F13); `generate.py` ignores it, and `JoinedInput`'s manifest key set admits it with `leadSilenceSeconds` and `noiseFloorDbfs`, since an unknown key stops the run. Flips are listed with transcripts, the human rules, and only then does `--write-baseline` re-pin. *Why:* side A is main's front end on the full corpus with no switch in shipped CMake; a key states the filler case's word where a rule over `phrase` would need the grammar to find it, and the split case has no `phrase`. *Rejected:* a `legacy|agc2` CMake option (two front ends in source, against rule 7 and F2); side A from `main` (no `pause-lead` fixtures); the first word derived from `phrase` or `segments` (the filler case defeats it). **Amended 2026-11-06:** side A as built is `.scratch/agc-filter/a.jsonl`, dumped over the 52-case manifest and re-dumpable from `ce4aa1c`, the Phase 2 build commit, which holds every dump input; Phase 4's side B joins against it. **Amended 2026-11-06 (pickup 4):** the retention line skips a leading `[unk]` token before comparing with `firstWord`, so the filler and noise-prefixed cases can be retained; Phase 4 changes that one line in `JoinedReport.cs` before the A/B, and side A's dump stands, the rule reading finals at report time — the human's ruling.

## Seams

**Components.** *Core* — `voxr::FrontEnd`, `decimator_taps.h`, the WebRTC subset and `absl::` targets (F1–F6, F17). *C ABI* — `voxr_frontend.h/.cpp`, Windows only (F7, F8). *Bridge* — `vosk_bridge.cpp/.h` (F2, F9, F10). *Editor* — `FrontEndNative.cs`, `EditorMicBackend.cs` (F7–F11). *Harness* — `main.cpp` pins and lifecycle check, `fe_probe.cpp` (F1, F6, F9, F10, F14). *Build* — `CMakeLists.txt`, `webrtc_agc2.cmake`, the preset, `build.sh` (F3). *Fixtures and rig* — `generate.py`, the manifest, `JoinedInput.cs`, `JoinedReport.cs` (F12, F13).

Cite: `vosk_bridge.cpp` (`recognition_loop`, `start_internal`, `vosk_bridge_init`, `vosk_bridge_reset`) ↔ `src/frontend/front_end.h` (`voxr::FrontEnd`).
- **Editor backend → DLL.** `InitialiseAsync` probes (`ProbeFrontEnd`, :78), then creates after the model and recogniser (:114), a null handle freeing both; `ProcessChunk` calls `voxr_fe_process` into `_int16Buffer` (:422), throws on a negative count, and hands the result to Vosk (:430); lifecycle calls per the table below; `StartPlayback` takes an optional `chunkSamples` (default 4800; under 1 → `AudioDeviceUnavailable`). Cite: `EditorMicBackend.cs` ↔ `Runtime/Native/FrontEndNative.cs` (`[DllImport("voxr-frontend")]`) ↔ `voxr_frontend.h`.
- **Recogniser → backend.** Unchanged: `micGainTargetDb` and `FireError` cross at `VoxrSpeechRecogniser.cs` :251-256. Cite: `VoxrSpeechRecogniser.InitialiseAsync` ↔ `EditorMicBackend.InitialiseAsync`.
- **Bridge ABI → harness.** `vosk_bridge_get_frontend_stats` (no C# binding) feeds the per-case digest pin and a lifecycle check after init and before `set_grammar` (speech: gain differs from the cold gain; stop, start, replay: gain unchanged, digest unlike the cold run's; `vosk_bridge_reset`: initial gain; else the bridge is destroyed and the run exits 2). Cite: `vosk_bridge.h` ↔ `main.cpp` (`RunHarness`).
- **Harness → pin → Editor test.** Cases in `expectations.json` gain `frontEndDigest` and `frontEndSamples`; the parity test reads the file from the package's `NativeBridge~/harness/`. Cite: `main.cpp` :495-499 ↔ the `Tests~/Runtime/` parity test.
- **Build → vendor.** `CMakeLists.txt` includes `cmake/webrtc_agc2.cmake` before its targets (:48); the module reads only `vendor/` archives and writes only the build directory.
- **Rig → dumps.** The F13 block reads the dumps' finals and, through `JoinedInput.ReadManifest`, the manifest's `category` and `firstWord`. Cite: `JoinedReport.cs` ↔ `JoinedInput.cs` ↔ `Tests~/Fixtures/audio/manifest.json`.

**Flow — one 10 ms frame.** (1) A caller passes n samples of 48 kHz float; each enters the decimator, every third yields one 16 kHz sample into the accumulator. (2) At 160: the detector scores the frame; the speech, noise and saturation estimates update; the gain moves toward −(speech level + saturation headroom + headroom), clamped to [0, 50 dB] and capped by −50 dBFS minus the noise level, up only after the confident-speech run, down always, at most 6 dB/s (rules 3–4). (3) The gain is applied, the limiter bounds the frame, the clamped int16 conversion follows (rule 5), and the samples fold into the digest. (4) Whole frames return to the caller for Vosk; a remainder waits for the next call.

**Lifecycle (F10).**

| Event | Device | Editor | Front end |
|---|---|---|---|
| Init / re-init | `vosk_bridge_init` | new backend | created cold |
| Start | `start_internal` | `Start` | `BeginStream`: level kept |
| Stop | `vosk_bridge_stop` | `Stop` | none; an unfinished frame is dropped at the next start |
| `ResetRecogniser()` | `vosk_bridge_reset` | `Reset` | `Reset` |
| Replay arm / harness case | `vosk_bridge_reset` per case | `StartPlayback` | `Reset` |
| Destroy / release | `vosk_bridge_destroy` | `Release` | cold / destroyed |

**State ownership.** All front-end state lives in `voxr::FrontEnd`, one instance per caller — `g_frontend` in the bridge, the backend's handle in the Editor; what `Reset` and `BeginStream` clear is R *Lifecycle*'s. The bridge loop alone writes `g_frontend`; readers see the published snapshot.

## Non-functional realization

- **Size (§6; F18).** Only the subset's link closure compiles; LTO, `--strip-all`, hidden symbols and `--exclude-libs` let the linker drop the rest. Probe (Phase 1): arm64 growth 100,632 bytes (`libbridge-with.so` 157,384 against `libbridge-bare.so` 56,752; `probe/report.md` `## Sizes (bytes)`), DLL 316,416; four absolute `__FILE__` paths in its `.so` made the growth build-path dependent. Shipped: `.so` (Phase 4, `build.sh`) 159,928 bytes, 103,176 over today's 56,752; DLL (Release) 320,512; APK (Phase 6): contribution 44,162,646 stored / 50,228,787 uncompressed under 70,000,000 (F18), whole 99,483,877.
- **Cost and ≤ 15 ms added latency (§6).** 219 multiply-adds per output sample, AGC2 once per frame, no allocation or lock in `Process`. `fe-probe` measures host cost per frame and the added latency — filter delay plus the worst-case remainder — recorded here in Phase 3; the bridge's read size is unchanged and not the front end's.
- **Arbitrary chunk lengths (§6).** Structural: the accumulator makes output a function of the stream; the stats' counts expose a dropped or duplicated sample, and the parity test feeds non-multiples of 3 and 480.
- **DLL load failure (§4.2).** Initialisation fails with a named error before any audio flows; the static runtime removes a dependency that could fail to load.
- **Determinism (F9).** Committed taps, scalar arithmetic, no fast-math, `-ffp-contract=off` on clang; parity is asserted on the host, where both callers run one x64 build.
- **Hot paths.** `NativeBridge~/src/**` and `Runtime/Native/**` gain one call per chunk and a snapshot store; the Editor's managed per-chunk work shrinks to the P/Invoke and the Vosk call.
- **Platform.** The DLL's import settings copy `libvosk.dll.meta` (:13-32): Editor, Windows, x86_64, no player; non-Windows Editors compile none of the backend (`EditorMicBackend.cs` :7).

## Risks, tradeoffs & open questions

- **AGC2 internals confirmed.** R *The AGC2 driver*'s amendment; `probe/report.md` `## Classes and APIs`.
- **Host-dependent digests (ruled).** Host-scoped, no patch: R *Parity*'s amendment.
- **Embedded build paths (resolved, Phase 4).** The shipped build maps source and build directories (`-ffile-prefix-map`, `CMakeLists.txt` :41-43, ahead of the AGC2 include so abseil and `webrtc_agc2` inherit it), so its `.so` embeds none of the four paths the probe's did (*Size*).
- **First-word retention and `[unk]` (ruled).** A leading `[unk]` is skipped: R *The A/B*'s amendment.
- **F11's step in the boost region (open, the tuning pass).** Phase 5's F11 test (≥ 30 s, last 10 s) shows 6.02 dB for −24 → −18 and 6.01 dB for −18 → −12, so the mapping holds on long input; `fe-probe`'s lead B still rises 3.16 dB, cause unproven (the 6 dB/s rate over the lead's length and the noise ceiling are both consistent). The tuning pass judges it.
- **Device versus host.** F9 is checked on the host; arm64 shares the source, not the bits; Phase 6 is the device evidence.
- **Readings.** Rule 1's "no resampler … inside APM" is read as the signal path; the detector's internal 24 kHz analysis resampling (recon) is AGC2's own. F11 rests on §8's assumption that AGC2's speech level is a dBFS level; today's −18 dBFS was mean-absolute (design §2), so the A/B shows what the decoder hears. Command 3's "never a re-pin" on exit 1 holds: Phase 4 re-pins only after the human's ruling.
- **Failure (e) unmeasured.** Hot Quest speech may leave the limiter compressing at the 0 dB floor (design §3); the tuning pass reads it.
- **Tradeoffs.** An unfinished frame (< 10 ms) at stop is dropped; a loaded DLL cannot be replaced while the Editor is open (Command 1 runs with it closed); the parity test decodes every fixture, so Command 1 grows.
- **Drift watch.** The SHA-256 pins live in the module and the README check; `build.sh` (:53, android-29) and the recipe (:58, android-27) disagree on the arm64 platform level — the probe uses the recipe's; Command 3 does not run `fe-probe`, which only a binding change would add.
