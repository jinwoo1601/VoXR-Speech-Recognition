# trees-fill — Architecture

## User story

As the VoXR maintainer, I want the `trees` binding filled so each branch runs in its own git worktree, so that branches can run side by side while every Unity test run still goes through the one host by the `host-repoint` bracket.

This feature is lite: it has no requirements doc, and its acceptance is the backlog row's criteria A1-A4 below.

## Context & scope

Backlog row, quoted whole from `Planning~/design-docs/parallel-trees.md` §6 (locked at G1 2026-11-05):

> **Feature:** `trees-fill`
>
> **Scope:** Fill the `trees` binding (`.claude/bindings/vc-git.md` :19-20) with the §1 values, and change the knock-on sites of §4: the vc binding's Branch procedure tail (:8), the `verification` binding's Run from (:5) and Tree-safe (:14), and the `session-launch` Launch command's `<tree>` note (`.claude/bindings/core.md`). Path: `development`. **Lite** (adr-0003): no requirements doc; acceptance — (1) `.claude/bindings/vc-git.md` `## trees` carries every §1 value — Hub, Location, Create, List, Clean, Catch-up and Remove procedures, Writer-branch naming, Pool `none`, Release files — and `doctor` reads `trees` filled; (2) the Branch procedure cuts each branch in its own tree by the Create procedure, no longer "in the one checkout"; (3) the `verification` binding's Run from names the root of the tree the session runs in, and Tree-safe reads `yes` under the host bracket; (4) the `session-launch` Launch command's `<tree>` note no longer says `trees` is none.
>
> **Depends on:** `host-repoint`.

The criteria, numbered as the row's (1) to (4):

- **A1.** `.claude/bindings/vc-git.md` `## trees` carries every §1 value — Hub, Location, Create, List, Clean, Catch-up and Remove procedures, Writer-branch naming, Pool `none`, Release files — and `doctor` reads `trees` filled.
- **A2.** the Branch procedure cuts each branch in its own tree by the Create procedure, no longer "in the one checkout".
- **A3.** the `verification` binding's Run from names the root of the tree the session runs in, and Tree-safe reads `yes` under the host bracket.
- **A4.** the `session-launch` Launch command's `<tree>` note no longer says `trees` is none.

**What the locked design commits the feature to:**

- The `trees` values of §1 (`Planning~/design-docs/parallel-trees.md` :103-109), one each:
  - Hub: `D:\Workspace\VoXR-Speech-Recognition`, on `main`, holding `memory/`; a command runs in another tree by `git -C "<path>" <command>`.
  - Location: `D:\Workspace\VoXR-Speech-Recognition.trees\<branch>`, and writer trees as `<branch>--<unit>` (adr-0003).
  - Create, List, Clean, Catch-up and Remove: the vc-git pack's procedures, as in the harness repo's filled binding (`D:\Workspace\harness\.claude\bindings\vc-git.md` `## trees`); Remove is by `.claude/references/vc-git/tree-remove.py`, and Catch-up merges `main` with `merge-attributes.txt`.
  - Writer-branch naming: `<branch>--<unit>`, cut from the branch's tip. Pool: none (adr-0004).
  - Release files: `CHANGELOG.md`, keeping both sides' `## [Unreleased]` entries, this branch's first; and `.claude/`, including `.claude/harness.json` but not `.claude/bindings/*.md`, regenerated by `upgrade` and never merged by hand (adr-0005).
- The knock-on sites of §4 (:137-147) that the row names: `.claude/bindings/vc-git.md` :8 and :19-20, `.claude/bindings/unity.md` :5 and :14, and `.claude/bindings/core.md` `## session-launch`. One difference from §4: the row names `unity.md` :5 Run from and :14 Tree-safe, and does not name §4's `unity.md` :6-7 or the recipe sites, because `host-repoint` (merged, PR #188) already built those.
- The hand-off in §4: the hub session `voxr-hub` takes on the trees contract's hub roles, and `memory/` writes become hub operations.

**G0 ruling:** the maintainer, 2026-11-05, in conversation by AskUserQuestion, was asked to agree the feature's scope, user story, track, path and lane, with the options "Agree as shown (Recommended)", "Agree, and fold in HRP-1" (a Unity-run timeout in `host_run.py`: a scope change) and "Not now", and ruled **"Agree as shown (Recommended)"**. Every default was taken unchanged: the user story as drafted; track lite (the row's mark `**Lite** (adr-0003)`); path `development` (the doctor read prints `development`); lane feature; HRP-1 stays deferred, outside this scope.

**In scope:**

- Fill `.claude/bindings/vc-git.md` `## trees` (:19-20) with the §1 values.
- Change the knock-on sites the row names: the vc binding's Branch procedure tail (:8), the `verification` binding's Run from (:5) and Tree-safe (:14), and the `session-launch` Launch command's `<tree>` note.

**Out of scope:**

- HRP-1 (`host_run.py` runs Unity with no timeout), which stays in STATUS `## Deferred`.
- TestGround's own `trees`, which stays `none` (§4 *Does not decide*).
- Core-pack changes, which go to harness-hub.
- Device testing of a branch.
- The two stale auto-memories §4 names, which are the PM's to update after G2.
