# feat-bench-fast-replay — Architecture

Realizes `Planning~/features/bench-fast-replay/requirements.md` (Track **Full**; S1, F1–F13, the §6 NFRs, §10 items 1–4), the first feature of design `audio-bench` (§6), fast mode only. A fast run is the verdict harness's own `--dump` run, unchanged — 16384-sample pushes into the real bridge (`NativeBridge~/harness/main.cpp` `PushAll` :156-183) — whose schema-2 dump already carries each result's `consumed` samples; a new `--bench` mode of the joined rig reads that dump with the generator's speech-boundary truth, refuses every number unless each case's finals equal the pins, drives each case's timeline through the rig's staged recogniser unchanged, and writes one deterministic report of audio-time offsets from end of speech beside command accuracy, WER and calibration. The governing driver is **the tie to the pinned path** (requirements §3; adr-0003; F3, F13): every number comes from the binary, push size, model copy and pins Command 3 uses, nothing under `NativeBridge~/` changes, and a run that cannot show the tie shows nothing.

## Context & scope

Three merged instruments hold most of the path. Under `--dump` the harness writes, per `result`, its `final` flag, Vosk's payload and the `consumed`/`origin` pair read through `vosk_bridge_get_result_position` (`main.cpp` `DrainResults` :107-151; `vosk_bridge.h` :71), per `case` the WAV's `samples` and `sampleRate` (`DumpCase` :84-91), and drains until `vosk_bridge_get_consumed()` equals the pushed count before stop (:461-478). The bridge zeroes its consumed counter per session (`vosk_bridge.cpp` :186), so a case's WAV sample 0 is `consumed` 0, and advances it by reads of up to `kReadChunkSize` 4096 (:62, :104-111), queuing every final, changed partial and tail final with it (:134-149, :164-167). The joined rig (`Planning~/features/coverage-in-selection/ab-rig/`) reads the dump strictly (`JoinedInput.ReadDump`), stages the shipped `Runtime/Commands/VoxrCommandRecogniser.cs` and `VoxrSpeechRecogniser.cs` (`stage.sh` :58-83), replays each case on a 90 Hz frame clock (`JoinedRecogniser.TickRate` :38, `ScoreCase` :262-317) and classes the first `OnCommandRecognised` fire (`VoxrCommandRecogniser.cs` :128; `JoinedScorer.Classify` :93-119). None has end of speech (the rig's delay counts from end of audio, `JoinedRecogniser.cs` :301-303), a single-run report, WER, ECE or NCE (design §1).

**Owns:** the generator's truth mode and the manifest's `speech` key; the rig's `--bench` mode and `bench.sh`. **Edited:** `Tests~/Fixtures/generate.py`, `Tests~/Fixtures/audio/manifest.json` (`speech` only); in the rig `JoinedInput.cs` (reads `speech`, `phrase`, `segments`), `Joined.cs` (two guards, `FirstDifference` and `JsonArray` made callable), `Program.cs` (`--bench` hook), `Rig.csproj` (the paired `flag bench` comment), `stage.sh` (bench files and `Runtime/Testing/VoxrWavReader.cs` in the recogniser stage). **Untouched (F13):** `NativeBridge~/`, `expectations.json`, the committed WAVs, `Runtime/`, Command 3. **Out:** paced mode, conditions, voices, A/B (requirements §2).

## Decision register

- **Fast mode is the harness, unchanged (F2, F13; adr-0002, adr-0003).** A run invokes Command 3's build, `NativeBridge~/build-windows/bin/vosk-bridge-harness.exe`, with `--dump`, on a confgen model copy and Command 3's fixtures; the bench never links the bridge, so pushes, padding (`main.cpp` :420), per-case reset and dump are the pinned path by identity, and F2 is verify-only. Harness exit 0 or 1 continues (the self-check decides); exit 2 stops with its stderr. *Why:* the pins come from this binary (adr-0003). *Rejected:* a bench executable linking `vosk-bridge` (a second push loop kept equal to `PushAll` by hand; Command 3 triggered); the run without `--dump` (no positions).

- **Stamps — the bridge's `consumed`, read off the dump (§10 item 3, F4; adr-0001).** A stamp is `consumed` ÷ the case's `sampleRate`. The **first partial** is the first non-final result with a non-empty `partial` (the bridge queues an empty one first, `vosk_bridge.cpp` :143-149); **each final** is every final with non-empty `text`, the pins' rule (`main.cpp` :144-148); the **command event** is the first fire's frame time (`Outcome.FireTimes`[0]). Each offset is signed, stamp minus the `end` of the case's last `speech` segment, computed from integer samples; a missing stamp prints `none`; no aggregate (R3). *Why:* consumption at emission is adr-0001's audio clock, already exact per result in the dump, so recording is reading. *Rejected:* a wall clock (`bench-paced-mode`); word `end` times (alignment, not emission); a bridge stamp (F13, a scope stop).

- **Self-check — finals only, against the committed pin, before anything is scored (F3; adr-0003).** After the readers, every dump case's non-empty finals are compared ordinally with the pin's `expectedFinals` (`JoinedInput.ReadPin` :624-666) and failed decodes listed; on any difference each differing case is printed with expected and actual, no report is written, exit 3. `--pin` defaults to `NativeBridge~/harness/expectations.json`, so F3's mutation runs on a `.scratch/` copy. The header fields the joined kill check also compares — `gain`, `libvosk`, `modelConf`, `grammar` (`Joined.cs` :214-277) — are named in the report (F10), the grammar also guarded as below. *Why:* F3's rule is the finals; a configuration §4.2 lets the maintainer name, such as a profile that keeps every final, must be quotable. *Rejected:* the joined kill check verbatim (refuses every non-pinned decoder configuration); the harness's exit code (also fails on host-scoped front-end digests, `NativeBridge~/harness/README.md` *The baseline*). Ruled 2026-11-08 by the maintainer at the plan stop (finals only, over the joined kill check verbatim).

- **Truth derivation — the generator's layout bounds a floor scan of the committed PCM (§10 item 1, F1; adr-0006).** `generate.py` gains a truth mode: per committed WAV it takes the layout it built — lead `leadSilenceSeconds` or `LEAD_SILENCE_S`, tail `TAIL_SILENCE_S`, gap `gapSeconds`, each as its own `silence()` length (:29-30, :76-77, :80-115) — and scans only the block between lead and tail at the silence floor, **−40 dBFS per sample, the generator's `TRIM_DBFS`** (:36): a segment runs from its first sample at or above the floor to after its last. n `segments` split at the n−1 longest sub-floor runs, each at least `gapSeconds` with the next longest shorter, else the case stops by name; stops also for floor-reaching noise in a pause-lead clip's lead and for a block with no sample at the floor; the silence entry gets none. The mode needs only the standard library (`py`, no Piper venv); regeneration runs it on the WAVs it has just written. *Why:* the generator placed the words (adr-0006 (A)), but Piper is not byte-deterministic (:12-14), so truth must come from the committed bytes (§4.1); Piper's edge silence makes the bare block too long for F1's check, which is stated against a floor; `TRIM_DBFS` already trims ladder segments (:63-73). *Rejected:* re-rendering (moves every WAV, F13); a detector on the replayed audio (adr-0006 (B)); the bare block bounds (fails F1). Ruled 2026-11-08 by the maintainer at the plan stop: this is adr-0006's generator truth, not its option (B).

- **Truth record — a `speech` key per manifest case, in integer samples (F1).** Each case of `Tests~/Fixtures/audio/manifest.json` gains `"speech": [{"start": s, "end": e}, …]`, samples at the clip's rate, start inclusive, end exclusive, one entry per segment, `[]` for silence; no other byte changes. The rig's strict reader learns it, typed (`JoinedInput.ManifestCaseKeys` :135-155, `ReadManifest` :465-590), and keeps `phrase` and `segments`; Unity ignores it (`JsonUtility`, `Runtime/Testing/VoxrAudioTestSuiteAsset.cs` :34). *Why:* §4.1 has the clip carry it; samples align with `consumed` and print alike in Python and C#. *Rejected:* a side file (two files to pair, as the joined rig ruled for timings); seconds (float text from two languages).

- **Truth check — an independent C# rescan at every run's start (F1, §6).** `--bench truth-check`, also the first step of `--bench run`, reads each WAV and checks its recorded end lies within one 20 ms frame — 960 samples at 48 kHz (design Status) — of its last sample at or above the floor before the tail, and that silence has none; a case with no `speech` stops (exit 2). *Why:* a second implementation makes F1 a check, not the generator reading itself; no clip without truth yields an offset (§6). *Rejected:* the generator's word alone.

- **Code home — a `--bench` mode of the joined rig, recogniser stage only (§10 item 2; adr-0002).** New `Bench.cs` (verbs, checks, stamps, run), `BenchMetrics.cs` and `BenchReport.cs` sit beside `Joined*.cs`, copied by `stage.sh` only under `recogniser`; `Program.cs` dispatches `--bench` through a hook set by a module initializer, as `JoinedRecogniser.Register` (:69-75) sets `Joined`'s, so DocCheck's parser stage compiles unchanged and stops `--bench` by name. `bench.sh` beside `joined.sh` runs it end to end. It stays outside the layout's Source and Tests slots, like the rig: an on-demand instrument (joined-rig adr-0004), never a gate (adr-0008). *Why:* the command stage is the rig's recogniser layer (adr-0002). *Rejected:* `Tests~/` (the host run renames it `Tests`, `Planning~/verification-recipe.md` :15, so Unity would compile the rig's `UnityEngine` stub); moving the rig (its home and DocCheck's, not this feature's); `NativeBridge~/harness/` (Command 3 for a C# consumer). **Amended 2026-11-09:** two rulings extend it. (1) "Stops `--bench` by name" holds per verb: a parser stage stops `--bench metrics-check`, `truth-check` and `run` by name (`Program.cs` :154, :214-229), and bare `--bench` stays issue #65's stdin timing mode with its block unchanged (:246-248), since other features' docs invoke it (plan-1 validation, ruled 2026-11-08 not a conflict). (2) The recogniser stage also stages `Runtime/Testing/VoxrWavReader.cs` (`stage.sh` :76), a copy with no `Runtime/` edit so F13 holds, and `Bench.ReadPcm` wraps it, a defective WAV stopping with exit 2 (`Bench.cs` :595-610); the review reversed the hand-written WAV reader the phase 2 plan had kept in `Bench.cs`.

- **Timeline feed — the dump case into the recogniser layer, unchanged (§10 item 4, F5; adr-0002).** Per case the bench hands `Joined.ScoreRecogniser` (`Joined.cs` :75-81, set to `JoinedRecogniser.ScoreCase`) the `ManifestCase` and `DumpCase`; it replays every result in dump order at `consumed` ÷ `sampleRate` (:282), delivered on the first 90 Hz frame at or after it through the stand-in bridge and the shipped speech recogniser, and returns the `Outcome` (class, `FireTimes`, `FinalCount`, `ExtraFires`, `Pending`, `AppliedGrammar`). The grammar-pin and applied-grammar guards (`Joined.cs` :196-212, :380-403) move into two internal methods both `Joined.Score` and the bench call, checks and messages unchanged. *Why:* one drive and one classifier, proved on the shipped sources (joined-rig-recogniser F3, F4). *Rejected:* composing through `--joined score` (its header names an A/B side a single run lacks, its `--pinned` check is the header rule above); exact-time delivery (a `Time.time` no frame takes); copied guards. **Amended 2026-11-09:** the surface the bench uses is wider by two methods: `Joined.FirstDifference` (the self-check's ordinal compare, `Bench.cs` :186) and `Joined.JsonArray` (finals and grammar lines, `Bench.cs` :192, `BenchReport.cs` :94) are `internal` too (`Joined.cs` :823, :837), so the self-check compares and formats finals as the kill check does and the two cannot drift; the review reversed the plan's own copies in `Bench` and `BenchReport`.

- **Command scoring — the joined classes, never netted, and three rates (F6).** Each case keeps `JoinedScorer.Classify`'s class (`Classes` :27-35). Over the cases with a non-empty `expectedIntent`, intent accuracy is (correct-fire + wrong-slots) ÷ those cases, semantic accuracy correct-fire ÷ those cases, phantom rate their summed `ExtraFires` ÷ those cases (`R6-evaluation-methodology.md` :356); the six counts print alone. *Why:* F6 derives the rates from the classes. *Rejected:* R6 :351's fired-set equality (folds extra fires into intent accuracy, netting what joined-rig adr-0003 keeps apart).

- **WER — reference the spoken text, hypothesis the finals' words (F7; R2, R5).** Reference: `phrase`, or `segments` joined with one space, split on whitespace. Hypothesis: every `result` `word` of the case's non-empty finals in order, `[unk]` kept. One Levenshtein alignment, unit costs, fixed backtrace order (match or substitution, deletion, insertion), gives per case S, D, I and per hypothesis word its correctness; corpus WER is the summed errors over the speech cases ÷ their reference words, per-case WER beside; the silence case is excluded and its words counted as stray words. *Why:* R5's reading; the fixed tie-break makes per-word correctness, so F8 and the report, deterministic. *Rejected:* dropping `[unk]` (hides filler and substitution errors); the mean of per-case WERs (weights phrases unequally); `expectedTranscript` (mostly empty, R5).

- **Calibration — ECE and NCE over the alignment's words, undefined named (F8, §6).** Over the speech cases' hypothesis words, each with `conf` and correctness: ECE sums, over 10 equal-width bins on [0, 1] (the last closed), bin share × |bin accuracy − bin mean confidence|; NCE is (H_base − H_conf) ÷ H_base, H_base the entropy of the word accuracy and H_conf the confidences' cross entropy against correctness. ECE with no words, and NCE with all words right, all wrong, or a wrong word at confidence 1 or a right one at 0, print `undefined` and the reason; nothing is clamped. The bin count is a named constant, provisional → the tuning pass. *Why:* R6's definitions (:206, :359); §6 forbids a made-up number. *Rejected:* an ε clamp (a knob inventing a finite NCE); the silence case's words (F8 takes F7's alignment). **Amended 2026-11-09:** a word's bin is floor(round(`conf` × 10, 6)), the last closed (`BenchMetrics.cs` :196); toy row 26 pins it (`Bench.cs` :508). *Do not undo:* `conf` is read as a `float` and widened, so a confidence written as `0.7` is 0.69999… and a bare floor puts it in bin 6, not 7; Vosk writes 6-decimal confidences, so rounding to 6 places is exact for them (review ruling, fixed by default).

- **Report — one deterministic markdown file, two axes, the label (F4, F9–F12).** `BenchReport` writes and prints `<out>/report.md` (default `.scratch/bench/`, never committed). Header: the label — TTS-only, provisional; can stop a change, never ranks decoders, proves no gain before R5; the configuration; the dump header's `libvosk`, `gain`, `modelConf` digest (`JoinedReport.ConfSha12` :1085) and grammar; the staged ref (`STAGED_FROM`, `stage.sh` :137-152) and recogniser configuration with tick rate (`Joined.RecogniserConfig`); the manifest's `voice` and `provenance`; the seed, `none — clean renders, no condition applied` until `bench-conditions`; the harness's exit code and the dump's `end` record. **Latency:** per case category and signed offsets of first partial, each final and command event; no aggregate row. **Accuracy:** per case class, finals count, extra fires, pending label, WER; then the six counts, the three rates, corpus WER, stray words, ECE, NCE. *Why:* adr-0008's side-by-side axes; R3. *Rejected:* `JoinedReport` (an A-versus-B shape, `bench-ab-report`'s); a combined score (adr-0008).

- **Configuration — pinned by default, every value echoed (§4.2, F10).** By default confgen runs at Command 3's `--profile Automatic --mode Continuous` into the run's model copy, and the pin's `gain` holds. Recogniser settings are the staged ref's, optionally with `stage.sh`'s `--buffer`/`--window` edit (:115-135), named by reflection. A named non-pinned profile, mode or gain (Phase 4) runs confgen with them and hands the harness a `.scratch/` pin copy differing only in `gain` and `modelConf`, since the harness refuses a conf off its manifest's pin (`main.cpp` :268-272); the self-check still reads the committed pin. *Why:* §4.2; F13. *Rejected:* refusing non-pinned decoder configurations (§4.2); editing `expectations.json` ("re-pin, never edit"). **Amended 2026-11-09:** (Phase 4 plan take, 2026-11-08) a run is *named* when any of `--profile`, `--mode`, `--gain` is given, a value equal to the pin's included, and *pinned* otherwise, its report byte-identical to Phase 3's; a named gain is 0 or a negative decimal (the front end clamps above 0, so a larger value would be named but never applied); a named run's `--out` lies under `.scratch/`, where `<out>/harness-pin.json` is written (`bench.sh` :48-67, :113-120); its header names the profile, mode and the copy (`BenchReport.cs` :74-93).

Cite: `main.cpp` (`DumpCase` :84-91, `DrainResults` :107-151, header :322-337, `end` :531-540) → `JoinedInput.ReadDump`, `DumpCase` :47-72, `DumpResult` :76-84.

**Flow:** after Command 3 has built the harness and confgen, the maintainer runs `bench.sh` from the project root in Git Bash; it checks its inputs (exit 2, named), runs confgen into `<out>/model`, for a named configuration writes the harness's pin copy, `<out>/harness-pin.json`, from the committed pin with the model's conf and the named gain, runs the harness with `--dump <out>/dump.jsonl` (on the copy when named), stages the ref with `stage.sh <ref> <out>/stage recogniser` and builds it, then runs `--bench run`, which reads dump, manifest and pin, rescans every WAV against its truth (exit 2), compares every case's finals with the pin (exit 3, cases named, no report), runs the grammar-pin guard, drives each case through a fresh staged world and the applied-grammar guard, takes stamps and offsets, scores WER and calibration, and writes and prints `report.md`.

## Non-functional realization

- **Performance (§6).** No budget; the rig's clock is simulated, so a run costs the harness's decode plus one world per case.
- **Input boundary (§6).** Each a named stop, exit 2, no report: no harness or confgen build at Command 3's paths; no model; harness exit 2; a reader defect; a case without `speech`; a failed truth check; a case missing from manifest or pin (`JoinedInput.Join` :740); a grammar guard. An undefined metric prints `undefined` and why, never a number.
- **Degraded dependencies (§6).** An unreadable joined-rig input stops with the reader's file and line (`Bench.Run`'s own catch, `Bench.cs` :93-114, modelled on `Joined.Run`'s, :124-146, with its own `reading` field, :21, and the prefix `bench:`); a staged error log or a command pending at the horizon stops as on the joined layer.
- **The tie (F3), structurally.** The self-check runs after the readers and before any world; the report is built in memory and written only after the last case, so no failing run writes numbers.
- **Determinism (F12).** The report holds no clock, host, temporary path or hash-ordered iteration; numbers print invariant-culture at fixed precision from integer samples or the ordered alignment. The one run-dependent input is the read boundary: `consumed` moves by reads sized by the ring's fill (`vosk_bridge.cpp` :104-111), which the joined rig bounds at one read run to run (joined-rig-recogniser F2) and measured at 0; Phase 1 re-measured it on the 52 cases and found the read boundary unmoved, and the two-run compares of Phases 3 and 4 gave identical reports.
- **Untouched (F13), by construction.** No write set holds a `NativeBridge~/` file, `expectations.json` or a WAV; truth mode opens WAVs read-only; the pin copy lives under `.scratch/`; each gate checks `git diff main` empty for those paths.
- **Hot paths.** None touched (`Runtime/`, `NativeBridge~/src/` unchanged).

## Risks, tradeoffs & open questions

- **F12 rested on read boundaries repeating — retired by the build.** The joined rig bounds the run-to-run position difference at one read, not zero; Phase 1's probe found none and the two-run compares of Phases 3 and 4 gave identical reports. A later difference would still need a change to how the harness pushes or the bridge reads — the pinned path — so it stops for the human, never a rounding fix.
- **Fast-mode resolution.** A result is stamped at the end of the read that emitted it, so offsets step by up to one 4096-sample read, and 16384-sample pushes keep the reader full where 20 ms arrivals would not; the command event also waits for the next 90 Hz frame. This is fast mode's audio-time part as adr-0003 defines it; device-like chunking is `bench-paced-mode`'s finding.
- **The floor is a reading of adr-0006.** adr-0006 (B) faulted a threshold in an energy detector; here the floor is confined to the block the generator placed and fixed to its `TRIM_DBFS`, and F1's check is itself floor-based. Ruled 2026-11-08: read as generator truth; no reopen.
- **The segment split may refuse a ladder rung** when a segment's own pause is as long as a 0.2 s gap; the case stops by name for a ruling, never a guessed boundary.
- **NCE may often be undefined.** Vosk's word `conf` is near flat (`R6-evaluation-methodology.md` :208) and one wrong word at confidence 1 makes NCE infinite; the bench prints `undefined` and why. If the lab's Phase B NCE/ECE probe reports before Phase 1, it feeds this definition (requirements §8).
- **F3 read as finals only.** The joined kill check also pins the header; here those fields are named instead, so a non-pinned configuration that keeps every final gets numbers. Ruled 2026-11-08: finals only; Phase 4 kept.
- **Coupling and drift.** A change to `JoinedRecogniser`, `JoinedScorer.Classify` or `stage.sh`'s closure changes the command stage (adr-0002). Truth reads `generate.py`'s `LEAD_SILENCE_S`, `TAIL_SILENCE_S`, `TRIM_DBFS` and `build_case` layout; changing them changes every truth on the next truth run. TTS-only evidence never ranks decoders (C12).
