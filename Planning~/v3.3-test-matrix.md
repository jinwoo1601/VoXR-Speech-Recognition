# v3.3 — Batch Test Runner Test Matrix

v3.3 (shipped as 0.13.0) adds a batch test runner for regression-testing
command definitions after changes. Two interfaces:

- **`VoskBatchTestRunner`** — pure C# runner that instantiates a
  `VoskCommandParser`, feeds test cases, applies threshold filtering,
  and compares against expected intents and slots. Works in Edit Mode
  without Play Mode or audio hardware; CI-safe.
- **`VoskBatchTestWindow`** Editor window (Window > VOSK XR > Batch Test
  Runner) — visual table with input/expected/actual/score/status columns,
  Run All and Re-run Failed buttons, per-row diagnostics expansion,
  CSV export, and JSON import/export.

Supporting types: `VoskTestCase`, `VoskTestResult`, `VoskBatchResults`,
`VoskTestSuiteAsset` ScriptableObject (Assets > Create > VOSK XR >
Test Suite), and `ExpectedSlot`.

The matrix has three halves:

1. **Phase 0: Automated coverage.** All existing Editor and Play Mode
   test suites, including the new `VoskBatchTestRunnerTests`.
2. **Phases 1–6: Editor window verification.** Manual spot-checks of
   the `VoskBatchTestWindow` UI: configuration, run, results table,
   diagnostics expansion, re-run failed, CSV export, JSON import/export,
   and the `VoskTestSuiteAsset` Inspector workflow.
3. **Phase 7: Regression.** Confirms v3.3 did not break any existing
   injection, debug-window, or live-mic behaviour.

## Prerequisites

1. **Consuming project**: `D:\Game Development\voxsdk` (per
   `reference_unity_test_project.md`) — the package is referenced via
   `file:` and `manifest.json` already has
   `"testables": ["com.jinwoo1601.vosk-xr"]`.
2. **No device required.** Quest does not need to be connected. Native
   bridge does not need to be built. The batch test runner and its
   Editor window work entirely in Edit Mode.
3. **Unity 6000.3.7f1** (matches the Android toolchain pinned in
   `CLAUDE.md`, but the Editor pieces work on any 2021+ Unity).
4. **Command Recognition sample imported.** The sample's slot assets
   (6), command assets (11), and command set assets (3) are used by
   Phases 2–6 as input to the batch test window.

## Test Suite Asset Setup (used by Phases 2–6)

Before starting Phase 2, create a `VoskTestSuiteAsset` for use
throughout the manual phases:

1. Assets > Create > VOSK XR > Test Suite. Name it `v3.3 Smoke Suite`.
2. In the Inspector, set `Suite Name` to `v3.3 Smoke`.
3. Add the following test cases to the `Cases` list:

| # | Input | Expected Intent | Expected Slots | Word Confidence | Description |
|---|-------|-----------------|----------------|-----------------|-------------|
| 1 | `cease fire` | `cease_fire` | (none) | -1 | Literal command, no word data |
| 2 | `launch all missiles target hotel one` | `launch_weapon` | quantity=all, weapon=missiles, target=hotel one | -1 | Full slotted command |
| 3 | `launch missiles target hotel one` | `launch_weapon` | weapon=missiles, target=hotel one | -1 | Optional slot omitted |
| 4 | `hello world` | (empty) | (none) | -1 | Out-of-grammar — expects rejection |
| 5 | `cease fire` | `cease_fire` | (none) | 0.85 | With word confidence above threshold |
| 6 | `cease fire` | (empty) | (none) | 0.2 | Low confidence — expects rejection |
| 7 | `orient heading two seven zero` | `set_heading` | heading=two seven zero | -1 | NumberSequence slot (parser returns raw text; use `VoskNumberParser` to convert) |
| 8 | `shoot jackals` | `launch_weapon` | weapon=jackal | -1 | Alias resolution |

> Cases 1–4 exercise basic pass/fail and rejection. Cases 5–6 exercise
> threshold filtering with simulated word confidence. Cases 7–8 exercise
> NumberSequence and alias features. This suite is intentionally small
> (8 cases) to keep manual verification fast — comprehensive coverage is
> in the automated tests.

### What this matrix proves

- The `VoskBatchTestRunner` programmatic API correctly instantiates a
  `VoskCommandParser`, feeds test cases through it, applies threshold
  filtering (score and confidence), compares results against
  expectations (intent, slots, rejection), and reports pass/fail with
  diagnostic data. Works in Edit Mode — no Play Mode, no audio, no
  native bridge.
- The `VoskBatchTestWindow` Editor window provides a functional visual
  interface for running batch tests: configuration fields, Run All,
  Re-run Failed, per-row diagnostics expansion, CSV export, and JSON
  import/export all work correctly.
- `VoskTestSuiteAsset` ScriptableObjects can be authored in the
  Inspector, round-tripped through JSON, and consumed by both the
  runner and the Editor window.
- Command set filtering works in the batch runner — the Active Sets
  field correctly scopes which commands are available.
- The `VoskBatchTestRunnerTests` meta-test suite (22 tests) provides
  automated coverage for the runner's core logic, preventing future
  regressions without manual re-testing.
- All prior v3.0–v3.2 features (injection, debug window, live mic,
  command parsing) continue to work — zero regressions.

### What this matrix does NOT cover

- **Live audio input.** The batch test runner bypasses VOSK entirely,
  feeding text directly to the parser. Any test that depends on what
  VOSK actually hears is out of scope. Those still need a Quest run or
  the v3.1 Editor mic path.
- **Play Mode integration.** The batch runner works in Edit Mode by
  design. Play Mode integration (buffer, debounce, cross-component
  subscription) is covered by the v3.0 test matrix.
- **Quest 3 on-device regression.** No Android build or deploy is
  required for v3.3. The batch runner is a pure C# Editor tool.
- **Large-scale test suites.** The manual phases use an 8-case suite.
  Performance with hundreds or thousands of cases is not validated
  (but the runner is a synchronous loop with no allocation hot spots,
  so scaling issues are unlikely).
