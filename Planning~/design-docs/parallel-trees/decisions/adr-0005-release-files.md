# adr-0005 — Release files are `CHANGELOG.md` and `.claude/`, over `CHANGELOG.md` only or none

## The fork

§0 of the design (`Planning~/design-docs/parallel-trees.md`, Forks for the design) left open which files are release files (In 3). Under the trees contract a release file is one a branch changes because it is being shipped, not because of what the feature does, so release files overlap between concurrent branches and each overlap is resolved by the file's rule; a Release files slot that names no path means no release class (`.claude/references/core/trees-contract.md` `## The release files`). `package.json`'s version changes only on `Release X.Y.Z` commits (`git log -- package.json`), and `CHANGELOG.md` `## [Unreleased]` gains entries at feature and light-lane closes. The precedent is the harness repo's filled `trees` binding (`D:\Workspace\harness\.claude\bindings\vc-git.md` `## trees`), which names `CHANGELOG.md` and `.claude/` (bindings excluded) as release files.

## Options considered

1. **(a) `CHANGELOG.md` and `.claude/`.** In `CHANGELOG.md`, both sides' `## [Unreleased]` entries are kept, this branch's first. In `.claude/`, including `.claude/harness.json` but not `.claude/bindings/*.md`, files are regenerated by `upgrade` and never merged by hand.
2. **(b) `CHANGELOG.md` only.** `CHANGELOG.md` is the one release file, with the same rule.
3. **(c) None.** No release class.

## The decision

**Option (a): the release files are `CHANGELOG.md`, where both sides' `## [Unreleased]` entries are kept, this branch's first, and `.claude/`, including `.claude/harness.json` but not `.claude/bindings/*.md`, whose files are regenerated by `upgrade` and never merged by hand.** `package.json` is not a release file: its version changes only on `Release X.Y.Z` commits.

## Why the rejected branches lost

- **(b) `CHANGELOG.md` only** — concurrent harness-upgrade overlaps in `.claude/` would stop for the human. What would have to change for it to win: concurrent branches never overlapping in `.claude/`.
- **(c) None** — every overlap stops for the human. What would have to change for it to win: concurrent branches never overlapping in `CHANGELOG.md` or `.claude/`.

## Consequences

- The `trees` binding's Release files line names `CHANGELOG.md` and `.claude/`, save `.claude/bindings/*.md`, each with its rule (design intent, not yet built).
- An overlap in `.claude/bindings/*.md` or `package.json` is outside the release class and is ruled as any other overlap.
- Changed by the follow-up feature after G1, not on this branch: `.claude/bindings/vc-git.md` :19-20, the `trees` value and comment.

## Status

Accepted on 2026-11-05 by the human's ruling (AskUserQuestion), option (a).
