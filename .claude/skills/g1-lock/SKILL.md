# g1-lock

## What this is

G1 locks a design: a preflight establishes that every fork is ruled and nothing outside the process docs changed, the human rules, the lock and the backlog are recorded, the branch merges — "locked" is the human's word.

> The preflight prepares, the human locks. A design is not locked because it reads finished.

## Bindings

- `process-docs` (required) — the *Design docs* slot, where the design doc and the feature backlog live, and, with the *Feature docs* slot, the area every changed file on this branch must lie in; and the *Prototype requirements* slot, the file name of the requirements doc LOCK sets `accepted` on a carry branch, `requirements.md` where it is absent or reads `TODO`. Absent → stop and say so before any brief is filed.
- `vc` (required) — the base-revision reads that give PREFLIGHT's changed-file list and `.claude/references/core/gate-close.md`'s current-branch and changed-file reads, the *Branch procedure*, whose lab form Prerequisites refuses, the merge procedure of MERGE, the check-in procedure of STATUS, and the main branch, PREFLIGHT's and MERGE's target, which `.claude/references/core/gate-close.md` `## The record` takes as `--main`.
- `verification` (required only where CATCH-UP brings the target in) — read only on the tree path: the whole key, quoted into `compile-check`'s brief at CATCH-UP, whose commands run in the branch's tree; `none` is a filled value, and CATCH-UP records `nothing to run`. It is consulted nowhere else. Absent there → stop before the merge and say so. Whole: passed on at CATCH-UP.
- `trees` (optional) — the Hub path ROOT compares with this session's root, PREFLIGHT's `budget` run takes as `--hub`, and STATUS's `scripts/hub.py write` and the `scripts/hub.py lock` commands take as `--root`; the List read that confirms the branch's tree; the Catch-up procedure; and the Clean read and the Hub slot's idiom by which HUB READ and MERGE run in the hub. The Release files slot gives HUB READ's version check its rule for the `version:` line. Absent → today's path. Filled → the steps run as `references/tree-path.md` orders them, and PREFLIGHT's `budget` run adds `--hub "<Hub path>"`.
- `session-launch` (optional) — the Hub session name, to which the tree path's REMOVE sends `FINISHED`. Absent, or the Hub session name missing or `none` → REMOVE as today and no report sent.
- Agents — `doc-extractor` missing → PREFLIGHT's question list is answered by the PM's own read, said so. `doc-writer` missing → the catch-up stop on a new decision where a conflict falls to it; otherwise stop after the ruling and say so. `compile-check` missing → where CATCH-UP brings the target in, stop before the merge and say so.

- Main branch: `main`
- Branch procedure: a re-lock — a `design-<topic>` branch cut from the feature branch's head in the feature's own tree, declared on its STATUS line `re-lock of <feature-branch>`, merged back into that feature branch after G1 — is cut by `git switch -c design-<topic>` in the feature's tree and merged back by `git switch <feature-branch>`, then `git merge design-<topic>`, in that tree; a carry — a `design-<topic>` branch cut from the main branch in a prototype's own tree, the one checkout where `trees` is absent, declared on its STATUS line `carry of <prototype-branch>`, which takes only the topic's design directory from the prototype branch — is cut and switched to by `git switch -c design-<topic> <main-branch>` in that tree; branches are `design-<topic>`, `feat-<feature>`, `light-<topic>` (an issue's `light-<n>-<slug>`), `lab-<topic>`, which merges nothing, and the release prep `chore/release-X.Y.Z`; each is cut from an up-to-date `main` — `git fetch origin`, then on `main` `git merge --ff-only origin/main`, then `git switch -c <branch>` — and runs in the one checkout, since `trees` is none
- Check-in procedure: inline on the main thread — `git add -- <paths>`, then `git commit -F <message file> -- <paths>`, each one command, never a heredoc or a chain, never `git add -A` — a hub operation's `memory/` check-in by the base's `scripts/hub.py commit --message <file> --root <hub> <paths>`, which commits the named paths under `memory/` alone; then `git push -u origin <branch>` on a branch's first push and `git push` after; the commit sha is the receipt

- Merge procedure: a pull request against `main`, opened by `gh pr create --base main --title "<title>" --body-file <file>` after the push, merged by the human on GitHub behind the gate's stop; Claude never merges

## Prerequisites

Confirm before proceeding:
- The checkout is on the design branch per the `vc` binding's base-revision reads.
- The design doc exists where the `process-docs` binding's *Design docs* slot says.
- The branch is not in the prototype form: the prototype form the `vc` binding's *Branch procedure* names, or `proto-<topic>` where it names none (a `<…>` placeholder matches any text). A prototype branch never merges → stop and say so before any brief is filed: its closing G1 runs on the `design-<topic>` branch `prototype-round` CARRY cuts, where the prototype path is composed.
- The branch is not in the lab form: the lab form the `vc` binding's *Branch procedure* names, or `lab-<topic>` where it names none (a `<…>` placeholder matches any text). A lab branch merges nothing → stop and say so before any brief is filed.

## Workflow

Where `trees` is filled, as the contract reads it, these steps run as `references/tree-path.md` orders them — on a re-lock, as its `## The re-lock path` orders them; otherwise they run as written.

1. **PREFLIGHT** — file `.scratch/g1-lock-<topic>-preflight-brief.md` from the common fields of `.claude/references/core/brief-fields.md` (the design doc by absolute path) and dispatch `doc-extractor` through the Agent tool without a `name`, with the fixed question list: is every fork ruled? is every decision marked locked? are the open questions listed, each with an owner? are the feature candidates named? Then the PM reads the branch's line in `memory/STATUS.md` — the hub's where `trees` is filled: where it reads `re-lock of <feature-branch>`, the branch is a re-lock and the target is that feature branch; otherwise the target is the main branch. The target is reported at PRESENT. Then the PM reads, per the `vc` binding's base-revision reads, the changed-file list from the branch's merge base with the target: every changed file lies in the process-docs area the binding's *Design docs* and *Feature docs* slots name — a file outside it is reported (the constitution: no product-doc edit on a design branch). Then the PM runs the base's `scripts/harness.py budget --root <project>`, the base being the `base` path in `.claude/harness.json`, relative to the project root, with `--hub "<Hub path>"` where `trees` is filled; G1 has no feature, so the check is STATUS only. With no manifest, the PM says the check could not run. Then, where `trees` is filled and this session's project root is not the Hub path, the PM runs the base's `scripts/hub.py level-check --root "<Hub path>" --branch <branch> --main <target>`, `<target>` the target this step read, the feature branch on a re-lock: exit 0 and a line opening `level-check: PASS` is level; exit 1 with stdout's last line opening `level-check: FAIL` is behind, that closing line a verdict and no path, remediated by `.claude/references/core/gate-close.md` `### CATCH-UP` and read again, its lines reported at PRESENT; anything else — a refusal on stderr, empty stdout, an exit 2, a refused call — is a refused read, never level, shown at PRESENT, and the packet is put in full.
2. **PRESENT** — the answers verbatim, read from the full report `.scratch/g1-lock-<topic>-preflight-report.md` (the index carries one sentence per answer), filed as `.claude/references/core/delegation-contract.md` `## Filing` says of a recon agent's report — by core's report filer where it runs, otherwise by the PM from the agent's transcript, with the changed-file list and the `budget` lines, or, with no manifest, that the check could not run. A `budget: FAIL`, every other FAIL remediated first, goes to the HARD STOP, as `.claude/references/core/gate-packet.md` `## The budget ruling` says; a refusal (`budget: refused — <reason>`) or no final line stays UNVERIFIABLE, shown and resolved before the HARD STOP and `budget` re-run, never read as a pass and never waivable. Anything unruled goes back to the design conversation, not to the gate. PRESENT also shows each feature candidate with its proposed mark, in the form `.claude/references/core/feature-lite.md` `## The mark` gives — lite only where the locked design fixes every file-level choice, with the design passages that fix them and the numbered acceptance criteria — and its proposed path beside that mark, one the base's `scripts/harness.py doctor --paths --root <project>` printed, and says the G1 ruling covers the marks and the paths. Where that read prints `no path is composed`, PRESENT shows no path and says none is composed; where it exits non-zero, its rows are shown and resolved before the HARD STOP, never read as none composed; with no manifest, it says the read could not run and shows no path.
3. **HARD STOP — the G1 ruling.** Ask for the human's explicit lock with the preflight in view, putting the packet by `.claude/references/core/gate-packet.md` `## The packet` and the ruling by `.claude/references/core/ruling-form.md` and saying, as it is put, that the lock is also the word to merge; a lock given earlier in this session is held, and stands or is asked again, as `.claude/references/core/gate-packet.md` `## The early word` says, and a stood lock is that ruling. A budget FAIL PRESENT sent here is put first, before the packet, by `.claude/references/core/gate-packet.md` `## The budget ruling`, the packet and the word waiting on that ruling and, on Trim, on `budget` passing. Silence, enthusiasm or a 'looks good' is not a ruling.
4. **LOCK** — file `.scratch/doc-writer-<topic>-g1-brief.md` from `.claude/references/core/decision-brief.md`; `doc-writer` sets the design doc's status to locked and dates the lock, as the doc's form provides. Where the branch's line in `memory/STATUS.md` — the hub's where `trees` is filled — reads `carry of <prototype-branch>` (a `<…>` placeholder matches any text), the same brief also has `doc-writer` set the prototype's requirements doc — the *Prototype requirements* file in the topic's directory under *Design docs*, `requirements.md` where that slot is absent or reads `TODO` — to `status: accepted`, its `updated` the lock's date.
5. **BACKLOG** — a second decision brief, `.scratch/doc-writer-<topic>-g1-backlog-brief.md`; `doc-writer` writes the feature backlog — one row per feature, its Feature cell the feature's slug in backticks, the name its `feat-<feature>` branch takes and the one name the item goes by, its Scope cell the one-line scope, then the path as ruled where PRESENT showed one, in the form `.claude/references/core/feature-lite.md` `## The mark` gives, and its Depends on cell naming other features by slug, or `None.`; a row whose path is ruled `prototype` names, in place of the `feat-<feature>` branch, the prototype form the `vc` binding's *Branch procedure* names, `proto-<feature>` where it names none; no number column — where the `process-docs` binding's *Design docs* slot says. Each row's Scope cell closes with the mark as ruled, `**Full.**` or `**Lite** (<adr>): no requirements doc; acceptance — (1) … (2) …`, `<adr>` the decision record the mark rests on, or the design section where the topic has none, as `.claude/references/core/feature-lite.md` `## The mark` says.
6. **MERGE** — the design branch into the target PREFLIGHT read: into the main branch per the `vc` binding's merge procedure; on a re-lock, into the feature branch by the re-lock merge-back the binding's *Branch procedure* names. **The G1 ruling is itself the word to merge**; there is no second stop. Relay first what was authored after the ruling — LOCK's and BACKLOG's edits — as a diff the human can read, then merge. Show, do not ask again.
7. **STATUS** — the PM's `memory/STATUS.md` line; the check-ins per the `vc` binding's check-in procedure are the PM's. The same act writes the session's dated note as `.claude/references/core/gate-close.md` `## The dated note` says.
8. **CLEAR** — where `trees` reads absent, as the contract reads it, and the target PREFLIGHT read is the main branch: as `.claude/references/core/gate-close.md` `## The clear` says; otherwise nothing is cleared.
9. **KEPT BRIEF** — where the target PREFLIGHT read is the main branch: as `.claude/references/core/gate-close.md` `## The kept brief` says; otherwise no command runs, since a re-lock's merge leaves the feature branch checked out, which the command refuses, and a brief its block cited stays, uncited, for a later bare run.
