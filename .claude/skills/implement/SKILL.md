# implement

## What this is

**One phase, one writer, one independent gate — or, where the persisted plan splits the phase into units, `trees` is filled and a `WorktreeCreate` hook is registered, one writer per unit, each in its own tree, joined onto the branch before that one gate. While writer trees are parked, no `WorktreeCreate` hook registered, that split path is refused and a plan naming units runs as one writer.** A brief goes down to `code-writer`; the writer runs its targeted checks, and `compile-check` runs the suite as the gate; when the gate fails for a reason its error list does not explain, `debugger` finds the cause read-only — at most two fix loops, then the escalation LOOP names: `debugger`, an `architect` fix pass and one more gate where the cause lies in the plan, the reopen stop where the fix needs an architecture change, BLOCKED otherwise.

> The agent's own report is never the evidence. Agents write, the gate verifies, the PM commits and rules.

## Bindings

- `verification` (required) — the whole key, quoted into `compile-check`'s brief at GATE: the suite runs in full at each full gate, a targeted re-gate running only what its `## Re-gate` section names (LOOP), and never in the writer. The writer runs only the `Targeted` slot's command, with the targets the plan names for the phase's own files, quoted in the brief under Verification command. Where the binding carries a Fallback whose replaced Commands the targeted run covers, the brief takes the routed form of `.claude/references/core/code-writer-brief.md` `## Verification command` instead, a LOOP's targeted command too; every other targeted run is quoted as above. A `Targeted` slot that is missing, carries `TODO` or answers `none` → the brief says `not run — the gate runs the suite`, and the writer runs nothing. `none` is a filled value: the brief says `none bound`, GATE is recorded as `nothing to run`, and nothing loops. A fix brief takes it on the gate's failing checks. Every code-writer brief also quotes the binding's *Shell*, *Working-dir read* and *Path form* lines under Conventions, verbatim — the shell the writer's commands run in, the read that prints its working directory, and the form it writes paths in; a filled binding lacking one of them → stop and say so, naming the slot, before any brief is filed — except a binding that is a single `none`, whose platform slots are not read: the brief then says the working directory is read by `pwd` and written by the path it prints, never a stop for that reason. Absent → stop and say so before any brief is filed. Whole: passed on at GATE.
- `vc` (required) — the base-revision reads behind the branch prerequisite, the main branch that prerequisite refuses, and the check-in procedure of the PM's closing commit.
- `trees` (optional) — the *Hub* slot, which this file's block carries so that the key reads filled as the contract reads it, and, on the split path, the slots `references/split-path.md` `## Bindings` names. Absent → today's path. Filled → where the persisted plan names units and a `WorktreeCreate` hook is registered, the steps run as `references/split-path.md` orders them; otherwise `## Workflow` runs as written — with no such hook registered, writer trees are parked and the split path is refused, as `references/split-path.md` `## Parked` says.
- `process-docs` (required) — the *Persisted plan* slot, the path a phase's plan file is written at, by which the prerequisites find the phase's plan file and BRIEF names it; the *Feature docs* slot, where the requirements and architecture docs BRIEF and LOOP name lie; and the *Design docs* slot, where a lite feature's backlog lies. Absent → stop and say so before any brief is filed.
- Agents — `code-writer` or `compile-check` missing → stop before any dispatch and say so. `debugger` missing → DIAGNOSE is unavailable, say so, and the loop runs on the parsed error list alone. `debugger` or `architect` missing at LOOP's escalation → BLOCKED with every report, naming the agent missing.

## Prerequisites

Confirm before proceeding:
- The phase's plan file exists at the path the `process-docs` binding's *Persisted plan* slot names and was validated (`plan-validator`), or was recorded unvalidated under the human's ruling at the plan stop — read from the plan's own record of it, its `Unvalidated:` line carrying `Accepted at the plan stop` with the ruling's date and words (`phase-pickup` `## Bindings`, its *Agents* bullet, and PLAN); an `Unvalidated:` line without them is a plan stop not yet ruled: stop and say so.
- The checkout is on the feature branch per the `vc` binding's base-revision reads (the current branch), never the main branch.
- The `verification` binding has been read: its commands, or `none`.

## Workflow

Where the persisted plan names units, `trees` is filled, as the contract reads it, and the project's `.claude/settings.json` registers a `WorktreeCreate` hook, these steps run as `references/split-path.md` orders them; otherwise they run as written — a plan that names units while `trees` reads absent, or while no `WorktreeCreate` hook is registered, runs here as one writer on its whole files table, every unit's rows and the `serial` rows alike. With no such hook, writer trees are parked: the split path is refused up front, before any brief, and REPORT says why — the split path is parked, its `WorktreeCreate` hook unregistered (`references/split-path.md` `## Parked`).

1. **BRIEF** — fill `.claude/references/core/code-writer-brief.md` into `.scratch/implement-<feature>-<phase>-brief.md` (create the folder if absent): the plan reference, naming the phase's plan file by that path, the files in scope from the plan's table, this dispatch's acceptance criteria — which also carry each entry of the plan's `Runtime claims` list and each runtime claim in `.scratch/plan-validator-<feature>-phase-<id>-report.md`, the path `plan-validator`'s `## Output` names, each to be checked by running it and reported true or false with its evidence — the notes, that report's findings outside the fix-pass classes `plan-validator`'s defect-class line names, as the template's Notes says, conventions, with each composed pack's writer-rules reference as the template's Conventions says, the Verification command as `## Bindings` says, out of scope, the project rules, as the template's Project rules says, constraints, the stop-and-report rule. A plan recorded unvalidated has neither the validator's claims nor notes: both read `none`. That report, where the filer did not file it, is read from `plan-validator`'s returned message in this session; missing both, for a plan not recorded unvalidated → stop and report to the PM before the brief is filed, never inferring claims or notes. Anything not in the brief does not exist for the agent.
2. **DISPATCH** — one `code-writer`, serially (one writer per tree), through the Agent tool without a `name`, model per the brief, with the brief's absolute path as its entire context.
3. **RECEIPT** — the report's first line must be a status word. `BLOCKED` or `PARTIAL` → stop, file the report, report to the PM; no loop. A report without a status line is a contract violation: report it, do not act on it. Where the feature is lite and a `BLOCKED` report names a design choice the plan does not carry, the feature returns to the full track, as `.claude/references/core/feature-lite.md` `## The escape` says.
4. **GATE** — First, where the `verification` binding names a test runner and the Verification command of the writer's brief does not read `none bound`, the PM reads the `red` fields of the DONE report's trailer, before the carry read below and before any gate brief is filed or inherit run — on the split path every unit's report, as this gate's runtime-claim read covers them. A DONE whose trailer holds no field opening `red` is not taken as DONE: the PM continues that `code-writer` by `SendMessage`, to the agent id its dispatch returned, naming the missing clause, and its answer, filed beside the same brief as the next numbered report, is read in its place; the send-back runs no gate and is not one of LOOP's two fix iterations. An answer still holding no field opening `red` is not sent back again, and where that `code-writer` cannot be continued none is sent: FILE records for it the line `red not shown - no clause after one send-back`, and GATE goes on. This read is made once per phase, on the DONE GATE answers: the `red` fields of LOOP's re-dispatches and of the fix pass's re-dispatch are not read as a DONE condition, and FILE records them with the rest. Then file `.scratch/implement-<feature>-<phase>-gate-brief.md` from the common fields of `.claude/references/core/brief-fields.md`, the `verification` binding quoted, and dispatch `compile-check` through the Agent tool without a `name`, naming that brief by its absolute path; every full gate of this phase re-uses it — this first gate, a full re-gate and the fix pass's gate; a targeted re-gate files its own (LOOP). This first gate is a full run or an inherit, never narrowed: every bound Command, in full, or an inherit in their stead. Before filing it, read the phase report FILE saved for the build plan's previous phase: where it holds a line opening `Run: targeted`, the gate brief gains a `## Carried` section naming that phase's id and the gate report path it records, or no report where it records `not filed`, and `compile-check` pays that carried full run, green or red; no such report or line adds nothing. Then, after that read and before the gate brief is filed, where the binding is not `none` and that read adds no `## Carried`, run the inherit command as `.claude/references/core/gate-inherit.md` says, after the compose step below where one applies, its record `.scratch/implement-<feature>-<phase>-gate-record.md`, beside the gate brief, the gate record each gate of this phase appends to: the command appends its line there itself, making the record where absent, and the reference's table reads what it printed. An inherit is this gate's suite result, green: no gate brief is filed and no `compile-check` dispatched, and the PM runs the verbatim searches and reads the runtime-claim results below itself, appending their results to the gate record, and they decide the gate as on a full run; the first full gate of this phase after that inherit — a full re-gate, the full run answering a `BLOCKED` re-gate, or the fix pass's gate — files the gate brief as above before it dispatches `compile-check`, with no `## Carried`, as that read added none; anything else is the full run on the gate brief, as above. Where the binding is not `none` and that read adds `## Carried`, no gate of this phase runs the inherit command, and each appends at once to `.scratch/implement-<feature>-<phase>-gate-record.md`, made where absent beside the gate brief, the reference's line for a gate that runs none, its reason `carried`, save the fix pass's gate, whose reason LOOP gives. Where the plan dictates text verbatim, the gate also searches the landed files for that text, fixed-string; the writer's report that it is verbatim is not the check. Where the phase edits files that a compose step re-derives, such as a base repository's pack sources, the gate runs after that step, not after the dispatch: the source and its composed copy change as one unit. This first gate also reads the report's runtime-claim results, the plan's claims and the validator's alike: a claim reported false or unchecked is a plan defect — stop and report to the PM, with no LOOP. `none` → record `nothing to run` and go to FILE.
5. **DIAGNOSE (optional)** — when the gate fails for a reason the parsed error list does not explain, the PM files a debug brief from `.claude/references/core/debug-brief.md` into `.scratch/debugger-<slug>-brief.md` and dispatches `debugger` (read-only); its fix proposal joins the re-dispatch brief as an addendum. It does not count as a fix iteration.
6. **LOOP** — on FAIL, re-dispatch `code-writer` with the same brief plus the gate's parsed `file:line` error list, its Verification command the targeted command on the gate's failing checks, then re-gate — `compile-check`, never the writer's report — dispatched as GATE dispatches it, on `.scratch/implement-<feature>-<phase>-regate-brief.md`, re-filed each iteration from the common fields of `.claude/references/core/brief-fields.md`, the `verification` binding quoted, and a `## Re-gate` section: the targets, the `Targeted` command in the slot's own words with `<target>` filled, the Commands it narrows and the Commands to run after it, each by number, and the phase id; the plan's verbatim searches run as at GATE. Each iteration, after its re-dispatch and before its re-gate is chosen, targeted or full, below, runs the inherit command as GATE does, by `.claude/references/core/gate-inherit.md`, its record the gate record GATE names, to which the command appends its line; where GATE's carry read added `## Carried` to the gate brief, it runs none and appends the reference's line for a gate that runs none, its reason `carried`. An inherit is that re-gate's suite result, green: no re-gate brief is filed, no `compile-check` dispatched, no `Run:` line written and nothing carried, and the PM runs the plan's verbatim searches as at GATE, appending their results to the gate record; with no miss the inherit passes the phase, and a miss makes it a red re-gate. Anything else is the re-gate below, targeted or full, as written; GATE's full run answering a `BLOCKED` re-gate runs no second inherit command, and appends no second line, in that iteration. The targets are the failing checks of the phase's red gates so far, the first gate's and each red re-gate's, their union, one per check in the form the slot's `<target>` takes, several as the slot's words repeat it. The narrowed Commands are those the binding's words say the `Targeted` command narrows; every other Command runs after it, once, in the binding's order, one the slot already names after it included. Where the binding carries a Fallback replacing a narrowed Command, the section takes the routed form of `.claude/references/core/code-writer-brief.md` `## Verification command`, its last `On` line the Fallback narrowed as the slot says, else the Fallback in full. The re-gate is instead GATE's full run, on the gate brief, where the `Targeted` slot is missing, reads `TODO` or `none`; no Command is named as narrowed; the red gates' failures all lie in Commands it does not narrow; the binding's Fallback replaces a Command the `Targeted` command does not narrow; no target can be derived from the failing checks, the union being empty, as where no red gate names a failing check of a narrowed Command at all, a verbatim-search miss its only fault; a failure in a narrowed Command names no single check, as a load error or a runner fault; or a red gate's report is unreadable, truncated, or a raw tail with no verdict. A re-gate whose report opens `BLOCKED` is answered by GATE's full run, on the gate brief, which stands as that iteration's re-gate. A full re-gate carries nothing forward; it still pays a `## Carried` the gate brief holds, its report writing the paying `Run:` line. A red re-gate's failures join the union; that it writes no `Run:` line is no fault. A green re-gate passes the phase, its full run carried to the next full gate where its report holds a line opening `Run: targeted` (FILE). Where a red gate paid a carry, the re-dispatch brief's `## Notes` name the carried gate report, where FILE recorded its path, the files of the carried phase's files table that the parsed error list names join its files in scope, and an escalation's debug brief names under `## Inputs` both phases' gate reports and the carried phase's plan file, a gate report recorded `not filed` left out. The fix pass's one gate is a full gate, on the gate brief. It runs no inherit command and appends to the gate record the reference's line for a gate that runs none, its reason `fix pass`, in a carried phase too. At most two fix iterations; after the second failure, escalate: file a debug brief from `.claude/references/core/debug-brief.md` into `.scratch/debugger-<slug>-brief.md`, its `## Scope` adding the phase's plan file and the architecture doc, and dispatch `debugger`. The PM routes on its *Root cause* and *Fix proposal*: a cause in the plan, or a fix the plan's files table, contracts or criteria do not admit → the `architect` fix pass; a fix that changes the architecture doc's seams or decision register → the reopen stop; else BLOCKED with every report. The fix pass: file `.scratch/architect-<feature>-phase-<id>-loop-brief.md`, mode `fix pass`, giving by path the requirements doc, the architecture doc, the plan, the `code-writer` brief, both failed gates' reports and the `debugger` report, the gate record standing for the report of a failed gate that inherited, and dispatch `architect`; its report, filed beside the brief, is the plan correction as text. Its return is added verbatim to the re-dispatch brief as its `## Plan correction`, governing over the plan for each item it names, the files it names joining the files in scope; then one re-dispatch and one gate, and a FAIL → BLOCKED with every report. A fix pass `BLOCKED` or `PARTIAL` routes as `debugger`'s report does, with no second pass: a correction needing the architecture doc's seams or decision register changed → the reopen stop; else BLOCKED with every report. The fix pass is no fix iteration and runs once per phase.
7. **FILE** — the final report lies beside the brief as `implement-<feature>-<phase>-report.md`, filed by core's report filer (the delegation contract's `## Filing`); where the filer did not file it, the PM makes that file holding only the records below, the report staying in the agent's returned message.
