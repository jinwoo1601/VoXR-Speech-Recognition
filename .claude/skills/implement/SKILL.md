# implement

## What this is

**One phase, one writer, one independent gate — or, where the persisted plan splits the phase into units, `trees` is filled and a `WorktreeCreate` hook is registered, one writer per unit, each in its own tree, joined onto the branch before that one gate. While writer trees are parked, no `WorktreeCreate` hook registered, that split path is refused and a plan naming units runs as one writer.** A brief goes down to `code-writer`; the writer runs its targeted checks, and `compile-check` runs the suite as the gate; when the gate fails for a reason its error list does not explain, `debugger` finds the cause read-only — at most two fix loops, then the escalation LOOP names: `debugger`, an `architect` fix pass and one more gate where the cause lies in the plan, the reopen stop where the fix needs an architecture change, BLOCKED otherwise.

> The agent's own report is never the evidence. Agents write, the gate verifies, the PM commits and rules.

## Bindings

- `verification` (required) — the whole key, quoted into `compile-check`'s brief at GATE: the suite runs at GATE, once per gate, and never in the writer. The writer runs only the `Targeted` slot's command, with the targets the plan names for the phase's own files, quoted in the brief under Verification command. Where the binding carries a Fallback whose replaced Commands the targeted run covers, the brief takes the routed form of `.claude/references/core/code-writer-brief.md` `## Verification command` instead, a LOOP's targeted command too; every other targeted run is quoted as above. A `Targeted` slot that is missing, carries `TODO` or answers `none` → the brief says `not run — the gate runs the suite`, and the writer runs nothing. `none` is a filled value: the brief says `none bound`, GATE is recorded as `nothing to run`, and nothing loops. A fix brief takes it on the gate's failing checks. Every code-writer brief also quotes the binding's *Shell*, *Working-dir read* and *Path form* lines under Conventions, verbatim — the shell the writer's commands run in, the read that prints its working directory, and the form it writes paths in; a filled binding lacking one of them → stop and say so, naming the slot, before any brief is filed — except a binding that is a single `none`, whose platform slots are not read: the brief then says the working directory is read by `pwd` and written by the path it prints, never a stop for that reason. Absent → stop and say so before any brief is filed. Whole: passed on at GATE.
- `vc` (required) — the base-revision reads behind the branch prerequisite, the main branch that prerequisite refuses, and the check-in procedure of the PM's closing commit.
- `trees` (optional) — the *Hub* slot, which this file's block carries so that the key reads filled as the contract reads it, and, on the split path, the slots `references/split-path.md` `## Bindings` names. Absent → today's path. Filled → where the persisted plan names units and a `WorktreeCreate` hook is registered, the steps run as `references/split-path.md` orders them; otherwise `## Workflow` runs as written — with no such hook registered, writer trees are parked and the split path is refused, as `references/split-path.md` `## Parked` says.
- `process-docs` (required) — the *Persisted plan* slot, the path a phase's plan file is written at, by which the prerequisites find the phase's plan file and BRIEF names it; the *Feature docs* slot, where the requirements and architecture docs BRIEF and LOOP name lie; and the *Design docs* slot, where a lite feature's backlog lies. Absent → stop and say so before any brief is filed.
- Agents — `code-writer` or `compile-check` missing → stop before any dispatch and say so. `debugger` missing → DIAGNOSE is unavailable, say so, and the loop runs on the parsed error list alone. `debugger` or `architect` missing at LOOP's escalation → BLOCKED with every report, naming the agent missing.

## Prerequisites

Confirm before proceeding:
- The phase's plan file exists at the path the `process-docs` binding's *Persisted plan* slot names and was validated (`plan-validator`), or was recorded unvalidated under the human's ruling at the plan stop — read from the plan's own record of it (`phase-pickup` `## Bindings`, its *Agents* bullet).
- The checkout is on the feature branch per the `vc` binding's base-revision reads (the current branch), never the main branch.
- The `verification` binding has been read: its commands, or `none`.

## Workflow

Where the persisted plan names units, `trees` is filled, as the contract reads it, and the project's `.claude/settings.json` registers a `WorktreeCreate` hook, these steps run as `references/split-path.md` orders them; otherwise they run as written — a plan that names units while `trees` reads absent, or while no `WorktreeCreate` hook is registered, runs here as one writer on its whole files table, every unit's rows and the `serial` rows alike. With no such hook, writer trees are parked: the split path is refused up front, before any brief, and REPORT says why — the split path is parked, its `WorktreeCreate` hook unregistered (`references/split-path.md` `## Parked`).

1. **BRIEF** — fill `.claude/references/core/code-writer-brief.md` into `.scratch/implement-<feature>-<phase>-brief.md` (create the folder if absent): the plan reference, naming the phase's plan file by that path, the files in scope from the plan's table, this dispatch's acceptance criteria — which also carry each entry of the plan's `Runtime claims` list and each runtime claim in `.scratch/plan-validator-<feature>-phase-<id>-report.md`, the path `plan-validator`'s `## Output` names, each to be checked by running it and reported true or false with its evidence — the notes, that report's findings outside the fix-pass classes `plan-validator`'s defect-class line names, as the template's Notes says, conventions, with each composed pack's writer-rules reference as the template's Conventions says, the Verification command as `## Bindings` says, out of scope, the project rules, as the template's Project rules says, constraints, the stop-and-report rule. A plan recorded unvalidated has neither the validator's claims nor notes: both read `none`. That report missing for a plan not recorded unvalidated → stop and report to the PM before the brief is filed, never inferring claims or notes. Anything not in the brief does not exist for the agent.
2. **DISPATCH** — one `code-writer`, serially (one writer per tree), through the Agent tool without a `name`, model per the brief, with the brief's absolute path as its entire context.
3. **RECEIPT** — the report's first line must be a status word. `BLOCKED` or `PARTIAL` → stop, file the report, report to the PM; no loop. A report without a status line is a contract violation: report it, do not act on it. Where the feature is lite and a `BLOCKED` report names a design choice the plan does not carry, the feature returns to the full track, as `.claude/references/core/feature-lite.md` `## The escape` says.
4. **GATE** — file `.scratch/implement-<feature>-<phase>-gate-brief.md` from the common fields of `.claude/references/core/brief-fields.md`, the `verification` binding quoted, and dispatch `compile-check` through the Agent tool without a `name`, naming that brief by its absolute path; every gate of this phase — LOOP's and the fix pass's included — re-uses it. The suite runs here, once, on the bound commands in full. Where the plan dictates text verbatim, the gate also searches the landed files for that text, fixed-string; the writer's report that it is verbatim is not the check. Where the phase edits files that a compose step re-derives, such as a base repository's pack sources, the gate runs after that step, not after the dispatch: the source and its composed copy change as one unit. This first gate also reads the report's runtime-claim results, the plan's claims and the validator's alike: a claim reported false or unchecked is a plan defect — stop and report to the PM, with no LOOP. `none` → record `nothing to run` and go to FILE.
5. **DIAGNOSE (optional)** — when the gate fails for a reason the parsed error list does not explain, the PM files a debug brief from `.claude/references/core/debug-brief.md` into `.scratch/debugger-<slug>-brief.md` and dispatches `debugger` (read-only); its fix proposal joins the re-dispatch brief as an addendum. It does not count as a fix iteration.
6. **LOOP** — on FAIL, re-dispatch `code-writer` with the same brief plus the gate's parsed `file:line` error list, its Verification command the targeted command on the gate's failing checks, then gate again. At most two fix iterations; after the second failure, escalate: file a debug brief from `.claude/references/core/debug-brief.md` into `.scratch/debugger-<slug>-brief.md`, its `## Scope` adding the phase's plan file and the architecture doc, and dispatch `debugger`. The PM routes on its *Root cause* and *Fix proposal*: a cause in the plan, or a fix the plan's files table, contracts or criteria do not admit → the `architect` fix pass; a fix that changes the architecture doc's seams or decision register → the reopen stop; else BLOCKED with every report. The fix pass: file `.scratch/architect-<feature>-phase-<id>-loop-brief.md`, mode `fix pass`, giving by path the requirements doc, the architecture doc, the plan, the `code-writer` brief, both failed gates' reports and the `debugger` report, and dispatch `architect`; its report, filed beside the brief, is the plan correction as text. Its return is added verbatim to the re-dispatch brief as its `## Plan correction`, governing over the plan for each item it names, the files it names joining the files in scope; then one re-dispatch and one gate, and a FAIL → BLOCKED with every report. A fix pass `BLOCKED` or `PARTIAL` routes as `debugger`'s report does, with no second pass: a correction needing the architecture doc's seams or decision register changed → the reopen stop; else BLOCKED with every report. The fix pass is no fix iteration and runs once per phase.
7. **FILE** — save the final report beside the brief as `implement-<feature>-<phase>-report.md` — met by core's report filer where it runs (the delegation contract's `## Filing`); by hand otherwise.
8. **REPORT** — to the PM: status, files written, verification result, attempts used, the fix pass's report path where one ran, for the as-built reconcile to record its deviation from the plan, suggested next step, and the agent's suggested CHANGELOG line. The commit is the PM's, per the `vc` binding's check-in procedure; this skill makes no commit of its own.

A handoff taken before FILE, at a step boundary as `handoff` `## When to hand off` says — on the split path, a step of `references/split-path.md` — first files each report received so far beside its brief, and its brief names those reports by path and the fix iterations used. After REPORT there is no next step, and the objective is the skill that follows — the next phase's `phase-pickup`, or `review-cycle` after the build plan's last phase — as `handoff` `## When to hand off` says of a skill's last step; a next phase's pickup is itself a phase boundary, where `phase-pickup` ORIENT hands off whatever the context.

Agents write, the gate verifies, the PM commits and rules.

Inside skill work a turn ends on a stop line, its last line `Stop: <kind>` or `Stop: <kind> — <detail>`, the kinds and the `declared` detail as `.claude/references/core/hooks.md` `## What the stop-line hook passes` states; core's stop-line hook blocks any other end once. A turn that ends on a stop line of a waiting kind — `declared`, `gate`, `irreversible act`, `scope change`, `fork` or `BLOCKED` — puts that stop to the human through AskUserQuestion first, as `.claude/references/core/ruling-form.md` states.
