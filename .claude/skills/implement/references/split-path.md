# implement — the split path

The order `implement`'s `## Workflow` steps run in where the persisted plan names units, `trees` is filled and a `WorktreeCreate` hook is registered, and the binding sentences only that order uses; "the contract" is `.claude/references/core/trees-contract.md`.

## Parked

Writer trees are parked: neither version-control pack's settings template registers its `WorktreeCreate` hook. Without one, DISPATCH's `isolation: "worktree"` gets no writer tree under the Location slot, and RECEIPT would stop the phase only after the writers had written. So the split path is refused up front: where the project's `.claude/settings.json` registers no `WorktreeCreate` hook, a plan naming units runs through `## Workflow` as written, one writer on its whole files table, and the phase report says why — the split path is parked, its `WorktreeCreate` hook unregistered. A version-control pack's settings template registering the hook again lifts the park.

## Bindings

- `verification` (required) — on the split path its `Tree-safe` slot decides each unit brief's Verification command: `none bound` where the binding answers `none`; otherwise the targeted command where `Tree-safe` answers `yes`, and `not run — not tree-safe` where it answers `no` or the slot is missing — the writer then runs nothing, and the join's gate is the only verification. The serial step's brief takes the targeted command as a unit brief does.
- `vc` (required) — on the split path also: the branch's tip, recorded as a revision the base-revision reads take — the fan-out base and the pre-join tip; the current-branch read, run in each writer tree by the Hub slot's idiom, which gives RECEIPT the writer branch; the working-tree read and the check-in procedure, run in each writer tree by the same idiom, by which JOIN checks the tree in whole; and the changed-file read from the pre-join tip to each writer branch.
- `trees` (optional) — on the split path: the Hub path, and the Hub slot's idiom by which a command runs in another tree — the reads and the check-in in each writer tree, and REMOVE in the hub; the Location slot, under whose directory RECEIPT requires every writer tree; the Clean read of the branch tree, at CLEAN and again at JOIN; the Catch-up procedure, by which JOIN merges each writer branch in the branch tree, the writer branch standing where the procedure names the main branch; and the Remove procedure and the List read, by which REMOVE removes each writer tree and reads the removal back.

## The split path

Where the persisted plan names units — a Unit column in its files table, and a Units table after it in join order — `trees` is filled, as the contract reads it, and a `WorktreeCreate` hook is registered, the steps run in this order — never while writer trees are parked (`## Parked`); an item that runs a `## Workflow` step names it. A unit's write set is the files-table rows naming it, and the `serial` rows are the serial step's. Every act of the join is a slot of the `vc` or `trees` binding, run from this session, which is open in the branch tree; a command for another tree runs there by the Hub slot's idiom. Every stop files the reports taken back so far beside their briefs, as FILE names them, and says what is merged and which writer trees are kept.

1. **PREREQUISITES** — `## Prerequisites`, as written; the project's `.claude/settings.json` registers a `WorktreeCreate` hook — none is the park, refused before this order starts, as `## Parked` says; and the `trees` section carries the Hub, Location, List read, Clean read, Catch-up procedure and Remove procedure slots. A missing one stops, named: nothing is dispatched, no writer tree is cut, and nothing is merged.
2. **CLEAN** — the Clean read of the branch tree, the tree this session is open in, shows nothing, since each writer tree is cut from the branch's tip and carries nothing uncommitted, the persisted plan included. Then record the branch's tip as the fan-out base. Not clean → stop and say what the Clean read shows: nothing is dispatched, no writer tree is cut, and nothing is merged.
3. **BRIEF** — `## Workflow`'s BRIEF, once per unit, into `.scratch/implement-<feature>-<phase>-<unit>-brief.md`: the task names the phase and the unit; the plan reference is the phase's plan file, the requirements doc (for a lite feature its backlog row, as `.claude/references/core/feature-lite.md` `## The acceptance source` says), and the architecture doc for decisions the plan cites; the files in scope are the unit's rows; the acceptance criteria are the unit's, from the Units table, with each runtime claim in the brief of the unit whose files it names and any other claim in the first unit's; the notes go as the runtime claims do, each note in the brief of the unit whose files it names and any other in the first unit's; the Verification command is the one the `verification` binding's `Tree-safe` slot decides, as `## Bindings` says; and declared out of scope are every other unit's files and the `serial` files. Where the plan has `serial` rows, also the serial step's brief, `.scratch/implement-<feature>-<phase>-serial-brief.md`, in the same form, on those rows and their criteria, with the targeted command as a unit brief takes it.
4. **DISPATCH** — in one message, one `code-writer` per unit, each through the Agent tool without a `name` and with `isolation: "worktree"`, model per its brief, and its brief's absolute path, in the branch tree, as its entire context; the Agent calls of one message run in parallel. For each call the `WorktreeCreate` hook PREREQUISITES found registered cuts the unit's writer tree and branch from the branch's tip, where the `trees` binding says; the writer's shell starts in that tree, and it writes by the path the `verification` binding's *Working-dir read* prints there, in its *Path form*.
5. **RECEIPT** — after every call has returned, all-or-nothing: each dispatch returned a report and a `worktreePath` under the directory the Location slot names, compared in the Path form the `verification` binding names — no *Path form*, the slot missing or the binding a single `none`, stops RECEIPT, naming the slot; and each report's first line is `DONE`. Anything else — a failed dispatch, the hook's refusal or failure among them; a missing `worktreePath`, or one outside that directory; a unit `BLOCKED` or `PARTIAL`; a report with no status line — stops the phase `BLOCKED` to the human with every report, the hook's message where there is one, and every writer tree's path: nothing is merged, every writer tree is kept, and no unit is redone, un-isolated or serially. For a lite feature, a unit `BLOCKED` on a design choice the plan does not carry is read as `## Workflow`'s RECEIPT reads it. Then the map, unit → writer tree → writer branch: the tree is that unit's `worktreePath`, and the branch is the `vc` binding's current-branch read, run in the tree by the Hub slot's idiom.
6. **JOIN** — in this order, every check before the first merge: (1) record the branch's tip as the pre-join tip; (2) check in each writer tree whole — every pending change the `vc` binding's working-tree read lists there, not only the write set's — by the `vc` binding's check-in procedure, both run in the writer tree by the Hub slot's idiom, the message naming the feature, the phase and the unit; (3) compare each writer branch's changed-file list, by the `vc` binding's changed-file read from the pre-join tip to that branch, with its unit's write set; (4) read the branch tree clean by the Clean read, with its tip still the fan-out base; (5) merge the writer branches one at a time, in the Units table's order, by the Catch-up procedure run in the branch tree, the writer branch standing where the procedure names the main branch. A file outside a unit's write set at (3), or a pending change or a moved tip at (4) → stop for the human, naming what was found: the check-ins stand on the writer branches, nothing is merged, and every writer tree is kept. A conflict at (5) → the Catch-up procedure's own undo, then stop for the human, naming the pre-join tip, the units merged so far and the conflicting unit: the earlier merges stand, the conflicting one is undone, and every writer tree is kept. Nothing else in the join stops.
7. **SERIAL** — where the plan has `serial` rows: `## Workflow`'s DISPATCH and RECEIPT, one `code-writer` without isolation, into the branch tree, on the serial step's brief. A stop there leaves every unit merged and every writer tree kept.
8. **GATE** — `## Workflow`'s GATE, once, on the joined result and the serial step's changes: `compile-check` dispatched from this session, so that its commands run in the branch tree and its report names that tree. Its runtime-claim read covers every unit's report from RECEIPT and, where there is one, the serial step's report. `none` → record `nothing to run`, then REMOVE.
9. **REMOVE** — whatever the gate returned: each writer tree by the Remove procedure, run in the hub by the Hub slot's idiom; then the List read, run there by the same idiom, shows none of them. A refused removal is said to the human with the tree's path, and `orient` names the tree until it is gone. The writer branches are kept. Then a PASS or `nothing to run` goes to FILE, and a FAIL to DIAGNOSE and LOOP.
10. **DIAGNOSE and LOOP** — `## Workflow`'s DIAGNOSE and LOOP, as written, one `code-writer` at a time, without isolation, in the branch tree, on a fix brief, `.scratch/implement-<feature>-<phase>-fix-brief.md`, whose files in scope are the phase's whole files table — every unit's rows and the `serial` rows — and whose Verification command is the targeted command on the gate's failing checks, with the gate's parsed error list. At most two fix iterations; after the second failure, stop and escalate to the human with both reports: every unit is merged, and the writer trees are removed.
11. **FILE** — each unit's report beside its brief, as `implement-<feature>-<phase>-<unit>-report.md`, and the serial step's as `implement-<feature>-<phase>-serial-report.md` — met by core's report filer where it runs (the delegation contract's `## Filing`); by hand otherwise; then `## Workflow`'s FILE, whose phase report also records the fan-out base and the pre-join tip, the unit → tree → branch map, each check-in's receipt, the merges, the removals and the gate's result.
12. **REPORT** — `## Workflow`'s REPORT, as written, naming the writer branches kept. The PM's closing commit carries the serial step's and the fix iterations' changes, where there are any; the join's check-ins and merges are the PM's own acts within JOIN, per the `vc` binding.
