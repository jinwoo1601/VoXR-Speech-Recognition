# g2-lite

## What this is

**The light lane's one gate.** Issue and maintenance work is exempt from G0 and G1, is still reviewed, and is closed at G2, by the human's ruling on the pull request or changeset, its class named beside it, or closed by class by the PM where the classes binding delegates the changeset's class — this skill prepares the evidence that close needs and executes what it unlocks.

> The lane skips two gates, never the third. The bounds are checked, preflight audits a slim changeset and the STATUS budget is read on prose and trivial, the review runs or is confirmed, the class is resolved — and close-out and merge exist only on the human's ruling or a delegated class.

## Bindings

- `vc` (required) — the *Branch procedure*, whose light-lane form LANE matches the branch name against; the working-tree and revision reads the preflight runs on an effective slim (*Base-revision reads*), the *Merge procedure* the review step branches on, and MERGE's own procedure. Absent → stop and say so before any brief is filed: the review step has no route to choose and the merge has no idiom. Whole: passed on at PREFLIGHT.
- `verification` (required) — on an effective slim, the whole key, quoted into the preflight brief, whose commands' run evidence the audit looks for; `none` is a filled value and the preflight reports `nothing to run`. On the tree path, also the whole key, quoted into `compile-check`'s brief at CATCH-UP, whose commands run in the branch's tree, where `none` has CATCH-UP record `nothing to run`. Absent → stop and say so before the brief is filed, or on prose and trivial before PRESENT. Whole: passed on at PREFLIGHT.
- `product-docs` (optional) — the *Reconciling agent* slot named at CLOSE OUT where the changeset falsifies a product doc. `none bound`, or a slot naming no agent → report the falsified doc to the human and go no further. A named agent → report it as the dispatch the PM makes; this skill never dispatches it, because that agent ships in a docs pack this pack neither provides nor requires.
- `trees` (optional) — the Hub path ROOT compares with this session's root, PREFLIGHT's `budget` run passes as `--hub`, and RESOLVE's, LIST's and RECORD's `scripts/hub.py write` and the `scripts/hub.py lock` commands take as `--root`; the List read that confirms the branch's tree; the Catch-up procedure; and the Clean read and the Hub slot's idiom by which HUB READ and MERGE run in the hub. Absent → today's path. Filled → the steps run as `references/tree-path.md` orders them. Whole: passed on at PREFLIGHT.
- `process-docs` (optional) — the *Design docs* and *Feature docs* slots, by which `.claude/references/core/gate-close.md` `### CATCH-UP` tells locked text. Absent → no path reads as locked text, and a writer's `BLOCKED` stands for it; never a stop of itself.
- `session-launch` (optional) — the Hub session name, to which the tree path's REMOVE sends `FINISHED`. Absent, or the Hub session name missing or `none` → REMOVE as today and no report sent.
- `board` (optional) — the *STATUS line cap*, which the `## Auto-closed` line, and the branch's line with RESOLVE's word, stay within; the *STATUS budget*, which PREFLIGHT's `budget` run reads, not this skill. Absent, `none` or missing the slot → no cap, never a stop.
- No `classes` key: the `bounds` verb reads the prose and trivial bounds and the batch cap, and the `close-class` verb the *Delegated classes* slot; neither is read by this skill. Absent or unfilled → prose and trivial fail closed to slim, a batch fails the cap and no class is delegated; never a stop.
- Agents — `gate-preflight` missing → stop before PREFLIGHT dispatches, on an effective slim, and say so. `compile-check` missing → where CATCH-UP brings the main branch in, stop before the merge and say so. `code-writer`, `doc-writer` or `architect` missing → the catch-up stop on a new decision where that writer's files conflict.

## When it applies — and prerequisites

**Trigger:** a light-lane changeset — one issue, one batch of deferrals, or one maintenance task — is finished and ready to close.

Confirm before proceeding — if any item fails, stop and say which step or lane is actually needed:
- The changeset is complete: nothing half-written, nothing left staged and forgotten.
- Everything the `verification` binding names has been run at the head being presented.
- The work is one changeset. Work that grew into a feature belongs on a path its project composes, at its G2, `g2-accept`, rather than here.
- The lane is declared light: by the lane `light` on the branch's line in `memory/STATUS.md` `## Current`, or by the branch name's light-lane form. Neither → this item fails: the work belongs to the tracks and gates it came from.
- The branch is not in the prototype form: the prototype form the `vc` binding's *Branch procedure* names, or `proto-<topic>` where it names none (a `<…>` placeholder matches any text). A prototype branch never merges and has no G2 → stop and say so before any brief is filed: it closes at its closing G1, by `g1-lock`.
- The branch is not in the lab form: the lab form the `vc` binding's *Branch procedure* names, or `lab-<topic>` where it names none (a `<…>` placeholder matches any text). A lab branch merges nothing → stop and say so before any brief is filed.

## Workflow

Where `trees` is filled, as the contract reads it, these steps run as `references/tree-path.md` orders them; otherwise they run as written.

1. **LANE** — in this order:
   1. **Read the declaration.** The lane `light` on the branch's line in `memory/STATUS.md` `## Current`; or else the branch name, matching the light-lane form of the `vc` binding's *Branch procedure* (a `<…>` placeholder matches any text).
   2. **Record which one declares it** — the lane prerequisite holds, so one does: it was declared at the start. Go on without asking.
2. **CLASS** — read the declared class and a batch's items from the branch's line in `memory/STATUS.md` `## Current` only (`class <c>`, `batch <id>, <id>...`); none found → slim. Then, at the head being presented, the PM saves the `vc` binding's per-file line-count read (its *Base-revision reads*) from the changeset's merge base with the main branch to its head, redirected to `.scratch/g2-lite-<changeset>-numstat.txt`, and runs the base's `scripts/harness.py bounds --root <project> --class <declared> --numstat .scratch/g2-lite-<changeset>-numstat.txt`, with one `--item <id>` per batch item, the base being the `base` path in `.claude/harness.json`, relative to the project root. Its verdict is read by exit code and words, never the dash: exit 0 and a line beginning `bounds: PASS` keep the declared class as the effective one; anything else — exit 1, `bounds: FAIL`, `bounds: refused` on stderr — is slim. With no manifest the check could not run: say so and read slim. Keep the output and the effective class.
3. **PREFLIGHT** — no agent on an effective prose or trivial: instead the PM runs the base's `scripts/harness.py budget --root <project>` itself, the base being the `base` path in `.claude/harness.json`, relative to the project root, which checks `memory/STATUS.md` against its budget. It is read as `gate-preflight` item 6 reads it: a final line `budget: PASS` passes; `budget: FAIL` is a FAIL, its failing lines quoted; a refusal (`budget: refused — <reason>` on stderr) or no final line is UNVERIFIABLE, quoted; `NOT CHECKED` lines are quoted and never a FAIL. Where `trees` is filled and this session's project root is not the Hub path, on an effective prose or trivial the PM also runs the base's `scripts/hub.py level-check --root "<Hub path>" --branch <branch> --main <main branch>`, `<main branch>` the `vc` binding's *Main branch* slot, read as `gate-preflight` item 7 reads it, and on an effective slim item 7 does it; `level-check: FAIL` is remediated by `.claude/references/core/gate-close.md` `### CATCH-UP` and read again, never rulable and outside `.claude/references/core/gate-packet.md` `## The budget ruling`, and a refused read does not read as passed: it is shown at PRESENT, never waivable, the packet put in full, and RESOLVE's `<reading>` is not `PASS` on it. On an effective slim, file `.scratch/g2-lite-<changeset>-preflight-brief.md` from the common fields of `.claude/references/core/brief-fields.md` — the changeset and what it claims to do, the composition's declared preflight checks, the `vc`, `verification` and `trees` bindings quoted, and the project rules, as those common fields say — then dispatch `gate-preflight` through the Agent tool without a `name`, scoped to the changeset rather than to a feature.
4. **PRESENT** — relay CLASS's output on every class — banner, bound lines, verdict, or that the check could not run; where the declared class is not slim and the verdict is not PASS, state the escalation: declared `<c>`, run at slim, with its FAIL lines. Where PREFLIGHT dispatched, relay the audit verbatim: per-item PASS / FAIL / UNVERIFIABLE with evidence. An audit FAIL → remediate and re-run the preflight; never present a failing audit as rulable. Where it dispatched none, say so and relay its `budget` output verbatim. A budget FAIL, at item 6 of the audit or in that output, every other FAIL remediated first, is relayed with no remediation, never as a PASS: REVIEW runs, RESOLVE passes `--preflight FAIL`, and HARD STOP puts `.claude/references/core/gate-packet.md` `## The budget ruling`, no question before RESOLVE. A refusal or no final line stays UNVERIFIABLE, shown and resolved before HARD STOP, never waivable. With a close given earlier in this session, the verdict is read as `.claude/references/core/gate-packet.md` `## The early word` says.
5. **REVIEW** — review per the `vc` binding, at the effective class, handed to the skill below as the class it reviews at. Where its *Merge procedure* names a pull-request route, run the pull-request review skill the project's version-control pack provides — it is in `.claude/skills/`. Where it names none, run core's `review-cycle` over the changeset. No `vc` binding: stop and say so. Where a review has already run on this changeset at the effective class or deeper — trivial below prose below slim below full, read from the profile its brief recorded under `## Angles` — it is confirmed rather than repeated — its CONFIRMED findings and the fixes landed for each, fixed by default and listed at the light lane's G2 stop, and the human's rulings on the only findings that took one: a disputed finding, a deferral, a scope change or a canon fork.
6. **RESOLVE** — at the head after REVIEW's fixes. A human-only check the issue, the branch's dated-note records (`memory/<YYYY-MM-DD>.md`) or the `verification` binding names, or the human's ask in this session to see the close, not yet on the branch's `memory/STATUS.md` line: the PM writes `human-check` or `human-ask` there. Where `.scratch/catch-up-record.md` holds a resolution line naming a writer, a fix round's among them, in any block, and `human-resolved` is not yet on the branch's line, the PM writes it there. Then the PM saves CLASS's read again, at this head, to `.scratch/g2-lite-<changeset>-close-numstat.txt`, and runs the base's `scripts/harness.py close-class --root <project> --class <declared> --numstat .scratch/g2-lite-<changeset>-close-numstat.txt --branch <branch> --status memory/STATUS.md --review clean|open --preflight <reading>`, with one `--item <id>` per batch item, the base being the `base` path in `.claude/harness.json`, relative to the project root. `--review clean` where every CONFIRMED finding is fixed and none is disputed, deferred or awaiting a ruling, else `open`; `<reading>` is `PASS` where PRESENT's audit or `budget` passed. Relay its output whole. Where CLASS's effective class was prose or trivial and a bound line of this output reads `FAIL`, the closing head is slim, deeper than the class PREFLIGHT and REVIEW ran at: both re-run at slim at this head — the `gate-preflight` audit and a slim review — then the read and `close-class` run again at the head after them, its `--preflight` and `--review` read only from that audit and that review. Its class is read by exit code and words: exit 0 and a last line beginning `close-class: delegated` or `close-class: audited` is that class, and no stop is put; anything else is a human class: HARD STOP. Where PRESENT relayed a budget FAIL, RESOLVE passes `--preflight FAIL`, which `close-class` reads as a human class: a waiver changes no reading, a re-run past it reads `FAIL` again, and the hub session's STATUS trim for a branch session moves no branch file, so RESOLVE does not re-run on it; with `trees` absent, or the hub session on its own branch, the trim goes as `.claude/references/core/gate-packet.md` `## The budget ruling` says.
7. **HARD STOP — the G2 ruling, `G2 · light lane · <class>`, on a human class.** Ask for the human's explicit G2 ruling on the pull request or changeset, its question headed `G2 · light lane · <class>` as `.claude/references/core/gate-packet.md` `## The class label` says, with the `bounds` lines, the audit where one ran, and the review in view, RESOLVE's output beside them, putting the packet by `.claude/references/core/gate-packet.md` `## The packet` and the ruling by `.claude/references/core/ruling-form.md`. A budget FAIL RESOLVE passed is put first, before the packet, by `.claude/references/core/gate-packet.md` `## The budget ruling`, the packet and the word waiting on that ruling and, on Trim, on `budget` passing. A clean preflight is not a ruling; neither is approval of anything but the close itself. Silence, enthusiasm or a 'looks good' is not a ruling. A close given earlier is held as `.claude/references/core/gate-packet.md` `## The early word` says, and a stood word is that ruling, the message put as information. The ruling's form — where and how it is given: in conversation, a pull-request approval, … — is the one the `vc` binding names; `ruling-form.md` governs what the PM's message puts to the human. Only that ruling unlocks steps 8 and 9.
8. **CLOSE OUT** — the CHANGELOG line and the `memory/` record, both inside the PM's own write scope and both the whole record this lane keeps: the lane writes no design, requirement or architecture doc, so no writer is dispatched to author a ruling into one. The close is recorded under its head: on a human class, `G2 ACCEPTED (light lane · <class>, <YYYY-MM-DD>)`, `<class>` the class the label names; on a delegated or audited class, `CLOSED BY CLASS (<delegated|audited>, <YYYY-MM-DD>)`, a close by class being no G2. The CHANGELOG line opens `` **`<changeset>`: <head>:** ``, and the dated note's H1 and any other STATUS or report line naming the close carry the head; the `## Auto-closed` line and the `FINISHED` line name no gate and stay as they are. The `memory/` record is the `memory/STATUS.md` line and the session's dated note; the same act writes the note as `.claude/references/core/gate-close.md` `## The dated note` says. For a batch, every item closes in the `memory/` record: each deferral's entry leaves `## Deferred` for the session's dated note. Where the changeset falsifies a product doc, say which doc and name the `product-docs` binding's *Reconciling agent* slot per `## Bindings` above, and leave the dispatch to the PM. The note's `## Changes` holds RESOLVE's output, the close numstat, `.scratch/g2-lite-<changeset>-close-numstat.txt`, as the changed-file list with line counts, and the CHANGELOG line.
