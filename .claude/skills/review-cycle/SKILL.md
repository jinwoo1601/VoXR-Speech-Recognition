# review-cycle

## What this is

**One union review cycle: correctness and quality in the same fan-out.** Finder angles read a shared brief and hunt in parallel; adversarial verifiers kill the weak findings; CONFIRMED findings are fixed by default and listed at the next gate, and the human rules only on a disputed finding, a deferral, a scope change or a canon fork; each fix goes to its owner from a brief. Its depth follows the lane and the changeset's class, as `## Depth profiles` says.

> Finders find, verifiers kill, a writing agent fixes what is CONFIRMED by default, and the human rules on what is disputed. No finding reaches the human unverified; every fix is listed at the next gate.

Scope boundary: this cycle reviews a working tree or branch in the checkout. A vc pack may ship a sibling bound to the hosted review its system provides; a feature may run both, and they are not redundant.

## Bindings

- `vc` (required) — the base-revision reads the brief quotes under `## Scope` (the changed-file list, a file at a revision, a diff between two revisions), the current-commit and working-tree reads of CHECK's reuse test, the *Branch procedure*, whose forms the lane read matches, the check-in procedure COMMIT follows, and the main branch, the lead's target. Absent → stop and say so before any brief is filed. A slot naming either read only inside a `TODO (`, or not at all, is never a stop: CHECK runs the suite.
- `verification` (required) — the whole key, quoted into `compile-check`'s brief at CHECK. `none` → CHECK is recorded as `nothing to run`. Whole: passed on at CHECK.
- `review` (optional) — the *Slim angles*, *Prose angles* and *Full angles* slots, the angles each profile runs, and the *Hot paths* slot, `core`'s `## review` section. Absent, empty or `TODO` → the defaults in `## Depth profiles`, and no hot paths declared, so EFF does not run; never a stop. A slot reading `default` means the table's default. Whole: every slot used.
- `process-docs` (optional) — the *Design docs* and *Feature docs* slots, by which `### CATCH-UP` tells locked text, and the *Persisted plan* slot, BRIEF's per-file intent. Absent → no path reads as locked text, and a writer's `BLOCKED` stands for it; never a stop of itself.
- `trees` (optional) — the Hub path the lead in `## Workflow` compares with this session's root and `### CATCH-UP` takes as `--root`; the Catch-up procedure and the Release files slot, read there. Absent → nothing is caught up, and the cycle runs as ever.
- Agents — `review-angle`, `finding-verifier`, or `compile-check` missing → stop before any dispatch and say so. `code-writer`, `doc-writer` or `architect` missing → the catch-up stop on a new decision where that writer's files conflict, the cycle otherwise unaffected.

## Prerequisites

Confirm before proceeding:
- The build is complete and green (run `compile-check` first if unsure).
- The scope is expressible as a revision range or branch in the `vc` binding's terms.
- The feature's process docs are locatable (they supply the invariants).

## Depth profiles

Depth is chosen by lane and class, not by taste.

| Profile | When | Angles (default) | Materiality floor | CHECK |
|---|---|---|---|---|
| **full** | a design or feature branch — at the feature track's G2, feature-lite included — and any branch the lane read cannot place | the composed roster set | no | as written |
| **slim** | a light-lane changeset of class slim, or of no declared class | LINE, GONE, XFILE | yes | as written |
| **prose** | a light-lane changeset of class prose | LINE, GONE, XFILE, CONV | yes | once, at the head after the last fix; a fix round does not re-run it |
| **trivial** | a light-lane changeset of class trivial | none — no fan-out | — | as written |

- **The lane read.** Match the branch under review against the forms the `vc` binding's *Branch procedure* names (a `<…>` placeholder matches any text), as `review-pr` does: the light-lane form is the light lane; the prototype form, `proto-<topic>` where the *Branch procedure* names none, selects the profile on the `depth:` line of the read's `--name prototype` form (`.claude/references/core/path-read.md` `## The read`), ahead of the table's *When*, and selects full where the read fails, the brief saying which case; the design and feature forms select full, save that the feature form, a feature-lite's too, selects the profile on the `depth:` line of the read's feature form (`.claude/references/core/path-read.md` `## The read`), ahead of the table's *When*, the feature name being the text that form's placeholder matches, and selects full where the read fails, as on `uncomposed`, `unreadable`, no `path:` line or no feature name readable, the brief saying which case; no match, or a slot naming no light-lane form, selects full, and the brief says which case applied. Never a stop.
- **The class read.** For a light-lane branch, the effective class the invoking skill's check named — its `bounds` verdict, handed in by `tackle-issue` REVIEW or `g2-lite` REVIEW — before the declared one; else the class the work declared at its start — the `class <c>` on the branch's line in `memory/STATUS.md` `## Current` — slim where none is found.
- **The `review` binding** replaces a profile's default angle list where its *Slim angles*, *Prose angles* or *Full angles* slot names one. The profile's name, the angles it runs, and where they came from (default or binding) are recorded under the brief's `## Angles`. On a `depth: <profile> (declared)` line, the record adds that the path declared it, naming the path; on `(default)`, nothing.
- **EFF** is listed only where the `review` binding's *Hot paths* slot names paths; the brief quotes them. With none declared EFF is not dispatched, in any profile, and the brief says so.
- **MOVED** is added after the profile's list is chosen, the default's or the `review` binding's, on every profile with a fan-out, whichever read selected it, so a project's own list keeps it. It is listed only where the brief's `## Master's changes` holds a `touches` or `calls` line, and once where the list already holds it, as the full default's composed roster set does. With no such line MOVED is not dispatched, in any profile, even where a list names it, and the brief says so. `## Angles` records it as added here, neither default nor binding. The trivial profile has no fan-out, so no angle: RULE shows that section with the diff.
- **A late move.** Where the step re-entering review hands in `late move` or `send-back`, the range runs from the head last reviewed to the present head, at the branch's profile. Clean or release-only, no block since the head last reviewed naming a writer: MOVED alone, where it applies; where it does not, no angle runs, the brief says so, and RULE follows. A resolved conflict, a block since naming a writer: the profile's angles and MOVED. The same on a `send-back`, whatever the blocks hold. `## Scope`'s range and base revision and `## Changed files` are read over that range, by the same slot; the trivial profile's RULE shows that range's diff.
- **The head last reviewed** is the head of the revision range under `## Scope` in the last review brief filed under `<slug>`: `.scratch/review-<slug>-late-<n>-brief.md` at its highest `<n>`, else `.scratch/review-<slug>-brief.md`. The blocks since it are those past the number that brief's `## Master's changes` records as read. A late move's brief is filed beside the earlier ones, `<slug>-late-<n>` being its `<slug>` in every name this cycle files, `<n>` one past the highest, from 1, so the earlier collation stands for the next gate's list. With none handed in, or no such brief, the cycle runs as ever: the whole branch at the profile, every block, the one brief name; `## Angles` says which case applied.
- **Widening and narrowing.** The human may widen any profile (e.g. "review thoroughly" → full). Never narrow below the profile without the human saying so; a narrowing is recorded in the brief and said at RULE.

## Materiality floor — slim and prose

A finding becomes a **numbered finding** only if it asserts something in the merged result is *wrong*: code that misbehaves, a doc statement that is false, a claim the change does not deliver, or a removal that lost behaviour. That is the whole bar — severity is not the test.

Everything about what the change *could additionally* have done — stronger coverage, a tighter assertion, an adjacent improvement, style, naming — is a **Note**: one line, no evidence block, marked unverified; a Note is not verified and not ruled.

The floor does not apply to the full profile, where a coverage gap can be exactly what blocks G2.

## Workflow

Where `trees` is filled, as `.claude/references/core/trees-contract.md` reads it, this session's project root is not the Hub path, and the branch under review is this tree's own, by the `vc` binding's current-branch read, `.claude/references/core/gate-close.md` `### CATCH-UP` runs first, before BRIEF, with `<skill>` `review-cycle`, `<slug>` this cycle's, and the target the main branch, or, where the branch's line in the hub's `memory/STATUS.md` reads `re-lock of <feature-branch>`, that feature branch. A range or another branch under review catches nothing up, since a review must not merge into a tree it was only asked to read; with those not met the cycle runs as ever.

1. **BRIEF** — build `.claude/references/core/review-brief.md` into `.scratch/review-<slug>-brief.md` before any fan-out: the revision range and the base-revision read idiom per the `vc` binding's *Base-revision reads* slot, stated literally (agents use exactly what the brief says); the changed-file list per the same slot; per-file intent from the persisted plan; under `## Load-bearing invariants`, first the entries of `.claude/references/core/prose-invariants.md`, copied verbatim and numbered under one lead-in line saying they are standing rules no check can read, so a finding against one is a breach of it in the change and never the observation that no check enforces it — whatever narrowing the human rules, since a narrowing chooses angles, not canon; a missing file is named there and again when the survivors are presented at RULE, and the cycle runs on — then the feature's own invariants; canon pointers from the feature docs; the project rules, as the template's Project rules says; under `## Master's changes`, read before `## Angles` is decided, the lines of `.scratch/catch-up-record.md`, what catch-up brought in from the target, whole, from the blocks since the head last reviewed, as that section's comment and `## Depth profiles` say; under `## Angles`, the angles of the profile `## Depth profiles` chooses, recorded as it says; the full profile's composed roster set is `.claude/references/core/angle-roster.md`, plus, for each name in `.claude/harness.json`'s `packs`, `.claude/references/<pack>/angle-roster.md` where it exists (no manifest, or a composed pack with no angle file of its own, is core's roster alone). A late move's range and file name are as `## Depth profiles` says. On the trivial profile, FAN OUT, DEDUP and VERIFY are skipped and RULE follows.
2. **FAN OUT** — one `review-angle` per angle listed under `## Angles`, each through the Agent tool without a `name`. Each call prompt = the brief's absolute path + that angle's roster entry pasted in full. Subagents inherit no context from this thread: every prompt must be self-contained. Read-only agents run in parallel — batch the dispatches in as few messages as possible.
3. **DEDUP** — main-thread reasoning, no agents: merge duplicate findings across angles, keep the strongest statement of each, drop anything the brief declared out of scope. On slim and prose, then apply `## Materiality floor — slim and prose`: each survivor is a numbered finding or a Note. The floor asks *wrong vs. could-be-better*, never *big vs. small*; never sort a real defect into Notes to shorten the review.
4. **VERIFY** — one `finding-verifier` per surviving numbered finding, its text passed verbatim plus the brief path; Notes are not verified. Batch ~5 at a time when findings exceed 10. No finding is presented to the human without a verifier verdict.
5. **RULE** — every CONFIRMED finding, a CONFIRMED-AS-CLARITY one included, goes to FIX without a ruling, and is listed, with its verdict and decisive evidence, at the next gate. The hard stop is only for a finding the PM disputes, one it proposes to defer, a fix that changes scope, or one a canon fork decides: present those ranked by severity then confidence, each with its verdict and decisive evidence, and each put to the human by `.claude/references/core/ruling-form.md`, its rule 3; the human rules fix / defer / reject per finding. Notes are listed after the findings, one line each, unverified, no ruling asked. On the trivial profile the human is shown the whole diff, by the `vc` binding's *Base-revision reads* slot's diff read, with the brief's `## Master's changes` whole, `other` lines too, and reads them; anything the human raises is ruled as a finding. File the collation — the profile run, findings, verdicts, and per finding `fixed by default` or its ruling — beside the brief as `.scratch/review-<slug>-collation.md` (the delegation contract's filing rule: read-only agents' reports are not filed raw). Deferred items are recorded in `memory/STATUS.md`, or where the project's deferral convention says.
6. **FIX** — a fix goes to its owner, from a brief of its own filed under `.scratch/`, never the review brief or the collation: for code and pack files, file `.scratch/code-writer-<slug>-review-fix-brief.md` on `.claude/references/core/code-writer-brief.md`'s field list — the findings it fixes as the task, each quoted with its verdict, its decisive evidence and its ruling where one was asked, its Plan reference reading `none — a review fix`, those findings standing in for the plan, the files in scope, the acceptance criteria, conventions, with each composed pack's writer-rules reference as the template's Conventions says, the project rules, as the template's Project rules says, and the Verification command the `verification` binding's targeted command, CHECK being the gate — and dispatch one `code-writer` through the Agent tool without a `name`, naming that brief by its absolute path, serially, one writer per tree; for prose docs and bindings, file `.scratch/doc-writer-<slug>-review-fix-brief.md` from `.claude/references/core/decision-brief.md`, each finding it fixes and its `fixed by default` or its ruling as the decision record, and dispatch `doc-writer` through the Agent tool without a `name`, naming that brief by its absolute path; for the architecture doc, file `.scratch/architect-<slug>-review-fix-brief.md` from the common fields of `.claude/references/core/brief-fields.md`, the doc by path and each finding it fixes quoted, and dispatch `architect` in its author mode through the Agent tool without a `name`, naming that brief by its absolute path; a later fix round re-files each. Each writer's report is read at the moment it returns: its first line must be a status word, and `BLOCKED` or `PARTIAL` stops the cycle there and goes to the human with the report — no CHECK, no further round; a report without a status line is a contract violation, reported and not acted on. The reviewed code's shape is canon, and the review is not a license to refactor. Agents find and verify, and a writing agent edits from the finding, or from the ruling where one was asked.
7. **CHECK** — where the `verification` binding is `none`, CHECK is recorded as `nothing to run` and no read is made. Else, first the reuse test, on the main thread, never taking a report's word that it is current: run, in this tree, the current-commit read and the working-tree read the `vc` binding's *Base-revision reads* slot names; then, of the `compile-check` reports under this tree's `.scratch/`, subdirectories included — each a `*-report*.md` file whose lines, blank ones and an opening `<!-- report-filer: … -->` line set aside, begin with a status line, `Tree:`, `Commit:` and `Clean:`, as `compile-check`'s `## Output` writes them — take the newest by modification time whose `Tree:` matches what the `verification` binding's *Working-dir read* prints in this tree, by its *Path form*, whose `Commit:` equals the fresh current-commit read, and which says `Clean: yes`; a report from another tree never counts. Reuse it only where all hold: the slot names both reads outside a `TODO (` and both ran without failing; the working-tree read printed nothing, an untracked file it lists counting as dirty; a report was taken; and it is green and full — its status line opening `DONE`, a `PASS` line for every Command the `verification` binding names, and no Fallback's line in place of one. A reuse runs no suite and files no `compile-check` brief: append to `.scratch/review-<slug>-check-reuse.md` a block holding the reused report's path, its `Commit:` line, the fresh current-commit read, the working-tree read's empty output and the date, and go to COMMIT. Anything else runs the suite: the commit moved, whatever files the move touched; a dirty tree; a report naming no commit or no clean state, red, partial or unreadable; no report taken; no read in the binding, or a failed one. To run it, file `.scratch/review-<slug>-check-brief.md` from the common fields of `.claude/references/core/brief-fields.md`, the `verification` binding quoted, and dispatch `compile-check` through the Agent tool without a `name`, naming that brief by its absolute path; a re-run of CHECK re-uses that brief. On FAIL, a fix round: add the parsed error list to the fix brief of each writer whose files it names, its Verification command now the targeted command on the failing checks, re-dispatch that writer as FIX says, and run CHECK again. **At most two fix rounds; after the second failure, STOP** and escalate to the human with both reports. On prose, it runs once, at the head after the last fix; a fix round does not re-run it. The reuse test holds in every profile, prose's one CHECK included.
8. **COMMIT** — per the `vc` binding's check-in procedure: inline on the main thread, or the agent the binding names; the findings summary is the message. This skill never commits by itself.

A handoff taken at a step boundary, as `handoff` `## When to hand off` says, after FAN OUT and before RULE files the findings the cycle holds, with any verdicts, as the collation `.scratch/review-<slug>-collation.md`, and its brief names that file and the review brief by path. After the last step there is no next step, and the objective is what follows — the invoking skill's next step where `tackle-issue` or `g2-lite` REVIEW invoked this cycle, otherwise the branch's gate skill — as `handoff` `## When to hand off` says of a skill's last step.
