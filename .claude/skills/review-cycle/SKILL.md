# review-cycle

## What this is

**One union review cycle: correctness and quality in the same fan-out.** Finder angles read a shared brief and hunt, in parallel one agent per angle on the full profile and in turn in one agent on slim and prose; adversarial verifiers kill the weak findings; CONFIRMED findings are fixed by default and listed at the next gate, and the human rules only on a disputed finding, a deferral, a scope change or a canon fork; each fix goes to its owner from a brief. Its depth follows the lane and the changeset's class, as `## Depth profiles` says.

> Finders find, verifiers kill, a writing agent fixes what is CONFIRMED by default, and the human rules on what is disputed. No finding reaches the human unverified; every fix is listed at the next gate.

Scope boundary: this cycle reviews a working tree or branch in the checkout. A vc pack may ship a sibling bound to the hosted review its system provides; a feature may run both, and they are not redundant.

Absent → stop and say so before any brief is filed. A slot naming either read only inside a `TODO (`, or not at all, is never a stop: CHECK reuses nothing and goes on as it says — the inherit command where no carry is owed, then the suite.
- `verification` (required) — the whole key, quoted into `compile-check`'s brief at CHECK. `none` → CHECK is recorded as `nothing to run`. Whole: passed on at CHECK.
- `review` (optional) — the *Slim angles*, *Prose angles* and *Full angles* slots, the angles each profile runs, and the *Hot paths* slot, `core`'s `## review` section. Absent, empty or `TODO` → the defaults in `## Depth profiles`, and no hot paths declared, so EFF does not run; never a stop. A slot reading `default` means the table's default. Whole: every slot used.
- `process-docs` (optional) — the *Design docs* and *Feature docs* slots, where BRIEF finds the feature's docs for its canon pointers, and the *Persisted plan* slot, BRIEF's per-file intent. Absent → never a stop of itself.
- `product-docs` (optional) — the *Location* slot, read by `.claude/references/core/gate-inherit.md` **A docs-only move.**, which CHECK's reuse test cites and its call reads as that paragraph says. Absent → that move adds no product-docs path, never a stop.
- Agents — `review-angle`, `finding-verifier`, or `compile-check` missing → stop before any dispatch and say so.

## Depth profiles

Depth is chosen by lane and class, not by taste.

| Profile | When | Angles (default) | Agents | Materiality floor | CHECK |
|---|---|---|---|---|---|
| **full** | a design or feature branch — at `g2-accept`'s G2, save where its path's `depth:` line names another profile, as `development-lite`'s slim — and any branch the lane read cannot place | the composed roster set | one `review-angle` per angle | no | as written |
| **slim** | a light-lane changeset of class slim, or with no class handed in | LINE, GONE, XFILE | one `review-angle` for all the listed angles, in turn | yes | as written |
| **prose** | a light-lane changeset of class prose | LINE, GONE, XFILE, CONV | one `review-angle` for all the listed angles, in turn | yes | once, at the head after the last fix; a fix round does not re-run it |
| **trivial** | a light-lane changeset of class trivial | none — no fan-out | none | — | as written |

- **The lane read.** Match the branch under review against the forms the `vc` binding's *Branch procedure* names (a `<…>` placeholder matches any text): the light-lane form is the light lane, save that a branch whose line in `memory/STATUS.md` `## Current` names no path `light` and is not read by its branch's form, each as `.claude/references/core/path-read.md` `## The STATUS line` reads it, is not the light lane whatever its form, and selects as the forms below select it, else full, the brief saying which case; the prototype form, `proto-<topic>` where the *Branch procedure* names none, selects the profile on the `depth:` line of the read's `--name prototype` form (`.claude/references/core/path-read.md` `## The read`), ahead of the table's *When*, and selects full where the read fails, the brief saying which case; the design and feature forms select full, save that the feature form, a feature-lite's too, selects the profile on the `depth:` line of the read's feature form (`.claude/references/core/path-read.md` `## The read`), ahead of the table's *When*, the feature name being the text that form's placeholder matches, and selects full where the read fails, as on `uncomposed`, `unreadable`, no `path:` line or no feature name readable, the brief saying which case; no match, or a slot naming no light-lane form, selects full, and the brief says which case applied. A `depth:` line whose word names no profile in the table above, as `computed` or `none` (`.claude/references/core/path-read.md` `## The read`), selects full on either form, the brief saying so. Never a stop.
- **The class read.** For a light-lane branch, the effective class the invoking skill hands in — the class its `bounds` check computed from the diff, handed in by `tackle-issue` REVIEW or `g2-lite` REVIEW — slim where none is handed in; the class is never read from `memory/STATUS.md`, whatever class token an older line there still carries.
- **The `review` binding** replaces a profile's default angle list where its *Slim angles*, *Prose angles* or *Full angles* slot names one. The profile's name, the angles it runs, and where they came from (default or binding) are recorded under the brief's `## Angles`. On a `depth: <profile> (declared)` line, the record adds that the path declared it, naming the path; on `(default)`, nothing.
- **EFF** is listed only where the `review` binding's *Hot paths* slot names paths; the brief quotes them. With none declared EFF is not dispatched, in any profile, and the brief says so.
- **Widening and narrowing.** The human may widen any profile (e.g. "review thoroughly" → full). Never narrow below the profile without the human saying so; a narrowing is recorded in the brief and said at RULE.

## Materiality floor — slim and prose

A finding becomes a **numbered finding** only if it asserts something in the merged result is *wrong*: code that misbehaves, a doc statement that is false, a claim the change does not deliver, or a removal that lost behaviour. That is the whole bar — severity is not the test.

Everything about what the change *could additionally* have done — stronger coverage, a tighter assertion, an adjacent improvement, style, naming — is a **Note**: one line, no evidence block, marked unverified; a Note is not verified and not ruled.

The floor does not apply to the full profile, where a coverage gap can be exactly what blocks G2.

## Workflow

1. **BRIEF** — build `.claude/references/core/review-brief.md` into `.scratch/review-<slug>-brief.md` before any fan-out: the revision range and the base-revision read idiom per the `vc` binding's *Base-revision reads* slot, stated literally (agents use exactly what the brief says); the changed-file list per the same slot; per-file intent from the persisted plan; under `## Load-bearing invariants`, first the entries of `.claude/references/core/prose-invariants.md`, copied verbatim and numbered under one lead-in line saying they are standing rules no check can read, so a finding against one is a breach of it in the change and never the observation that no check enforces it — whatever narrowing the human rules, since a narrowing chooses angles, not canon; a missing file is named there and again when the survivors are presented at RULE, and the cycle runs on — then the feature's own invariants; canon pointers from the feature docs; under `## Red evidence`, each line opening `red` held by the phase report `implement` FILE saved for each of the build plan's phases, copied verbatim, phase by phase, or `none` where no phase report holds one, as the template's Red evidence says; the project rules, as the template's Project rules says; under `## Angles`, the angles of the profile `## Depth profiles` chooses, recorded as it says; the full profile's composed roster set is `.claude/references/core/angle-roster.md`, plus, for each name in `.claude/harness.json`'s `packs`, `.claude/references/<pack>/angle-roster.md` where it exists (no manifest, or a composed pack with no angle file of its own, is core's roster alone). On the trivial profile, FAN OUT, DEDUP and VERIFY are skipped and RULE follows.
2. **FAN OUT** — the dispatch follows the profile's *Agents* cell in `## Depth profiles`, each call through the Agent tool without a `name`. On the full profile, one `review-angle` per angle listed under `## Angles`, each call prompt = the brief's absolute path + that angle's roster entry pasted in full. On the slim and prose profiles, one `review-angle` for all the angles listed under `## Angles` — the profile's default or the `review` binding's list, with EFF where it applies — its call prompt = the brief's absolute path + every listed angle's roster entry pasted in full, in `## Angles` order. Subagents inherit no context from this thread: every prompt must be self-contained. Read-only agents run in parallel — batch the dispatches in as few messages as possible.
3. **DEDUP** — the PM's reasoning, no agents. On slim and prose, first match each angle listed under `## Angles` to its `### <NAME>` block in the one report: an angle with no block, or whose block reads `Not run — <why>.`, is named in the collation as not run, with its why where given, and is not re-dispatched. On full, slim and prose alike, merge duplicate findings across angles, keep the strongest statement of each, drop anything the brief declared out of scope. On slim and prose, then apply `## Materiality floor — slim and prose`: each survivor is a numbered finding or a Note. The floor asks *wrong vs. could-be-better*, never *big vs. small*; never sort a real defect into Notes to shorten the review.
4. **VERIFY** — one `finding-verifier` per surviving numbered finding, its text passed verbatim plus the brief path; Notes are not verified. Batch ~5 at a time when findings exceed 10. No finding is presented to the human without a verifier verdict.
5. **RULE** — every CONFIRMED finding, a CONFIRMED-AS-CLARITY one included, goes to FIX without a ruling, and is listed, with its verdict and decisive evidence, at the next gate. The hard stop is only for a finding the PM disputes, one it proposes to defer, a fix that changes scope, or one a canon fork decides: present those ranked by severity then confidence, each with its verdict and decisive evidence, and each put to the human by `.claude/references/core/ruling-form.md`, its rule 3; the human rules fix / defer / reject per finding. Notes are listed after the findings, one line each, unverified, no ruling asked. Each angle DEDUP named not run is listed at the next gate after the Notes, one line each, with its why where given. On the trivial profile the human is shown the whole diff, by the `vc` binding's *Base-revision reads* slot's diff read, and reads it; anything the human raises is ruled as a finding. File the collation — the profile run, each angle DEDUP named not run with its why, findings, verdicts, and per finding `fixed by default` or its ruling — beside the brief as `.scratch/review-<slug>-collation.md` (the delegation contract's filing rule: read-only agents' reports are not filed raw). Each finding the human rules defer is drafted as an item, `kind: deferral`, at `.scratch/review-<slug>-items/<item-slug>.md` beside the collation, which names each by slug, and the next gate's record files it (`.claude/references/core/gate-close.md` `## The record`).
6. **FIX** — a fix goes to its owner, from a brief of its own filed under `.scratch/`, never the review brief or the collation: for code and pack files, file `.scratch/code-writer-<slug>-review-fix-brief.md` on `.claude/references/core/code-writer-brief.md`'s field list — the findings it fixes as the task, each quoted with its verdict, its decisive evidence and its ruling where one was asked, its Plan reference reading `none — a review fix`, those findings standing in for the plan, the files in scope, the acceptance criteria, conventions, with each composed pack's writer-rules reference as the template's Conventions says, the project rules, as the template's Project rules says, and the Verification command the `verification` binding's targeted command, CHECK being the gate — and dispatch one `code-writer` through the Agent tool without a `name`, naming that brief by its absolute path, serially, one writer per tree; for prose docs and bindings, file `.scratch/doc-writer-<slug>-review-fix-brief.md` from `.claude/references/core/decision-brief.md`, each finding it fixes and its `fixed by default` or its ruling as the decision record, and dispatch `doc-writer` through the Agent tool without a `name`, naming that brief by its absolute path; for the architecture doc, file `.scratch/architect-<slug>-review-fix-brief.md` from the common fields of `.claude/references/core/brief-fields.md`, the doc by path and each finding it fixes quoted, and dispatch `architect` in its author mode through the Agent tool without a `name`, naming that brief by its absolute path; a later fix round re-files each. Each writer's report is read at the moment it returns: its first line must be a status word, and `BLOCKED` or `PARTIAL` stops the cycle there and goes to the human with the report — no CHECK, no further round; a report without a status line is a contract violation, reported and not acted on. The reviewed code's shape is canon, and the review is not a license to refactor. Agents find and verify, and a writing agent edits from the finding, or from the ruling where one was asked.
7. **CHECK** — where the `verification` binding is `none`, CHECK is recorded as `nothing to run` and no read is made. Else, first the reuse test, in the PM's context: one call, as `## The reuse test` says, decides it in this tree and, on a reuse, appends the reuse block to `.scratch/review-<slug>-check-reuse.md` itself. A reuse runs no suite and files no `compile-check` brief: CHECK goes to COMMIT. Anything else runs the suite: a `not reused:` line, a refusal, a call printing none of the table's first words, or a `manual:` line whose test by hand reuses nothing.
