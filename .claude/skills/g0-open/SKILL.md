# g0-open

## What this is

G0 opens a design topic, a feature or a prototype: the human and the PM agree the scope, the branch is created, and the scope, with a feature's user story beside it, is recorded as the doc's opening sections — no doc or code exists before the branch does.

> The branch first, then the scope in writing. Nothing is built on the main branch.

## Workflow

Where `trees` is filled, as the contract reads it, these steps run as `references/tree-path.md` orders them; otherwise they run as written.

1. **SCOPE** — the hard stop: the PM puts the G0 packet (`.claude/references/core/gate-packet.md` `## The G0 packet`) by `.claude/references/core/ruling-form.md` — one question asking only agreement to the topic, or the backlog feature, and its scope, its defaults shown: for a feature the user story, drafted by the PM in the form *As a \<user\>, I want \<capability\>, so that \<value\>.*, and the track, and the path, read with the mark from the row, `development` where it names none, the composed paths by the base's `scripts/harness.py doctor --paths --root <project>` as that section says; the lane; on the tree path, concurrency — each overridable in the same answer. For a prototype — from a backlog row whose path reads `prototype`, its topic the row's Feature slug, or standalone, before any design, from a topic and the question it answers — the scope is that one question, the packet showing path and lane `prototype` and no story or track, and no locked design is named (`adr-0088` S4): the two feature clauses below do not apply to it. A standalone open naming no question, or a topic whose directory under *Design docs* the main branch already holds, is refused and asked again, the ask saying why, before the packet is put and again on a topic the answer changes; the main branch holds that directory where the `vc` binding's *Base-revision reads* file read, given the main branch and that directory's path, succeeds. A prototype open runs the composed-path read a feature open runs, the base's `scripts/harness.py doctor --paths --root <project>` as `.claude/references/core/gate-packet.md` `## The G0 packet` says, before the packet is put, and is refused and asked no further, the refusal saying why, where the read does not print the path `prototype` — the project not composing the prototype path — or exits non-zero or cannot run, the refusal then saying the composed paths could not be read; nothing is cut or written. Before putting the scope, the PM reads `memory/backlog-candidates.md` and `memory/notes-for-future-features.md`, where they exist. For a feature, the PM names with the scope the design doc it comes from, locked at G1 by `g1-lock`, and the feature's row in that design's backlog, or the locked design doc that names the feature, each where the `process-docs` binding puts design docs; where it can name neither, it puts no feature scope and creates nothing for the feature: it stops and offers a design topic for the work in its place, which this skill opens as a design topic where the human takes it. Nothing is created before that agreement. For a backlog feature the PM reads the row's mark and names the track, lite or full, with the scope (`.claude/references/core/feature-lite.md` `## The mark`).
2. **BRANCH** — per the `vc` binding's branch procedure; the ceremony is the PM's. For a prototype it cuts the prototype form the branch procedure names, `proto-<topic>` where it names none.
3. **RECORD** — file `.scratch/doc-writer-<slug>-g0-brief.md` from `.claude/references/core/decision-brief.md`: the agreed scope with each default shown and how it was ruled — taken, or overridden in the human's words — as the decision record, the target and form per the `process-docs` binding's *Design docs* or *Feature docs* slot — the design doc's scope section for a design topic, the requirements doc's §1, the user story, and §2, the scope, for a feature. For a lite feature the target is the architecture doc's `## User story` and `## Context & scope`, no requirements doc is made (`.claude/references/core/feature-lite.md` `## The three placements`), and the brief says `lite`, gives the backlog's path and quotes the row (`.claude/references/core/feature-lite.md` `## The acceptance source`). Dispatch `doc-writer` through the Agent tool without a `name`. For a prototype the brief's target is the *Prototype requirements* file, `requirements.md` where that slot is absent or reads `TODO`, in the topic's directory under *Design docs*, by absolute path, created whole from the form, no section named, `doc-writer` filling the front matter's `topic` with the topic and `updated` with the open's date, the title's `<Topic>` with the topic, and `## 1. The question` with the agreed question in place of its guidance comment, and leaving `## 2. Learned enough`, `## 3. Out` and every other line as the form has them; the form to match is the pack's template, `.claude/skills/prototype-requirements/assets/requirements-template.md`, and `prototype-requirements` settles `## 2. Learned enough` and `## 3. Out` with the human. Where the taken word changes what the row reads, the brief also names the backlog as a further target, its `Section:` the feature's row, the row's path sentence only, quoting the word, as `.claude/references/core/feature-lite.md` `## The mark` says; that target is listed last on a full feature and first on a lite one, whose brief quotes the row as edited, the PM composing that quote before the edit exists, so the opening quote and `gate-preflight`'s match read the edited row; a refused edit is reported and the PM stops, the record `doc-writer` still writes staying out of any check-in until the edit lands or, the human withdrawing the word, the record is rewritten to the row as it reads, and on a lite feature the stop says the record's quote is of an edit that never landed; the check-in carries both files on the feature branch.
4. **STATUS** — the PM adds the branch's line to `memory/STATUS.md` (name, lane, stage, next action; on a feature's or a prototype's line the path too, as `.claude/references/core/path-read.md` `## The STATUS line` says; within the `board` binding's *STATUS line cap* — absent or `none` → no cap stated) and checks in per the `vc` binding's check-in procedure.

Where `trees` is filled, as the contract reads it, several items the human orders at once start under one ruling, as `references/tree-path.md` `## Several items` orders them; where it reads absent, one item at a time through `## Workflow`, as today.
