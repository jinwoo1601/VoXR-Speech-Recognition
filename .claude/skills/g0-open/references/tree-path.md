# g0-open — the tree path

The order `g0-open`'s `## Workflow` steps run in where `trees` is filled, and how several items start under one ruling; "the contract" is `.claude/references/core/trees-contract.md`.

## The tree path

Where `trees` is filled, as the contract reads it, the work runs in two parts, in two sessions: the ordering session — the one holding the human's order, the hub session as a rule — cuts the branch and its tree from the item's line and launches the branch's own session, and that session agrees the scope and records it. Each step names the `## Workflow` steps it runs, and CUT stands in for BRANCH wherever this skill names BRANCH. Which session a run is in, one command, alone in its call, run from this session's project root, decides: `py <script> where`, `<script>` as `.claude/references/core/gate-close.md` `## The clear` gives it, which compares that root with the Hub path and with each tree the List read names, as the trees contract (`.claude/references/core/trees-contract.md`) compares them. A run is the branch's where it prints `tree:` and that tree's branch's block of the hub's `memory/STATUS.md` `## Current`, which its `current:` lines print whole, is absent or LAUNCH's, its next action `g0-open` SCOPE; any other run is the ordering session's, as the table below reads each first word.

| `where` prints | The run is |
|---|---|
| `tree: <path>; branch <branch>` | the branch's where its `current:` lines read `current: none` or are LAUNCH's block, its next action `g0-open` SCOPE; otherwise the ordering session's |
| `hub:` or `none:` | the ordering session's |
| `manual: <slot>` | settled as the binding writes that slot, for that part only: this session's project root compared with the Hub path as the trees contract compares them, the List read, run in the hub by the trees contract's hub clause, naming that root as a tree, and that tree's branch's block read from the hub's `memory/STATUS.md` `## Current` by absolute path under the Hub path, a *Path form* absent or a single `none` stopping here, naming the slot, as the contract says; then the row of the word `where` would have printed decides |
| no manifest, exit 1, any other output, or a refused call | stop and say so, never retried in another form; nothing is made |

The active branches, which INDEPENDENCE, RE-CHECK and `## Several items` read, are the blocks of the hub's `memory/STATUS.md` `## Current`, read by absolute path under the Hub path, and the trees the List read names, run in the hub by the trees contract's hub clause, the hub excepted, whose branch no block names and which are in progress, each judged on its backlog line: a tree whose branch no `## Current` block names is in progress — counted among the active branches, and never "merged and awaiting removal" — when a session is at it (the List command, a session being at a tree when its working directory, as the list shows it, is the tree's path or lies under it, compared as the trees contract compares paths, where the `session-launch` key reads filled) or its branch has a commit the main branch lacks (the `vc` binding's log read); where the key reads absent, so sessions cannot be seen, every such tree counts as active. Where the key reads filled, such a tree with no session at it and no commit of its own is not among them.

**In the ordering session:**

1. **INDEPENDENCE** — on the item's line, its backlog line or the design topic as the human names it: state for each active branch whether this item is independent of it — neither depends on the other, and their expected write sets do not overlap outside the release class, `memory/` exempt; and, where a release class exists, name each overlap outside it (code, locked docs, annex register rows, the shared test file) and the release files whose overlap is set aside. The release class is the `trees` binding's Release files slot, as the contract's `## The release files` reads it: an entry with no rule is outside it, and where the slot names no release class, every overlap is outside it. Where any active branch is stated not independent, the human rules run concurrently or wait, put to the human by `.claude/references/core/ruling-form.md`; Wait → stop; nothing is made. Where none is, or no active branch exists → no ruling: the item runs concurrently, shown as a default in the branch's G0 packet (`.claude/references/core/gate-packet.md` `## The G0 packet`).
2. **CHECKS** and **CUT** — for a prototype, CHECKS first runs the composed-path read `## Workflow`'s SCOPE runs for a prototype, in the hub, before the call below, and its refusal stops here, saying why, as SCOPE says; nothing is made. Then one command, alone in its call, run from this session's project root, its Bash call given 600000 ms, never the tool's shorter default: `py <script> cut --branch <branch> [--item <slug>] --allow-kept`, `<script>` as `.claude/references/core/gate-close.md` `## The clear` gives it, `<branch>` the branch the `vc` binding's branch procedure names for this work, by its own name, never prefixed with the main branch's name, and `--item <slug>` where LAUNCH takes an item, `<slug>` its slug, omitted where it takes none. The verb runs CHECKS, a branch the branch check finds passing only as a kept branch, by the `vc` binding's log read from the main branch, then CUT, its kept-branch form for a kept branch, in the hub, and the List read confirm; `py <script> cut --help` states each rule. The table below reads what it prints, each line by its first word, a `fail:` line ruling over a `manual:` line.

| `cut` prints | CHECKS and CUT |
|---|---|
| `cut: <path>; branch <branch>[; kept]` | the branch and its tree are cut, a kept branch moved to the main branch's head; LAUNCH follows, the new tree at `<path>` |
| `fail: <check>: <what the read showed>` | a check failed: stop and say each `fail:` line, as printed; nothing is made |
| `refused: <step>: …` or `unconfirmed: <path>; …` | the cut ran and is not confirmed: stop and say the line, as printed; nothing is retried or undone, and the branch and tree it names are left for the human |
| `manual: <slot>` | nothing was made: that slot's part runs as the binding writes it, then each part after it as `py <script> cut --help` states it — the Create procedure's branch check, kept-branch read and cut, and the List read confirm, each in the hub by the trees contract's hub clause, a *Path form* absent or a single `none` stopping here, naming the slot, as the contract says; where the Create procedure names no form for a kept branch, a found branch fails as the branch check does, saying the binding names none; any failing → stop and say which; nothing is made |
| `skipped: trees absent` | the `trees` key reads absent after all: stop and say so; nothing is made |
| exit 1 with no outcome line, any other output, or a refused call | stop and say so, the `hub.py cut:` line where it printed one, never retried in another form; nothing more is made |

   *Amended 2026-11-16, by the human's ruling "Delete empty, recreate (Recommended)":* where no command moves an existing branch, the Create procedure's form for a kept branch may delete the kept branch, which CHECKS has read as holding nothing the main branch lacks, and recreate it at the main branch's head by the Create procedure's own steps; that recreate is this step's "moves that branch to the main branch's head". A form that refuses — the delete refusing a branch that holds anything of its own, or a workspace on that branch — stops CUT, saying the refusal; nothing is deleted or made. (Path-on-status decision L's note of the same date quotes the ruling in full.)

3. **LAUNCH** — invoke `handoff` for the branch's launch brief: the target the new tree, by its path per the List read; the lane `design` for a design topic, `feature` for a feature or `prototype` for a prototype; the next step `g0-open` in that tree, whose branch run starts at SCOPE; and the branch's `## Current` entry, naming the branch, that lane and the next action `g0-open` SCOPE, which `handoff` drafts. Where the order cuts the branch for an item — a feature's `memory/items/<feature>.md`, `<feature>` its row's Feature slug, and each `memory/items/<slug>.md` whose slug the row's `Sites:` list names in its Scope cell, or, for a design topic, the item the human's order names by slug; a prototype takes none — LAUNCH names each such item's slug to `handoff` as taken, one `--take-item <slug> <branch>` per slug, each only where one Glob of the hub's `memory/items/<slug>.md`, by absolute path under the Hub path, issued in the message carrying `handoff`'s drafts, lists the file; no such file → no item and no error, for that slug alone. `handoff`'s call lands that entry in the hub first, then the brief is written into the new tree's slot, and only then does `handoff` launch the session by its `references/launch.md` or give the paste line. A refused `--take-item` — the item absent, malformed or taken by another branch — ends the run as the table in `handoff` `## The dated note` reads that call's outcomes: BLOCKED, the drafts kept, no brief, no launch. This session's part in the branch ends here.

**In the branch's own session**, launched or opened from the paste line:

4. **SCOPE** — `## Workflow`'s SCOPE, as written, on the item the brief's Objective names. The packet's concurrency default states "run concurrently" with each active branch, this one excepted, read as `## The tree path` reads them, each stated independent or not on the item's line as INDEPENDENCE judges it, and, where a release class exists, naming each overlap outside it and the release files set aside. For a feature, where the PM can name no locked design, `## Workflow`'s SCOPE makes its offer, saying that this run agrees no scope whatever the answer, and the item reads as Declined: a design topic the human takes is a new item the human orders in the ordering session, whose CUT cuts its own branch. For a prototype, a topic `## Workflow`'s SCOPE refuses as one the main branch already holds reads as Declined the same way, the reason said, a new topic being a new item the human orders in the ordering session; a standalone open naming no question is asked again here. Declined or Wait → nothing written but that removal and the taken item's return or close: where `## The tree path` found LAUNCH's block, one `scripts/hub.py write --root <hub> --message <file> --remove-entry Current <branch>` command removes it, adding, per item the base's `scripts/hub.py items --root <hub> --status taken` shows `taken <branch>`, `--release-item <slug>`, or, where the human's words decline the item itself, as the PM reads them, `--note <file>`, an entry in `.claude/references/core/gate-close.md` `## The dated note`'s form, then `--close-item <slug> declined`, a failed read said and returning nothing, with `--main` as the trees contract says, `<hub>` the Hub path, run from this tree, its inputs drafted into `.scratch/g0-open-<slug>-record/` and what it prints read by the table after this step; then, where the `session-launch` binding reads filled with its Hub session name, as the contract reads it, say the report line, `FINISHED - <branch>; lane: <lane>; declined at G0, nothing written` for a decline or `FINISHED - <branch>; lane: <lane>; waits at G0, nothing written` for a wait, `<lane>` the brief's Lane, then send it by `SendMessage` to the Hub session name as this session's last act, since the hub session may stop this session within seconds and removes the tree once its checks pass; otherwise nothing is sent, and the tree stays until `orient` proposes its removal. On a wait the item stays on its backlog line. Either way this session does no further work.

| `write` prints | Declined or Wait |
|---|---|
| the commit line, exit 0 | the removal and the item's return or close landed: the report line follows, as SCOPE says |
| `hub.py write:` with a `correct:` line, exit 1 | correct the part it names and re-run, by the trees contract's rule, as STATUS says |
| `hub.py write:` with a `clear:` line, exit 3 | the lock held: BLOCKED and stop, naming the `clear:` line, by the same rule |
| `hub.py write:` with no `correct:` line, exit 1 — a `--release-item` whose item is absent or malformed among them — or any other output | BLOCKED and stop, by the same rule |

5. **RE-CHECK** — once the scope is agreed: the active branches, this one excepted, each stated overlapping or not — their expected write sets against this branch's, judged on its agreed scope, outside the release class as INDEPENDENCE reads it, `memory/` exempt — and each overlap stated as shown in SCOPE's packet or not: where a release class exists, an overlap the packet did not name is not shown; where none exists, an overlap with a branch the packet did not state, or stated independent, is not shown. RE-CHECK takes no stop and sends no report line: each overlap the packet did not show is stated in this session's output, and the PM appends, per other branch, the line `re-check <branch> overlaps <other branch>: <the overlap as stated>`, each overlap by the paths it expects to share where the agreed scope names them, by area otherwise, `<branch>` this branch, to this tree's `.scratch/catch-up-record.md`, no heading, making the record where absent, for the gate packet to name (`.claude/references/core/gate-packet.md` `## The packet`); an overlap the packet showed was ruled at the cut and is not recorded. RECORD follows, whatever RE-CHECK found.
6. **RECORD** — `## Workflow`'s RECORD, with the brief naming `doc-writer`'s target in this tree; then the PM checks the record in on the branch, in this tree, per the `vc` binding's check-in procedure, run here as the binding writes it.
7. **STATUS** — `## Workflow`'s STATUS, the branch's line written to the hub's `memory/STATUS.md` `## Current` by one `scripts/hub.py write --root <hub> --message <file> --entry Current <branch> <file>` command, replacing LAUNCH's block in place, or added where there is none, with `--main` as the trees contract says, `<hub>` the Hub path, run from this tree, its inputs drafted into `.scratch/g0-open-<slug>-record/`, `<slug>` the topic or feature, the `--entry` file holding the one entry line, opening `- **` and its key; a refusal printing a `correct:` line: correct it and re-run; any other refusal, the re-run cap spent, or a lock the command holds on its own failure: BLOCKED and stop — both by the trees contract's rule (`.claude/references/core/trees-contract.md` `## The hub operation`). The branch's work goes on in this session.

## Several items

1. **SET** — the human names the items, or approves a set the PM proposes: the PM proposes at most three, and the human may name more. Nothing is made before the set is named or approved, and nothing launches on the PM's judgement.
2. **INDEPENDENCE** — once for the set: each item, on its line, against the active branches as `## The tree path` reads them, and pair by pair within the set, each stated independent or not as `## The tree path`'s INDEPENDENCE states it, any release class's files set aside; then, only where an item is stated not independent, of an active branch or of another item in the set, one ruling from the human on which items run and which wait, put to the human by `.claude/references/core/ruling-form.md`; otherwise no ruling, and every item runs. None runs → stop; nothing is made.
3. **CHECKS, CUT and LAUNCH, per item** — for each item that runs, in turn, `## The tree path`'s CHECKS, CUT and LAUNCH, the next item's CHECKS only once this item's LAUNCH has returned. A CHECKS or CUT failure stops the loop: say the item, what failed, and what the loop has made so far — each earlier item's branch, tree, `## Current` entry and brief — and nothing more is made. A failed launch, `handoff` giving that item's paste line, is that item's outcome, its tree kept, and the loop goes on.

Each item's branch session then runs `## The tree path` from SCOPE.
