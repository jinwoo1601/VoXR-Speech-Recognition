## The tree path

Where `trees` is filled, as the contract reads it, a run first settles whether it is resumed, before `## When it applies — and prerequisites` is confirmed, by one command, alone in its call, run from this session's project root: `py <script> where`, `<script>` as `.claude/references/core/gate-close.md` `## The clear` gives it, which compares that root with the Hub path and with each tree the List read names, as the trees contract (`.claude/references/core/trees-contract.md`) compares them. It is resumed where it prints `tree:` and the block of the hub's `memory/STATUS.md` `## Current` for that tree's branch, which its `current:` lines print whole, names the issue, or the batch, the human named for this run; any other run is a cutting run, as the table below reads each first word.

| `where` prints | The run is |
|---|---|
| `tree: <path>; branch <branch>` | resumed where a `current:` line names the issue, or the batch, the human named for this run; otherwise a cutting run |
| `hub:` or `none:` | a cutting run |
| `manual: <slot>` | settled as the binding writes that slot, for that part only: this session's project root compared with the Hub path as the trees contract compares them, the List read, run in the hub by the Hub slot's idiom, naming that root as a tree, and that tree's branch's block read from the hub's `memory/STATUS.md` `## Current` by absolute path under the Hub path, a *Path form* absent or a single `none` stopping here, naming the slot, as the contract says; then the row of the word `where` would have printed decides |
| no manifest, exit 1, any other output, or a refused call | stop and say so, never retried in another form; nothing is made |

**A cutting run** takes these steps, each naming the `## Workflow` steps it runs; CUT stands in for BRANCH, and the run ends at LAUNCH.

1. **SELECT, UNDERSTAND and RECORD** — `## Workflow`'s SELECT, UNDERSTAND and RECORD, as written. RECORD's line is written at STATUS.
2. **INDEPENDENCE** — read the other active branches from the blocks of the hub's `memory/STATUS.md` `## Current`, by absolute path under the Hub path, and state for each whether this branch is independent of it: neither depends on the other, and their expected write sets do not overlap outside the release class, `memory/` exempt; and, where a release class exists, name each overlap outside it (code, locked docs, annex register rows, the shared test file) and the release files whose overlap is set aside. The release class is the `trees` binding's Release files slot, as the contract's `## The release files` reads it: an entry with no rule is outside it, and where the slot names no release class, every overlap is outside it. Where no release class exists, the human rules run concurrently or wait; where one exists, the human rules only where any branch is stated not independent, and where none is, or no other active branch exists → no ruling: the branch runs concurrently, shown as a default in the run's output. Wait → stop; nothing is made. No other active branch → nothing to rule.
3. **CHECKS** and **CUT** — one command, alone in its call, run from this session's project root, its Bash call given 600000 ms, never the tool's shorter default: `py <script> cut --branch <branch>`, `<script>` as `.claude/references/core/gate-close.md` `## The clear` gives it, `<branch>` the branch the `vc` binding's branch procedure names for this work, on Plastic SCM its own name. The verb runs CHECKS, a branch the branch check finds failing, then CUT, in the hub, and the List read confirm; `py <script> cut --help` states each rule. The table below reads what it prints, each line by its first word, a `fail:` line ruling over a `manual:` line.

| `cut` prints | CHECKS and CUT |
|---|---|
| `cut: <path>; branch <branch>` | the branch and its tree are cut; STATUS follows, the new tree at `<path>` |
| `fail: <check>: <what the read showed>` | a check failed: stop and say each `fail:` line, as printed; nothing is made |
| `refused: <step>: …` or `unconfirmed: <path>; …` | the cut ran and is not confirmed: stop and say the line, as printed; nothing is retried or undone, and the branch and tree it names are left for the human |
| `manual: <slot>` | nothing was made: that slot's part runs as the binding writes it, then each part after it as `py <script> cut --help` states it — the Create procedure's branch check and cut, and the List read confirm, each in the hub by the Hub slot's idiom, a *Path form* absent or a single `none` stopping here, naming the slot, as the contract says; any failing → stop and say which; nothing is made |
| `skipped: trees absent` | the `trees` key reads absent after all: stop and say so; nothing is made |
| exit 1 with no outcome line, any other output, or a refused call | stop and say so, the `hub.py cut:` line where it printed one, never retried in another form; nothing more is made |

4. **STATUS** — the branch's line — its name, the light lane, the issue or a batch's items as `batch <id>, <id>...`, and the next action, with RECORD's word, within the `board` binding's *STATUS line cap* (absent or `none` → no cap stated), `path light` standing after the lane, as RECORD records it — written as a draft into `.scratch/tackle-issue-<slug>-record/`, `<slug>` the topic of the branch CUT cut, as the one entry line, opening `- **` and its key, for `--entry Current <branch> <file>` on the hub's `memory/STATUS.md` `## Current`; LAUNCH's call lands it in the hub. Each item SELECT took is taken by that call, `--take-item <item-slug> <branch>` per item after the entry, with no draft.
5. **LAUNCH** — invoke `handoff` for the branch's launch brief: the target the new tree, by its path per the List read; the lane `light`, or for a batch `light, batch <id>, <id>...`; the next step `tackle-issue` for the same issue or batch in that tree, whose resumed run goes on from DIAGNOSE; and STATUS's draft, the entry, with each item SELECT took named as taken, by its slug. `handoff`'s call lands that entry in the hub first, then the brief is written into the new tree's slot, and only then does `handoff` launch the session or give the paste line, telling the human the tree's path and to open a plain `claude` session there, never `claude -w`. A refused `--take-item` — the item absent, malformed or taken by another branch — ends the run as the table in `handoff` `## The dated note` reads that call's outcomes: BLOCKED, the drafts kept, no brief, no launch. The run stops here: DIAGNOSE and every step after it run in that session, as a resumed run.

**A resumed run** works that issue in the branch's own tree. SELECT takes the issue, or the batch, the block names; the prerequisite that no changeset for this issue is already in flight, and SELECT's skip of an issue already in flight, are met by this run's own branch, not failed by it; UNDERSTAND runs as written; RECORD writes nothing, the line being the block's; BRANCH cuts nothing, since the session is already in the branch's own tree; and DIAGNOSE through REPORT AND STOP run as written, in this tree.
