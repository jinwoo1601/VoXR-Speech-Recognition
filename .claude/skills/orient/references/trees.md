# orient — the trees

What `orient`'s TREES states and which tree removals its PROPOSE proposes where `trees` is filled, and the binding sentences only those use.

## Bindings

- `verification` (optional) — the *Path form*, whose conversion a pack's `## The probe` may name for `<tree>`, by which PROPOSE forms it as `close-tree` STOPPED does. Absent → as that `## The probe` says; never a stop for that reason alone.
- `session-launch` (optional) — the List command, which TREES reads beside the List read, and whether PROPOSE routes a merged tree's removal through `close-tree`.

## TREES

**TREES** — where `trees` is filled; skipped otherwise. The hub and each tree with its branch, per the List read run in the hub by the Hub slot's idiom; then each entry of the directory the Location slot names that the List read does not show, stated as a leftover. Then each tree other than the hub, and each leftover, whose branch no block of the hub's `memory/STATUS.md` `## Current` names — a leftover's branch read from its name, per the Location slot's naming — stated as merged and awaiting removal where the `vc` binding's log read from the main branch to that branch lists no commit, and as unaccounted otherwise. Where `session-launch` reads filled with its List command, the List command is read beside the List read and each tree is stated with the sessions at it — a session is at a tree when its working directory is the tree's path or lies under it, compared as the trees contract (`.claude/references/core/trees-contract.md`) compares paths; a tree other than the hub whose branch a `## Current` block names, not merged by the same log read, with no session at it, is stated as its session vanished without finishing; and a tree whose branch no `## Current` block names is in progress — counted among the active branches, and never "merged and awaiting removal" — when a session is at it (the List command, a session being at a tree as above, where the `session-launch` key reads filled) or its branch has a commit the main branch lacks (the `vc` binding's log read): with a commit of its own, it is stated as in progress, with its sessions; with no commit of its own and a session at it, it is stated as "in progress, or finished with its report lost", with its sessions, since the log read cannot tell a just-cut branch from a merged one; neither is stated as merged and awaiting removal or as unaccounted, and only such a tree with no session at it and no commit of its own is stated as "merged and awaiting removal, or cut and never opened". Otherwise no session is read, and TREES states what it states today.

## PROPOSE

Where TREES states a tree merged and awaiting removal, propose its removal too — where `session-launch` reads filled with its List command, `close-tree` for that tree's branch, run on the human's word; otherwise, as today, on the human's word that no session is open in it, the PM first runs the holder probes on the tree as `close-tree` `## Workflow` STOPPED runs them — from "Then the holder probes" — `<tree>` the tree's path as TREES read it, formed as STOPPED forms it: held or unreadable → `close-tree`'s `references/outcomes.md` held line in that form, `<branch>` the tree's branch, the tree kept, nothing removed and no later probe run, and the human's word to close the tree again runs this removal again, probes first; every probe not held, none composed, or no manifest → the PM runs the Remove procedure in the hub by the Hub slot's idiom, then reads back with the List read and the tree's path; anything left is said to the human with its path, and TREES names it until it is gone. A tree TREES states as "in progress, or finished with its report lost" has `close-tree` offered for its branch only on the human's word that the branch finished, and a tree it states as in progress alone is never proposed. This skill proposes the removal and runs none of it.
