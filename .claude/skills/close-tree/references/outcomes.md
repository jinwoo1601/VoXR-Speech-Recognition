# close-tree — outcomes

The outcome table and the line each close tells the human. `py <script> close-tree`, the one call of `close-tree`'s `## Workflow`, prints each line ready to relay, after its first word, `removed:`, `kept:`, `held:` or `half-removed:`, and this file is the contract its tests hold each line to.

| Outcome | The tree | Its sessions | The human hears |
|---|---|---|---|
| not merged | kept | untouched | R3's line |
| a session at the tree without an `<id>` | kept | untouched | R3's line |
| a session still listed after the Confirm window | kept | the stop sent | R3's line |
| a stop refused — the stop verb exited 1 before its stop, live child processes past its wait among them | kept | untouched | R3's line, then the verb's `!` line where it prints one, with its `children:` line where it prints one |
| held — a holder probe read held or unreadable, or READ BACK found the Remove procedure's held result | kept | stopped, conversations kept | the held line |
| not clean | kept | stopped, conversations kept | R3's line |
| the removal refused — still listed | kept | stopped | R3's line, with the procedure's message |
| half-removed — unlisted, its directory present | unregistered; its directory left, empty or still holding files, as the Remove procedure leaves it | stopped | R3's line naming the directory; `orient` names it as a leftover until the human removes it |
| refused — a step's tool call refused by permission or policy | kept, or as the last read showed it where REMOVE or READ BACK was refused | as the steps before the refusal left them | the refused line |
| removed — unlisted, its directory gone | gone; the branch kept | stopped | the removed line |

R3's line is `<branch>: tree kept at <path> - <the check> failed: <what the read showed>`, one plain-ASCII line to the human: `<path>` the tree's path; `<the check>` the step that failed — MERGED, STOPPED, CLEAN, RELEASE or REMOVE, RELEASE only where the Remove procedure runs by `close-tree`'s `manual:` row; and `<what the read showed>` the read's own words — for MERGED, the branches read and the commits each listed, for MERGED's halt pass, the governing halt record's path and the two heads compared (the record's for `<branch>` and the tree's), else the record that did not parse or the head not read, the sessions without an `<id>` or still listed, the stop verb's `hub.py stop:` line, the Clean read's lines, the procedure's message, or the directory left in place; where STOPPED or RELEASE could not run, the binding or slot missing.

The held line is one plain-ASCII line to the human, in one of two forms, each opening as R3's line does. Held: `<branch>: tree kept at <path> - held by <source>: <what the read showed>; to remove it, save and close the holder, then say to close the tree again` — `<source>` the pack whose probe read held, or `REMOVE` where READ BACK found the Remove procedure's held result; `<what the read showed>` the holder as that pack's reference names it from the probe's output, or the procedure's own message. Unreadable: `<branch>: tree kept at <path> - <pack> holder probe unreadable: exit <code>: <output>; to remove it, close any holder of the tree, then say to close the tree again` — `<pack>` the pack whose probe could not be read, `<code>` and `<output>` its exit code and raw output, the output's line breaks folded to spaces, and both `none` where no command could be read.

The refused line is one line to the human, its template plain ASCII: `<branch>: tree at <path> <state> - <step> refused by permission or policy: <the refusal message>; nothing was retried; to close it, clear the refusal, then say to close the tree again` — `<path>` the tree's path as TREE read it, or `unread` where TREE's own read was refused; `<step>` the step whose tool call was refused, TREE to READ BACK; `<state>` `kept` where the refusal came before REMOVE, and `listed before REMOVE, unread since` where REMOVE or READ BACK was refused; `<the refusal message>` the refusal's own words, its line breaks folded to spaces.

The removed line is one line to the human, its template plain ASCII: `<branch>: tree removed, branch kept - no commit outside <destination>; report: <detail><held><taken>` — `<destination>` the branch MERGED's log read found no commit against, the main branch or another tree's branch; `<detail>` the detail of the `FINISHED` line that triggered this close, as printed, its line breaks folded to spaces, or `none` where the human's word triggered it; `<held>` nothing, or `; waiting on it: <item>, ...`, each item this session already holds as waiting on `<branch>`, from the order the human ruled, with nothing new read for it and, none held, nothing added; `<taken>` nothing, or `; still taken: <item>, ...`, each item the hub's `memory/items/` shows `taken <branch>` when the tree is removed, read by the verb, in the order read, or `; taken items not read: <reason>` where that read fails. The line says merged only in the report's words, since MERGED's read cannot tell a merged branch from one that never held a commit. Where MERGED passed by a halt record, the removed line takes its halted form, `<branch>: tree removed, branch kept - halted at <head>; report: <detail><held><taken>`, `<head>` the record's head for `<branch>`, and `<detail>`, `<held>` and `<taken>` as above. It is no stop, asks nothing and carries no push, and it opens nothing, since an opening keeps the human's word. `<held>` is advice: whether a session names everything it holds takes judgment, and no check finds a missed item (`adr-0189`). `<taken>`, unlike `<held>`, is a read: the check that the close-out closed every item the branch held, since by the time `close-tree` runs every such item should be closed or released.
