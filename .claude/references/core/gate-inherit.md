# Gate inherit

**The command.** A gate that may inherit a green full run whose read set this tree leaves unchanged names this file once and says when the command runs there and what an inherit spares there, and names its record; this file says how the command runs, how its result is read and the lines the record gains. The command is `py <script> --inherit --record <record>`, one command alone in its call, run from this tree's root, `<script>` the base's `scripts/run_tests.py`, joined and normalised as `.claude/references/core/gate-close.md` `## The clear` joins the base's `scripts/hub.py`, so a base of `.` gives `scripts/run_tests.py`, and `<record>` the record its site names, a path under `.scratch/` ending `.md`. With no manifest naming a base the command cannot be formed, as with no manifest that clear could not run: the command is not run, and the gate is the full run with no verdict, recorded `no manifest`. A refused call is reported, and the gate goes on as the full run with no verdict, recorded `refused`.

**The reading.** Exit 0 with stdout's last line opening `inherit: from ` is an inherit, that line its closing line: the gate's suite result, green, the command having run the `verification` binding's structural check itself. Exit 1 with stdout's last line opening `inherit: full run — ` is the full run, that line its closing line. Anything else — another exit, a prefix with the other exit, no output, a crash, a refused call — is the full run with no verdict. The command never turns a gate red. Where the `verification` binding is not `none`, each run of a gate that names this file appends one line at once to the record its site names: `gate ` and the closing line verbatim, where the command gave one; `gate inherit: full run — no verdict (<what it printed or exited>)` where it gave none, the parenthesis holding `exit <code>: <stdout's last line>`, `exit <code>: no output`, `refused` or `no manifest`; or `gate full run — <why the command did not run>` where the site runs no command, for a reason it names. The command appends that line to `<record>` itself, and the table below reads what it printed about it, by first word; where its output holds no line opening `recorded:`, it wrote nothing, and the site appends the one line at once itself, with no `gate at <revision>` line. An inherit's line is followed by one more, `gate at <revision>`, appended as **A docs-only move.** says. A line the command prints before its closing line is not copied. With the binding `none` the command is not run and no line is written: the gate records `nothing to run`.

| First word | What it says | Next |
|---|---|---|
| `recorded:` | the line after it, appended to `<record>`: the gate's line, then, on an inherit with a clean working tree, `gate at <revision>` | nothing more is appended |
| `skipped:` | `skipped: gate at` and why that line was not appended — the working tree not clean, its first path named, a read that failed, or the `vc` binding naming no read of the head; or `skipped: record`, the `verification` binding absent, `none` or not read, nothing appended | after `skipped: gate at`, that inherit has no revision a docs-only move is read from; after `skipped: record`, the site appends as where nothing was written |
| `manual:` | `manual: Base-revision reads`: the gate's line was appended, and the `vc` binding's *Base-revision reads* slot is not its pack's template default | run that slot's read of the head and its working-tree read as the binding writes them, each its own bare call, at once, and append `gate at <revision>` to `<record>`, `<revision>` the head it read, only where the working-tree read printed nothing |
| `unwritten:` | the append failed, `<record>` and why named; nothing was appended | the site appends as where nothing was written |

**A docs-only move.** A green gate stands for a head that moved from the revision it ran at only in docs paths, and no new gate runs. An inherit's revision is the one its site's record names on the line after the inherit's, `gate at <revision>`: the head the `vc` binding's *Base-revision reads* slot reads, read by the command once its closing line is decided, with that slot's working-tree read, the line appended only where the working-tree read printed nothing; an inherit with no such line has no revision a docs-only move is read from. A docs path is one under a directory the `process-docs` binding's *Design docs* or *Feature docs* slot places, one the `product-docs` binding's *Location* names, or one under `memory/`. The read is `py <script> --docs-only <revision>`, one command alone in its call, run from this tree's root, `<script>` as **The command.** forms it, its last line read by the table below by its first words, any other last line, exit or a refused call being a failed read; listing docs paths only, the move is docs-only; a failed read, or any other path listed, runs the gate. A binding absent, `none`, or a slot reading `TODO` adds no path. The site citing this paragraph keeps the read's output with the gate's evidence.

| First words | What it says | Next |
|---|---|---|
| `docs-only: yes` | exit 0: every path listed is a docs path, counted, from the revision named | the move is docs-only: no new gate runs |
| `docs-only: no` | exit 1: the first path listed that is not a docs path | the gate runs |
| `docs-only: failed` | exit 1: the read failed, why named | the gate runs |
| `manual: Base-revision reads` | exit 1: the `vc` binding's *Base-revision reads* slot is not its pack's template default, and nothing was read | run that slot's changed-file read from the revision to the head as the binding writes it, its own bare call, its listing read as this paragraph reads one |
