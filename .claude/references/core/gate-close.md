# Gate close

The close steps the three gate skills share word for word — `g1-lock`, `g2-accept` and `g2-lite` — each loaded where the calling skill names it: the session's dated note, the record as one hub operation, and the tree-path steps. Each skill's CLEAR loads `## The clear` as well, and its KEPT BRIEF `## The kept brief`. Each skill's HARD STOP loads `## The ruling line`. In these blocks, `## Workflow` and "the items below" are the calling skill's, and "the contract" is `.claude/references/core/trees-contract.md`.

## The dated note

`memory/<YYYY-MM-DD>.md` for today's date, created when absent: re-read it, since concurrent sessions share it, then append one entry at its end and edit nothing above — an H1 naming the date, the branch and this step, then `## Summary`, `## Changes`, `## Decisions` and `## Open issues` in that order, none dropped, an empty one saying so in one line. The closed branch's block moves out of `memory/STATUS.md`'s `## Current` into the entry's `## Changes`, whole and verbatim, opened by one line naming where it came from and this step: in a hub operation by `## The record`'s `--move-current <branch> '<step>'`, which places the line ``Moved from `memory/STATUS.md` `## Current` at <step>:`` at the end of the entry's `## Changes`, after a blank line only where `## Changes` is empty, and directly under it the block's line and its continuation lines, unchanged, the block never copied by the session; with `trees` absent, or the hub on the session's own branch, by the session's own edit, its opening line in the session's words; gate evidence — commit shas, test counts, exit codes, live-run transcripts — and authorship or provenance confessions go under `## Changes`, and the gate ruling and review-cycle records — angle counts, findings, verdicts, rulings — under `## Decisions`; deferrals and named limitations left at the gate are filed as `deferral` items, backlog candidates as `candidate` items and a finding about the project's base as an `upstream` item in this project's own register, its `refs` the `base` its `.claude/harness.json` records, as written there, relative to this project's root, each `memory/items/<slug>.md` with the `---` header (`slug`, `kind`, `route`, `status: open`, `checked`, `raised`, `title`), `route: untriaged` unless the filer knows it, its full text the body, the entry's `## Open issues` naming each by slug; an item the work closes leaves `memory/items/` for the end of the entry's `## Changes` with its outcome — `done`, `declined`, `superseded by <slug>`, `folded into <slug>`, `withdrawn` or `relayed` — as ``- Closed item `<slug>`: <outcome>.``, a blank line and its whole text six spaces in, the file removed; lessons for future features go to `memory/notes-for-future-features.md`, appended to and created where absent, lessons only, a note proposing work a `candidate` item instead; with `trees` absent, or the hub on the session's own branch, each item edit is the session's own, in that form, the item written by the Write tool and checked in with the record, else one of `## The record`'s edits. Where no branch stays active, `## Current` keeps one headline for the main branch naming the next action. A project root with no `memory/` at all: say so and write no note, inventing no other location.

## The record

## The ruling line

The command writes the segment above last on the branch's line in the hub's `memory/STATUS.md` `## Current`, each run of whitespace one space and each `"` written `'`, an earlier segment removed wherever it stands on the line, then reads the line back as the merge's `ruling` check reads it, so a segment the merge cannot read never lands; the table below reads what it prints. The full record stays after the merge, as `## The record` says.

## The clear

A gate's CLEAR empties the project root's `.scratch/` by one command, alone in its call, run from that root: `py <script> scratch-clear --root "<project root>"`. `<project root>` is that root's absolute path as the Bash tool takes it; `<script>` is the base's `scripts/hub.py`, the base being the `base` path in `.claude/harness.json`, relative to the project root, the two joined and normalised, so a base of `.` gives `scripts/hub.py`. With no manifest the clear could not run: say so and go on. A gate's clear names no `--keep`; a `kept:` line names a directory whose hub write has not landed, which stays, and is relayed with the `pending:` lines after it, each naming a mark and its state. A non-zero exit or a refused call: one line saying so, no retry in another form; what ran before it stands, what follows still runs, and the next clear takes what is left.
