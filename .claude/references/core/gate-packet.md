# Gate packet

The form of the packet a gate puts to the human is stated here once, and the gate skills cite it by section rather than restate it: `## The packet` for what every packet carries, `## The G0 packet` for G0's, `## The G2 packet` for `g2-accept`'s G2, `## The early word` for a gate word given before the preflight at G1 and at G2, the light lane's included, and `## The class label` for the label the light lane's G2 is headed with. `## The budget ruling` states the waive-or-trim ruling a budget FAIL draws at a gate's own stop. Its rules are held in prose at the gate, in the human's view — no check reads a packet or a word.

## The packet

One message, put by `.claude/references/core/ruling-form.md`, carrying: the issue; the one asked question; each default shown, with its option text; any fork meeting an exception of the fork default (`CONSTITUTION.md` *Display, don't ask*), put as a ruling of its own (`ruling-form.md` rule 3), never shown as a default; and what a yes authorizes.

Every packet carries the hub STATUS `## Auto-closed` lines verbatim, read by absolute path when the packet is drafted, or says there are none. The gate's first `memory/` write after its ruling removes each line shown, by its key, and no other: one `--remove-entry Auto-closed <key>` each in a hub operation, else the PM's own edit; a gate that makes no write clears nothing. A close by class puts no packet and clears nothing.

A packet at G1, at G2 or at the light lane's G2, where `trees` is filled, also names each late overlap, by the late-overlap read of this tree's `.scratch/catch-up-record.md`: every block whose `branch` line names this branch, in the whole record, and every `re-check <branch>` line. A block's `touches` lines are its paths; a block with no `level-check` line merged nothing; a block whose `head after` line reads `undone` merged nothing and names no path, its step's re-run a block of its own; a `level-check: refused` block keeps only its `touches` paths that the `vc` binding's *Base-revision reads* changed-file read, from the refused line's base to the block's `head before`, also lists, `memory/` set aside. A path is set aside only where an entry with a rule in `.claude/references/core/trees-contract.md` `## The release files` names it whole, as `.claude/references/core/gate-close.md` `### CATCH-UP` *Classify* reads it; one named at a part only is named, its `resolution <path> — rule` line beside it; with no release class every path is named. Each path is named under its block's `## Catch-up <n>` heading with its resolution, its `resolution <path>` lines read in that block and in each later block holding no `touches` line, their fix rounds included: a `resolution <path> — writer` line, a fix round's included, is a conflict and its writer; no `resolution` line for the path is a clean merge. Each `re-check <branch>` line is named with each block whose `touches` line holds a path the `re-check` line states, or one under a directory or glob it states, naming that path, or as not met where none does; a `re-check` line that states no path, an area alone, is named as stated, `no path to match`, for the gate word. With none of these, or no record, it says `No late overlap on this branch.`; a refused block whose changed-file read fails, or a record the read cannot parse, says `late-overlap read failed`, naming the block, never none. The gate word rules them, with no question of their own. A G0 packet names none, and a close by class puts no packet; with `trees` absent, or where `.claude/references/core/gate-close.md` `### ROOT` finds the hub on this branch, the packet names none.

A ruling is the gate's clear word, the word with clear overrides of named defaults, or a clear decline. Any other answer is no ruling and is asked again, the ask naming what was unclear; nothing is inferred from tone.

## The G0 packet

Put by `## The packet`; only the scope is asked: agreement to the topic, or the backlog feature, and its scope. Shown as defaults, each with its text:

- for a feature, the user story the PM drafts from the backlog row and the locked design, in the form *As a \<user\>, I want \<capability\>, so that \<value\>.*;
- for a feature, the track, lite or full, the row's mark as `.claude/references/core/feature-lite.md` `## The mark` reads it;
- for a feature, the path, the one the row names, `development` where the row names none; `development-lite` on a `**Lite**` row naming `development` or none, the path its alias reads;
- for a design topic, the path, `design`, with no read run;
- for a prototype, the path and the lane, each `prototype`;
- the lane, `design` for a design topic or `feature` for a feature;
- on `g0-open`'s tree path only, concurrency — "run concurrently" with each active branch, this one excepted, each stated independent or not, as that path reads them.

A design topic's packet has no story or track; today's path shows no concurrency.

A prototype's packet — from a backlog row whose path reads `prototype`, or standalone with a topic and the question it answers — shows that question as its scope and has no story or track.

For a feature, the PM runs the read, the base's `scripts/harness.py doctor --paths --root <project>`, before drafting the packet, the base being the `base` path in `.claude/harness.json`, relative to the project root; the default comes off the row whatever the read says. Where the feature has no row, the read prints no path other than `design`, `light` and `lab`, or the row names none and the read does not print its default, the packet shows that default — `development-lite` on a `**Lite**` row, `development` otherwise — with a clause that nothing checks it. Where the read exits non-zero or no manifest lets it run, the packet says the composed paths could not be read, its rows shown. Where the feature has no row, the read prints no path other than `design`, `light` and `lab`, or the read could not run, any word changing the path is refused and asked again, the ask saying why; for no row, that a re-lock at G1 adds one.

For a prototype, the PM runs the same read before drafting the packet. Where the read does not print the path `prototype`, the open is refused and asked no further, the refusal saying the project does not compose the prototype path; where it exits non-zero or no manifest lets it run, the open is refused the same way, the refusal saying the composed paths could not be read. No packet is put, and nothing is cut or written.

Any default is overridden in the same answer, and recorded with the scope at RECORD:

- a story override is taken as worded;
- a track override to full is taken;
- a track override to lite on a `**Full.**` row amends what G1 ruled — exception (4) — so the PM stops and puts two options: open the feature on the full track now, as the row's `**Full.**` mark reads, or re-lock the row as lite at G1 first (`.claude/references/core/feature-lite.md` `## The mark`);
- a path override: a word naming what the row already reads, `development` where it names none and is not marked lite, edits nothing; a word naming `design`, `light` or `lab`, paths no backlog row takes, is never taken onto the row but read as the lane override of that name below, a decline for `light` and `lab` and a scope change for `design`; on a row marked lite, by its Path sentence naming `development-lite` or by the `**Lite**` alias: a word naming `development-lite` names what the row reads and edits nothing, a word naming `development` is the up move (`adr-0246`), taken with no ruling as the track override to full is taken, the feature opening on the full track with its requirements doc and the row unedited, and a word naming any other printed path amends what G1 ruled — exception (4) — so the PM stops and puts two options: open the feature on `development-lite` now, as the row reads, or re-lock the row at G1 as `**Full.**` with that path first (`.claude/references/core/feature-lite.md` `## The mark`); on a row not marked lite, a word naming `development-lite` is the track override to lite above, and the PM stops as that bullet says; else a word naming a path the read printed is taken, no exception (4), G1 having ruled the row changeable by this word (`adr-0091` item 1), and RECORD edits the row; any other is no ruling, refused and asked again, the ask naming the printed paths a backlog row takes, each but `design`, `light` and `lab`. A taken word puts the backlog in the branch's write set, as `g0-open`'s tree-path RE-CHECK reads it;
- a path override on a design topic, in place of the bullet above: a word naming `design` edits nothing; a word naming `light` or `lab` is read as the lane override to that lane below, a decline; a word naming any other path changes what is opened, so it is a scope change and the PM stops (`CONSTITUTION.md` *Display, don't ask*);
- a lane override to light or lab is a decline at G0, opening neither lane;
- a lane override between `design` and `feature` changes what is opened, so it is a scope change and the PM stops (`CONSTITUTION.md` *Display, don't ask*);
- a path or lane override into or out of `prototype` changes what is opened, whatever the path override above takes, so it is a scope change and the PM stops (`CONSTITUTION.md` *Display, don't ask*);
- a wait stops the branch with nothing written but the removal `g0-open`'s tree path names.

## The G2 packet

The one message at `g2-accept`'s HARD STOP, put by `## The packet`, carrying:

- the audit verbatim, per item, any line `SKIPPED BY PATH <name>` staying in it as shown, so nothing a path skips drops out unseen;
- the budget ruling: a budget FAIL, the one FAIL the packet carries, every other remediated at PRESENT, is ruled before the packet by `## The budget ruling`, its waiver's line beneath the audit;
- the side rulings: every option the PM took by the fork default for which G2 is the next gate (`CONSTITUTION.md` *Display, don't ask*) — this run's takes, and those the PM finds since the branch's last gate in the dated notes (`memory/<YYYY-MM-DD>.md`) and the branch's line in `memory/STATUS.md` `## Current` — each with its option text; CHANGELOG and fix-versus-defer takes are examples, not a list;
- any fork meeting exception (4) or (5) met before the packet, put as a ruling of its own before the word (`ruling-form.md` rule 3), never listed as taken, and cleared as `## The early word` says of another stop;
- the ask, and what a yes authorizes.

The re-run rule. After "Accept, but fix X", the PM makes the change, itself or by brief where composition or code logic is needed. The change, where it touches a tracked file, is checked in per the `vc` binding, the `verification` binding's commands run green at the new head, and STAGE re-runs, all before PREFLIGHT re-runs. There is no ask where the re-run is no worse than the audit ruled on; the packet asks again, the new audit in view, on any FAIL but a budget a waiver holds, its later figure shown, on the change meeting exception (4) or (5), and on an UNVERIFIABLE item the ruled audit did not carry. A ruled audit carries no FAIL but a budget's, so no other FAIL is a ruled finding: one the re-run reads, on text the change touched or not, is remediated as today, and the packet asks again, naming the FAIL. RECORD then records the new head. The fix's diff, and any take after the ruling, such as a catch-up's resolution, go in MERGE's relay.

The form RECORD records: at the stop, for the word given there; for an early word, "in session, before the preflight, stood at `<head>`", `<head>` the head the passing preflight audited or, past a waiver, the head that audit read; for "Accept, but fix X", that ruling with the new head.

## The budget ruling

A `budget: FAIL` on STATUS is the human's waive-or-trim ruling at the gate's own stop (`adr-0179`), at G1, at `g2-accept`'s G2 and at the light lane's G2. The route opens only on the final line `budget: FAIL`, every other FAIL remediated first, and that FAIL stays FAIL in the audit. Every other FAIL stays remediated, never rulable; a `budget` refusal or no final line stays UNVERIFIABLE, never waivable.

The ruling is put before the packet, one question per failing budget, each in its own AskUserQuestion call (`ruling-form.md` rules 3, 4), naming the budget, its figure, its limit and the gate, its options Waive and Trim. No option is marked Recommended, so the question offers the fork default nothing to take (`CONSTITUTION.md` *Display, don't ask*): only the human waives, by no fork-default take and no standing ruling. "Waive at G2, fix later" is retired, its 2026-10-30 notes staying records.

**Waive:** the gate goes on over budget; one line lands in the dated note; nothing goes on the board; a later census reads it. A waiver is a closed ruling, no named limitation: it files no deferral item and extends none, so `.claude/references/core/gate-close.md` `## The dated note`'s deferral routing does not take it.

**Trim:** that file shrinks, at work now; the gate is put once `budget` passes. Still over, the ruling is asked again.

The line: `Budget waiver — <label>; <bytes> of <limit> bytes; gate <G1|G2|g2-lite>; branch <branch>; "<the human's words>"`, alone on a line under `## Decisions`, no bullet, the human's words folded to one line and last, since they may hold anything. `<label>` and the figures copy `budget`'s line, `STATUS budget`, and none of the rest of it; the gate `g2-lite` is the light lane's G2. One line per waiver; the gate's record never restates it in this form. `rg -c "^Budget waiver — " memory/` counts them per note, the census being their sum, and each matches `^Budget waiver — (STATUS budget); (\d+) of (\d+) bytes; gate (G1|G2|g2-lite); branch (\S+); "(.*)"$`.

It lands when ruled, in its own entry: one hub operation (`.claude/references/core/trees-contract.md` `## The hub operation`), `scripts/hub.py write --root <hub> --message <file> --note <file>`, its inputs under `.scratch/<skill>-<slug>-waiver-<n>/`, in `## The dated note`'s shape: H1 `# <date> - <branch> - budget waiver`, the other sections saying none, `## Decisions` the line, two waivers from one answer two lines; no block moves. With `trees` absent or the hub on this branch, the PM's own edit. The command carries `--note` alone, so a waiver adds zero bytes to STATUS. A refused write goes by `## The hub operation`, a `correct:` line corrected and re-run, any other BLOCKED, and the gate waits on the line landing. With no `memory/`, `## The dated note` applies: the PM says so and writes no note, and the waiver stands as the human's ruling in session.

A waiver's write clears no `## Auto-closed` line: it precedes the ruling `## The packet`'s clearing follows, a word typed in one answer with a waiver being held as an early word and the line landing first, and the lines shown stay until the gate's record removes them (`gate-close.md` `## The record`), a declined gate showing them again.

A STATUS trim is the hub session's, act 7 being its own (`trees-contract.md`) and `## The hub operation` holding a branch session to its own block; a branch session never trims. On Trim the session sends, where the Hub session name is filled, `BLOCKED - <branch>; lane: <lane>; STATUS trim asked at <gate>, <bytes> of <limit> bytes` (`handoff` `references/launch.md` `## Reporting`), then re-puts the ruling by AskUserQuestion, saying the trim is the hub session's, its options `Trim landed`, `Waive` and `Hold`. The human tells the hub session, whose relay is one line with no push (act 4); it trims by a hub operation and never replies. The session reads the effect from evidence: on `Trim landed`, the base's `scripts/harness.py budget --root <project> --hub "<Hub path>"` re-runs, the base as `## The G0 packet` reads it. PASS, the gate is put; FAIL, the ruling is asked again; a refusal or no final line, UNVERIFIABLE. It polls nothing; on `Hold` the turn ends `Stop: gate`, passing with the call in its window (`.claude/references/core/hooks.md` `## What the stop-line hook passes`), and no `stops:` entry changes. No Hub session name, or a failed send: no report, the same question. With `trees` absent, or the hub session on its own branch, one session holds act 7: the PM moves closed history to the note, deleting nothing (`CONSTITUTION.md` *Context is the budget*), and re-runs `budget`; on the hub's own branch the check-in moves the head: at `g2-accept`'s G2 the trim is that check-in per the `vc` binding, then `## The G2 packet`'s re-run order — the `verification` binding's commands green at the new head, STAGE, then PREFLIGHT, whose item 6 is the `budget` re-run; at G1 and the light lane's G2 the trim is that check-in, then the `budget` re-run.

A waiver holds for that budget at that gate of that branch, keyed by the line's fields and no head: a fix or a catch-up moves the head and the hold stands. `gate-close.md` `### HUB READ` runs no `budget`; where a re-run reads it, the later figure goes in the packet or MERGE's relay, with no ask and no second line. A successor finds the hold by that pattern in the dated notes, the hub's under `trees`.

## The early word

The gate's explicit word — the lock, the acceptance or the close, as each HARD STOP names it — given in the session running the gate, after the invocation and before the stop's message. The phrase that invokes the gate skill — its trigger, such as "accept the feature", "lock the design" or "ready for G2" — is no word; an earlier session's word is none. The PM says it holds the word and runs the steps as written.

- **Stands** where the first preflight returns every item PASS — at G1, every fixed question yes, no changed file outside the area, and `budget: PASS`; at G2, the light lane's on slim included, every `gate-preflight` item PASS, an item `SKIPPED BY PATH` aside, its line still in the information message; at the light lane's G2 on prose or trivial, `budget: PASS`. The message is still put, as information, the PM saying the word stands. At the light lane's G2 the word stands on the preflight run at the effective class CLASS reads; a deeper class RESOLVE reads at the closing head, or a `bounds` check that could not run, is no FAIL of itself — the preflight at the class it brings decides — and the `bounds` lines go in the information message, as HARD STOP puts them in view. At G1 a stood lock covers the feature marks and paths PRESENT showed, as the stop's ruling does (`g1-lock` PRESENT); the information message carries the marks and paths and says the lock is also the word to merge.
- **Void** on a FAIL — at G1, a fixed question answered no, a changed file outside the area, or `budget: FAIL` — save a budget FAIL alone, which is *Held*; beside another FAIL it voids as today. Every other FAIL is remediated as today, and the packet asks again, naming the FAIL, a budget FAIL ruled first by `## The budget ruling`.
- **Held** on a budget FAIL alone: the word never waives. The question `## The budget ruling` puts goes alone, no packet. On Waive the line lands, then the word stands, the message put as information with the FAIL and the line. On Trim the word is void, and the packet asks once `budget` passes.
- **Re-asked** on an UNVERIFIABLE item — a `budget` refusal or no final line among them (`gate-preflight` item 6): the packet is put in full, those items with the ask. Beside a budget FAIL the item is still *Re-asked*, never *Held*: no word stands, and the ruling `## The budget ruling` puts goes first.
- **Degraded**: no word stands, and the packet is put in full, where `gate-preflight` returns no verdict, or where at G1 `doc-extractor` is missing and the answers are the PM's own read; `gate-preflight` missing stops before dispatch, as each skill says.
- **Suspended**: where a stood word meets another declared stop — a review ruling at the light lane's G2, an exception fork — that stop is put as today; once it clears, the word stands and the PM says so, unless the clearing changed scope, which voids the word and runs the gate again from PREFLIGHT. At the light lane's G2 the review runs after PRESENT as today, its CONFIRMED fixes listed with the stood word.

A stood word is the ruling: it unlocks what HARD STOP unlocks and is the word to merge (`adr-0033`). The sentence on what is no ruling stands beside it in each HARD STOP — `g1-lock` HARD STOP, `g2-accept` HARD STOP and `g2-lite` HARD STOP.

No conditional word at G1 or the light lane's G2: "lock, but fix X" is no ruling; the change is made as work and the gate put again.

## The class label

The light lane's G2 is headed `G2 · light lane · <class>`, `<class>` the effective class at the closing head: the class the header of RESOLVE's last `close-class` run names, whichever it is — CLASS's, a lighter one where the closing head's diff shrank, or a deeper one, preflight and review having been re-run at it or deeper first. `g2-lite` HARD STOP heads its question with it; that stop is reached on a human class, or as a human class where CLOSE OUT finds the branch's `## Auto-closed` line already present, the label naming the effective class on either path, and a close by class that puts no stop carries no label. The turn putting that stop closes on `Stop: declared — ` followed by the `stops:` entry as it reads, `<class>` left literal, since the stop-line hook matches a declared line's detail to the entry by equality (`.claude/references/core/hooks.md` `## What the stop-line hook passes`), or on `Stop: gate`; only the question's heading carries the filled-in class. The label heads the question only; the records the close writes carry the heads `g2-lite` CLOSE OUT states.
